# 变更与完成定义

- 一次变更聚焦一个可验收能力；超过 500 行业务逻辑应拆分。首次骨架可包含必要配置与文档，不把它们视作额外业务能力。
- 完成定义：Scenario 可追溯、make check 通过、相关集成验证通过、文档同步、证据留档。未执行的外部检查明确写待验证。
- 提交信息包含改动及规约标识；合入 main 必须通过 check。禁止强推、删除主干或绕过门禁。
- 机器负责格式、类型、测试和依赖方向检查；实现者确认需求含义、授权边界与迁移取舍。不得用机器检查通过代替尚未进行的实际验证。
- 例外记录于对应规范，包含理由、影响和替代检查；禁止临时口头跳过。证据路径 docs/verification/<change>.md。
- 标签仅指向通过自动门禁的提交；后续更改必须重新检查。产品里程碑与骨架变更独立判断，不能把骨架成功说成产品完成。
