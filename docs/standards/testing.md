# 测试规范

- 每个 Scenario 在 docs/verification/traceability.md 对应测试或实际运行证据。用例分正常、失败、边界；测试名称说明行为，不仅断言对象形状。
- 服务单元测试使用可注入探针；API 测试验证 HTTP、错误码、数据副作用；少量端到端验证真实容器连接和状态页。检查：make check 与 make smoke。
- 自动单元/接口测试不依赖生产服务、真实模型或时钟；容器测试使用唯一 Compose project 与独立卷，退出清理自身资源。禁止连接用户数据运行破坏性测试。
- 请求成功依 HTTP 和约定业务状态共同判断；错误响应不算成功，后台 202 仅表示受理。被放行指取得无权数据或发生无权写入；合法请求被拒即误拒；未捕获异常或泄露堆栈属故障。
- make check 任一命令非零即失败，禁止忽略或跳过；修复缺陷先补复现用例。断言必须能发现破坏业务条件的变更。
- 骨架性能阈值仅约束探针超时与 worker 停止；模型耗时与容量待实测，不能套用普通接口毫秒阈值。前端状态测试覆盖 loading/ok/degraded/network error。
