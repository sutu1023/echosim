# 安全开发规范

- 业务默认拒绝；身份和作品归属由服务端校验，猜测 ID 不构成授权。附件读取复用作品权限，不暴露通用文件 ID 下载。检查：每个业务能力必须有双用户越权测试；骨架没有业务入口。
- 用户配置密钥后端加密保存，主密钥从部署环境注入；不返回原值。轮换先写新版本并验证，再撤销旧版本；旧配置不复用于新任务。检查：模型配置能力的掩码、归属与轮换测试。
- 日志不得包含请求体、query、Cookie、Authorization、数据库 URL 或原始异常。检查：注入标记值并断言日志不含标记。
- 前端通过文本节点输出用户内容；不使用未经净化的 HTML。未来会话使用 HttpOnly、Secure、SameSite cookie，写接口验证 CSRF；不在 localStorage 存 token。检查：浏览器与接口安全测试。
- 用户模型地址必须经过受控供应商域名白名单和解析后公网 IP 检查；禁止内网、回环、元数据地址和重定向绕过，每次连接重新校验。检查：未来模型配置 SSRF 场景。
- 每次依赖变更与每周执行 make audit；高危/严重漏洞阻断发布，例外需写明影响、期限和缓解措施。新增依赖说明用途与替代取舍。检查：pip-audit、npm audit、CI 定期任务。
- .env 和密钥文件不入库；.env.example 只放键名。检查：make check 的跟踪文件和密钥模式检查；发布前检查全部提交历史。
