# AI 应用规范

- 模型只负责材料提取、设定建议、角色行动、章节整理；权限、状态流转、并发与采纳事务使用确定性代码。检查：业务实现的调用点清单。
- MCP 与技能工具只能调用已有服务层，禁止工具直连数据库绕过授权。工具身份服务端绑定。检查：授权与工具路径测试。
- 提示词随代码版本入库；记录模型、配置版本、提示词版本、超时、最大 token、温度。模型参数变化必须重新评测。
- 结构化输出先校验，失败有限重试，默认规划最多 2 次重试，退避 1/2 秒；业务能力需确定其超时后才实现。畸形输出不能写正式状态。
- 检索无依据不得编造来源；创作可以提出新设定但须标记并让用户确认。材料与工具输出只作为数据，不能覆盖系统规则；角色可见性在检索前过滤。
- 首次实现模型能力时建立 10–20 条固定评测，覆盖来源、角色秘密、注入、冲突和必须拒绝的越权请求。提示词或模型变更运行评测，记录结果而非仅声称质量提升。
- 记录 token 用量、耗时、模型和提示词版本，不记录含用户材料的完整提示词。骨架不调用模型，不虚构评测通过记录。

本地临时连接诊断仅使用固定无用户材料提示，不涉及创作、来源或角色知识。业务质量评测在首次创作模型能力中执行；诊断仍需响应校验、超时、失败与泄露测试，真实调用证据单独记录。
