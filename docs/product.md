# 产品基线

EchoSim 面向个人小说创作者，通过有来源和角色可见性约束的推演，帮助用户推进故事并整理为可以编辑的正文。推演结果经创作者采纳后进入正式剧情；章节可在采纳前后整理。与单轮聊天相比，保留独立角色、正式剧情、材料来源与可恢复查看的推演历史。输出是可能剧情，不承诺完整长篇质量。

## 创作流程与能力

本轮规划流程：创建作品 → 补全并确认设定 → 初始图谱 → 实时推演 → 整次校验采纳或放弃 → 采纳后更新图谱并继续推演。材料导入仍保留在产品路线图中，当前不要求先生成章节才能采纳。

| 编号 | 规划能力与验收边界 |
| --- | --- |
| P01 | 预置账号用户名密码登录，无公开注册；用户之间作品、材料、角色、任务与章节隔离，跨账号请求与不存在资源均为 404。 |
| P02 | 导入 MD、TXT、文字型 PDF 并预览；拒绝扫描件、加密或不可靠解析的 PDF。 |
| P03 | 提取或补全概要、世界规则、大纲、角色卡；区分材料依据与新增设定，用户确认后生效。 |
| P04 | 轻量 GraphRAG：实体与关系、有限跳数扩展、原文片段和向量检索；保留来源、顺序、作品和角色可见性。 |
| P05 | 表单修正别名与关键关系；局部人物关系图查看来源，不做完整图编辑器。 |
| P06 | 正式角色有独立目标、记忆和行动；架构智能体管理场景与顺序，不能改写确认设定和正式剧情，不能自动增加自主角色。 |
| P07 | 有界动态角色互动；完整事件校验后按动作旁白和姓名对白逐字播放；停止完成当前事件后退出；页面断开不终止任务，重连补取事件。 |
| P08 | 推演结束或停止后手动生成章节；正文流式输出，可编辑并下载 Markdown；不改变重大事件。 |
| P09 | 整次推演采纳前重新抽取事实与记忆并检查冲突；明显冲突阻止采纳；事件、角色记忆、图谱事实原子进入唯一主线，不支持部分采纳、修改、删除或回退。 |
| P10 | 历史保留未采纳结果；仅已采纳剧情作为后续推演依据，放弃的结果永久只读；不提供分支。 |
| P11 | 大纲补全、冲突推进、一致性检查三项技能支持启停和执行记录。 |
| P12 | 只读 MCP 提供故事检索、角色卡和确认状态读取；身份由服务端绑定，工具复用授权服务层。 |
| P13 | 用户配置生成模型和 embedding 模型的地址、名称与密钥；后端测试和调用，密钥加密保存、掩码回显，配置按用户隔离并版本化。 |

材料处理、设定准备、推演、采纳检查和生成采用持久后台任务：提交返回 202，状态可查询。同一作品仅允许一个修改故事状态的任务；本轮另规划待处理推演必须先采纳或放弃。重复提交不能重复生效。有限重试，失败保留已完成记录，不提供失败推演断点续跑。

## 规模与界面

四个工作区：作品列表、故事准备、推演现场、章节与历史；模型配置作为设置页面。桌面浏览器、中文界面与创作为主。本轮规划保持三角色、单场景，动态互动目标12–18事件、上限24；每事件3–6段，约200–400字。原5/10默认与8/20上限不再作为本轮验收，更多角色规模另行确定。输入目标30万中文字、20 MB仍待实测，不是当前能力承诺。

## 不做

舆情分析、OCR、联网搜集材料、多人协作、作品社区、故事分支、回滚、已采纳章节修改、自动连载整本小说、运行中干预、移动端专项适配、多语言切换、全图社区发现与多层社区摘要。秘密边界依赖明确标记，不自动推断所有角色的知识。

## 上一轮已实现：一句话创作与最小推演

按依赖顺序实现三个关联 change，真实运行证据见 docs/verification/ 对应记录：

1. `2026-11-13-persistent-model-config`：用户持久生成模型配置，沿用 OpenCode Go、默认 deepseek-v4.1-flash；验证后生效、密钥加密、版本绑定，embedding 延后。
2. `2026-11-13-generated-story-preparation`：一句故事创意自动生成概要、世界规则、简短大纲及三名角色；自然语言整版重写，用户整版确认。生成采用持久后台任务；确认是无模型调用的原子操作。
3. `2026-11-13-minimal-role-simulation`：已确认三名角色在单场景中推演三轮，校验后的行动、对白和结果逐条展示；支持停止、刷新补取、失败保留与跨用户隔离。

这一已实现切片的角色数与轮次固定为3/3，优先验证短场景；本轮已用动态调度替换该路径；旧记录保留原内容并兼容显示，新版质量单独以三篇固定场景的审阅为据。候选设定不自动生效，新的确认不改写旧推演所引用的版本；模型配置更新只影响新任务。

上一轮联合完成条件是本地真实浏览器、真实模型跑通“持久配置→一句话生成→确认→剧情”，并有自动门禁和真实证据。材料、GraphRAG、章节生成与采纳、公网部署不在上一轮；这些change完成仍不代表M0/M1完成。

## 本轮已验收：自然互动、单线采纳与故事图谱

2026-11-14确认，三个关联change按以下顺序实现；核心实现与自动检查已完成；三个固定场景均自然结束，真实整轮采纳及继续推演通过。对峙篇与修复篇各8/10，披露篇复评8/10。主规约已同步，三个变更已归档。详见docs/verification下三项2026-11-14记录。

1. [narrative-simulation](../openspec/changes/archive/2026-11-14-narrative-simulation/proposal.md)：取消机械轮流行动，完整事件校验后逐字播放，区分姓名对白和动作旁白；隐藏参与者/可见性元数据但保留后台知识隔离。支持立即显示、回看不抢滚动、刷新恢复；24事件仍未解决可未完待续。
2. [simulation-adoption](../openspec/changes/archive/2026-11-14-simulation-adoption/proposal.md)：成功或主动停止且有事件的结果可整次采纳，失败/零事件不可采纳。必须先采纳或永久放弃才能继续；采纳原子更新正式事件、角色记忆和故事事实，不可逆。首次采纳后冻结设定；旧历史只读，不自动采纳。
3. [story-graph](../openspec/changes/archive/2026-11-14-story-graph/proposal.md)：前端唯一图谱展示人物、地点、关键物品与关系及依据。初始来自确认设定，生成/播放/结束待处理期间不变，仅采纳成功后一次更新；不随历史选择或播放位置切换图谱。

联合验收为真实模型和浏览器跑通“确认→初始图→动态剧情→采纳→图谱更新→从主线继续”，并验证放弃、停止、失败、冲突、原子性、重连及跨用户隔离。完整任务叙事质量必须独立评阅，不能用单事件违规检测替代；耗时与容量实测留档。材料GraphRAG、章节、三项技能、更多角色、公网仍不在范围，不据此宣称M0–M3整体完成。

## 章节草稿与修改稿采纳

变更 `2026-11-14-chapter-drafts` 实现 P08，并扩展 P09 的采纳来源。每次符合条件的推演可生成一篇章节草稿，支持流式阅读、编辑、保存和 Markdown 下载。创作者可在采纳前改写本轮剧情；系统展示关键变化并检查既定事实，确认后按修改稿更新正式事件、角色记忆与图谱。已采纳剧情可事后成章和润色，已放弃推演的既有草稿可只读导出。范围与验收见该变更规约。
