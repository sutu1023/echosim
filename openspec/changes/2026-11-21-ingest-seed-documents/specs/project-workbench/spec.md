# Spec Delta

## ADDED Requirements

### Requirement: 项目材料列表与上传入口

项目详情页与第一阶段工作台 SHALL 显示当前项目的真实材料列表，每项至少包含展示名称、类型、大小、状态，以及 PDF 的总页数或就绪材料的分块数。列表为空时 MUST 显示“还没有材料”并提供上传入口，说明支持 PDF、Markdown、TXT 与 20 MiB 单文件上限。

上传 MUST 只发生在已完成身份与项目归属校验的私有页面，MUST 在完成后刷新同一项目的材料列表。上传、切换到材料详情与返回 MUST NOT 改变当前项目、当前阶段、`layout` 与 `lang`；中文与英文界面 MUST 使用各自语言的状态、错误与上限文案。

#### Scenario: 空材料时提供上传入口

- **GIVEN** 项目所有者打开自己项目的第一阶段，项目还没有材料
- **WHEN** 页面加载完成
- **THEN** 材料区显示“还没有材料”，并提供选择文件与上传的操作
- **AND** 说明支持 PDF、Markdown、TXT，单文件不超过 20 MiB
- **AND** 不显示图谱节点、示例材料或“已完成”

#### Scenario: 上传后就绪材料出现在列表

- **GIVEN** 项目所有者在一份有效材料上传完成后停留在同一阶段
- **WHEN** 材料解析完成
- **THEN** 列表出现该材料，显示名称、类型、大小、状态“就绪”、PDF 总页数与分块数
- **AND** 当前项目、阶段、布局与语言保持不变

#### Scenario: 上传被拒绝时显示原因

- **GIVEN** 用户选择超过 20 MiB 的文件或空文件
- **WHEN** 用户提交上传
- **THEN** 页面显示与拒绝原因对应的中文或英文说明，并保留已选状态供重新选择
- **AND** 材料列表数量不因被拒绝的上传而变化

#### Scenario: 英文界面下的材料区

- **GIVEN** 用户在 `/projects/<项目 ID>/workbench/evidence-graph?layout=graph&lang=en` 打开材料区
- **WHEN** 材料列表为空或解析失败
- **THEN** 空态与失败原因使用英文文案
- **AND** 项目名称、阶段 slug 与文件原始名称保持原样

### Requirement: 材料状态在页面上可区分

材料区 SHALL 区分排队中、解析中、就绪、失败四种状态，并区分“服务暂时不可用”与“还没有材料”。解析中 MUST NOT 显示为空列表或失败；失败 MUST 显示可读原因与重新上传入口；就绪 MUST 显示摘录与来源入口；服务故障 MUST 显示不可用提示与重试，且保留会话。

#### Scenario: 解析中不误报为空或失败

- **GIVEN** 一份材料已上传但解析尚未完成
- **WHEN** 用户查看材料列表
- **THEN** 该材料显示为排队中或解析中，并说明可以稍后刷新
- **AND** 不显示“还没有材料”，也不显示失败原因
- **AND** 打开其摘录时得到空结果而不是错误页

#### Scenario: 解析失败显示原因并可重试

- **GIVEN** 一份材料因无文字层、无法解码或 PDF 页数超过上限而失败
- **WHEN** 用户查看材料列表
- **THEN** 该项显示失败与具体原因，页数超限时 MUST 说明当前上限值
- **AND** 提供重新选择文件上传的入口，不显示分块数或“就绪”

#### Scenario: 服务不可用与空材料文案不同

- **WHEN** 材料列表请求返回 503
- **THEN** 页面显示“服务暂时不可用”与重试操作，保留登录态
- **AND** 不把服务故障显示成“还没有材料”或解析失败

### Requirement: 摘录与来源定位

材料详情 SHALL 按分块序号稳定展示阅读摘录，并允许分页读取。PDF 材料的每个分块 MUST 显示其物理页码，查看来源 MUST 打开原件并定位到该页（`#page=<物理页码>`）；文本材料的每个分块 MUST 显示其原始段落范围，查看来源 MUST 在原文视图中定位到该段落。

来源 MUST 以原件为准：原文视图展示的是未清洗的原件内容，摘录展示的是清洗后的可检索文本；两者不一致时 MUST 不把清洗结果伪装成原件。原件与原文视图 MUST NOT 以可执行 HTML 方式渲染。

材料详情 MUST 由完整 URL 表达：即当前项目与阶段地址加上 `?document=<材料 ID>`，并保留既有 `layout` 与 `lang`。刷新或直接粘贴该地址 MUST 回到同一材料；未登录打开 MUST 先登录并在成功后返回该完整地址；他人项目或不存在项目 MUST 显示相同的“项目不存在”，不得显示材料内容或“无权访问”。

#### Scenario: PDF 摘录跳回物理页

- **GIVEN** 一份三页 PDF 材料已就绪，第 3 页有正文
- **WHEN** 用户在第 3 页的分块上点击“查看原件”
- **THEN** 打开的原件地址以 `#page=3` 结尾
- **AND** 页面显示的是用户自己的原件，不是缓存副本或他人材料

#### Scenario: 文本摘录定位到原始段落

- **GIVEN** 一份 Markdown 材料已就绪，其中某分块来自第 12 段
- **WHEN** 用户点击该分块的“查看原文”
- **THEN** 原文视图定位并高亮第 12 段的原始内容
- **AND** 高亮内容取自原件，而不是清洗后的分块文本

#### Scenario: 刷新或粘贴材料地址回到同一材料

- **GIVEN** 项目所有者已打开 `/projects/<项目 ID>/workbench/evidence-graph?layout=graph&lang=en&document=<材料 ID>`
- **WHEN** 用户刷新页面，或在另一个标签页粘贴同一地址
- **THEN** 页面回到同一项目、同一阶段、图谱布局、英文界面与同一材料详情
- **AND** 摘录、来源与状态重新从 API 读取，不依赖浏览器内存中的上次选择

#### Scenario: 匿名打开材料地址后登录返回原地址

- **GIVEN** 未登录访客直接打开带 `document` 的材料地址
- **WHEN** 访客完成登录
- **THEN** 登录页的 `next` 保留包含 `layout`、`lang` 与 `document` 的完整地址
- **AND** 登录成功后回到同一材料，而不是项目列表或控制台

#### Scenario: 他人打开材料地址只看到项目不存在

- **GIVEN** 用户 B 已登录，A 的项目中存在一份材料
- **WHEN** B 打开 A 的材料地址，随后打开一个随机不存在的项目地址
- **THEN** 两次页面显示相同的“项目不存在”提示
- **AND** 不显示材料名称、页数、摘录、来源链接或“无权访问”

#### Scenario: 材料切换不丢布局与语言

- **GIVEN** 用户在 `/projects/<项目 ID>/workbench/evidence-graph?layout=workbench&lang=en` 打开一份材料
- **WHEN** 用户切换另一份材料并返回材料列表
- **THEN** 地址中的 `layout=workbench` 与 `lang=en` 始终保留
- **AND** 页面仍为英文工作台布局，不回到双栏或中文

#### Scenario: 摘录分页顺序与定位稳定

- **GIVEN** 一份分块数超过一页上限的材料
- **WHEN** 用户在详情页连续加载下一段摘录后返回顶部
- **THEN** 摘录按分块序号递增显示，不重复、不跳号
- **AND** 每个分块仍显示自己的页码或段落范围

#### Scenario: 原文视图不执行材料内容

- **GIVEN** 材料正文包含 HTML 标签或脚本片段
- **WHEN** 用户打开原文视图
- **THEN** 这些内容以纯文本显示，不生成可执行元素
- **AND** 页面不因材料内容发起额外请求

### Requirement: 材料就绪不改变图谱状态

材料就绪 SHALL 只使第一阶段的“至少一份材料”条件得到满足，MUST NOT 把证据图谱标记为已构建。材料列表、摘录与来源定位 MUST 与“测试任务”面板相互独立：任一侧的加载、失败或重试 MUST NOT 改写另一侧的状态，也 MUST NOT 改变阶段进入条件或生成图谱节点。

#### Scenario: 材料就绪后图谱仍待构建

- **GIVEN** 项目已有至少一份就绪材料
- **WHEN** 项目所有者打开第一阶段
- **THEN** 材料列表显示就绪材料，图谱区域仍显示“待构建”或等价的未完成说明
- **AND** 不显示节点、边、进度百分比或“已完成”

#### Scenario: 材料失败不影响其他阶段外壳

- **GIVEN** 项目唯一一份材料解析失败
- **WHEN** 项目所有者打开第一阶段与第二阶段
- **THEN** 第一阶段显示失败原因与重新上传入口，第二阶段仍按缺少前置条件说明
- **AND** 工具条、阶段导航、布局与语言保持可用

#### Scenario: 材料区与测试任务面板互不改写

- **GIVEN** 材料列表加载成功，而测试任务面板请求失败
- **WHEN** 用户在页面上重试测试任务面板
- **THEN** 材料列表保持已加载的内容与状态
- **AND** 材料区的错误或重试不会把测试任务标记为失败或成功

#### Scenario: 测试任务列表不包含材料解析任务

- **GIVEN** 同一项目既有材料解析任务，也有最近一次连通性测试任务
- **WHEN** 用户打开测试任务面板的任务列表
- **THEN** 列表只包含连通性测试任务，不出现材料解析的 `jobId`、文件名称或页数
- **AND** 材料解析的进度与结果只在材料区显示
