# Proposal

## Why

证据图谱已经能把材料变成可追溯的主体、事件、关系与原文位置，但第二阶段仍只是一句“角色与环境尚未配置”。项目所有者无法把一次已完成的建图变成可审阅的角色画像、活跃时段、双平台配置、初始话题与轮数安排，也无法保证后续双平台推演使用的是同一份 build 与同一份已发布快照。若直接进入 Change 09，角色、环境与轮数会缺少稳定的事实来源，多个 build 之间也容易混用主体。

本变更把第二阶段做成可交付能力：从指定 build 的最终已发布快照选出有来源、能参与讨论的主体，由 worker 生成并发布角色画像与环境配置，把材料事实与模拟设定分开显示，并在用户确认后冻结本次选择，供 Change 09 读取。默认启动、默认验收与 CI 仍保持零真实外呼。

## What Changes

- 新增“准备角色与环境”的绑定上下文：进入第二阶段时，后端复用项目归属校验，核对传入的 build 与 `canContinue`，只接受该 build 已发布且 `complete=true` 的最终快照，并把 `buildId`、`snapshotId`、推演问题固定到本次准备。直接进入、图谱未完成、打开旧 build、准备期间又建新图都有明确行为，准备不能从一个快照取角色、从另一个快照取来源。
- 新增角色候选与画像生成：按 EchoSim 实际发布的快照读取中文显示类型、英文类型与旧快照的 `其他主体`，不依赖可能为空的 `summary`；只选取有有效材料来源、且能作为人物/群体/组织/机构/媒体机构参与讨论的主体。事件、待核实说法、报告建议与平台渠道不成为角色；只出现在关系终点的主体仍可入选，关系起点身份本身不作为资格证明。节点引文只证明主体被提及；把话题写成角色表达过的关注必须有支持该归属的原句，只有关联时显示“材料涉及的话题”，无背景或关注证据时显示“材料未说明”。材料陈述保留原 `claimNature`，旧边为空时保留未知；模型补充的动机、立场、活跃习惯与关注点明确标为“模拟设定”。真实模型与替身都接收本次绑定的推演问题。
- 新增环境配置与就绪判定：服务端生成并发布角色活跃时段、两个平台的稳定别名与原生平台映射、初始话题、首发角色与激活顺序；`platform_a/twitter` 与 `platform_b/reddit` 是平台映射，Change 06 的 `create_post`/`create_comment` 只是连通性探针动作，不写成后续唯一允许动作。只有角色、来源、顺序、平台、话题与时间配置全部通过校验时才进入 `ready`，前端不得自行推断。
- 新增基于现有 worker 的准备任务：使用新的 run 类型与操作键，复用领取、租约、`run_steps`、`jobs.next_step`、持久事件与 SSE；固定步骤完成候选、分批画像、配置、校验与发布。每批画像通过来源校验后即可在准备接口中预览，页面标明“准备中”；SSE 只传标识与计数。刷新恢复已完成批次，worker 接手不重复生成已提交批次。同一 build 的普通开始遇到 `preparing` 或 `ready` 返回 200 原准备；只有失败或取消后用户点重试才创建新的准备/job/run 并返回 202。整套角色、平台、话题与顺序仍在最后一步原子发布，预览不能确认或启动第三阶段。
- 新增自动/手动轮数与冻结选择：默认 72 小时、每轮 60 分钟，服务端计算为 72 轮；用户可切换手动并保存其他轮数（如 40、3），刷新后从服务端读回同一值；零时长、非整除、越界或非法轮数在保存与确认时给出具体原因。确认请求必须携带用户最后读到的 `settingsRevision`，服务端在同一事务内核对版本并冻结，版本不一致返回 `settings_conflict` 且不创建冻结记录；相同版本重复确认返回同一 `selectionId`。冻结数据保留推演问题、角色、轮数、平台映射、初始话题的来源性质以及首发角色与话题的对应关系，Change 09 只能读取这份冻结核查结果。
- 新增第二阶段工作台：显示真实准备结果与准备中的分批角色预览、三类角色详情与来源跳转、材料事实与模拟设定的视觉区分、活跃时段、双平台映射、初始话题、首发角色与激活顺序；提供普通开始、失败/取消后的显式重试、轮数编辑、保存、确认与错误恢复。预览批次可展开但不能确认或进入第三阶段；图谱未完成、无角色、资源不存在、匿名访问、他人项目与模型不可用均显示可区分状态。
- 扩展验收：`make verify CHANGE=2026-11-24-prepare-agent-environment` 用原创小材料覆盖中文快照筛选与三个反例、材料提及/关联/表达/模拟设定分层、第一批预览、普通开始/重试、两页并发确认、轮数持久化、冻结、匿名/跨项目/资源不存在、无角色、零时长、非法轮数与模型不可用；默认使用测试替身，报告 `calls.real=0`。作者私有材料只用于私有项目人工走查；私有 PDF、含正文截图、真实画像与模型原始输出留在仓库外，`docs/acceptance/` 只记录脱敏结论与必要标识，不进入自动化、日志或报告。

## Capabilities

### New Capabilities

- `agent-environment-preparation`: build 与最终快照绑定、角色候选筛选、材料来源与模拟设定区分、画像/活跃时段/双平台/初始话题/首发顺序生成、worker 准备任务与发布就绪、自动/手动轮数、保存读回、确认冻结与 Change 09 读取契约、重复开始/刷新/接手/失败边界。

### Modified Capabilities

- `project-workbench`: 第二阶段从“角色与环境尚未配置”的空态改为真实准备面板；保留阶段深链接、布局/语言与 build 上下文，增加准备进度、角色详情、来源跳转、轮数编辑、确认与可区分错误状态。
- `background-job-queue`: 新增 `agent.environment.prepare` run 类型与按 build 的操作键，复用既有领取、租约、步骤事务、接手与终态语义；准备任务不得混入测试任务面板，失败或取消不得发布半成品。
- `run-event-stream`: 新增准备任务事件语义：事件只携带准备标识、build/快照标识、批次标识、阶段、计数与原因码，不携带角色正文或材料正文；刷新与重连先读取受鉴权的准备详情，再按游标补齐事件，终态后以准备详情为准。
- `reproducible-verification`: 新增 Change 08 专属离线场景、报告字段与零真实外呼断言；覆盖角色来源、三类角色、事实/假设区分、换材料、轮数读回、冻结、无效配置与边界错误，并继续区分自动化结论与人工走查。

## Impact

- 代码：新增准备服务与路由、worker 准备执行分支、模型画像适配器与测试替身、数据库前向迁移、第二阶段面板与角色/环境子组件；不改变健康检查、会话、项目隔离、材料入库、证据图谱与测试任务语义。
- 数据库：新增准备、角色、角色来源、平台配置、话题、激活顺序与冻结选择记录；角色与来源通过复合外键绑定同一 `snapshot_id`，不使用 `create_all()`；扩展 `runs.kind`。
- 接口：新增准备上下文读取、普通开始、失败/取消后的显式重试、准备详情与分批预览、轮数保存、确认冻结接口；所有接口先鉴权与项目归属，匿名 401、他人/不存在统一 404，图谱未完成 409，普通开始遇到失败/取消返回 `preparation_retry_required`，无效轮数 422，确认版本冲突 409，模型不可用进入失败终态并返回稳定原因码。
- 配置：新增准备 provider/替身开关、默认时长与每轮分钟数、手动轮数边界、画像批次与超时；同步 `.env.example`、`docker-compose.yml`、`app/config.py` 与 README。
- 验收：默认 `make verify` 增加轻量第二阶段回归；Change 08 专属场景使用原创微型材料与 stub provider，不读取私有样本、不注入真实密钥、不发起真实模型调用；CI 复用同一 `make verify` 入口。
- 非目标：不实现双平台实际推演、报告生成、深度互动、平台账号凭据、真实分轮调度、跨项目角色共享、人工编辑角色画像或把私有材料与截图写入仓库。
