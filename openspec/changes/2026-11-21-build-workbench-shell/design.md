# Design

## Context

本变更基于 `da980bc`（Change 02 合并提交）。当前前端只有 `/login`、`/`（项目列表）、`/projects/:id`（详情）与 `/history`，路由守卫把除登录页外的所有页面都当作私有页面；后端已提供 `GET /health`、`GET /api/auth/session`、`GET /api/projects`、`GET /api/projects/{id}` 与既有 401/404/503 契约，`app/static.py` 的 SPA 回退已能把未知路径交给前端路由。

本次不新增阶段数据接口，也不改变后端鉴权与归属校验；前端必须在没有材料、运行与报告数据的前提下，仍能提供可审阅、可深链接、不会伪造进度的工作台外壳。约束来自 `AGENTS.md` 与既有规范：同域相对路径、仅回环绑定、健康检查语义不变、私有数据只对所有者可见、`make verify` 只用 Python 标准库并绑定 SHA。

需求见 `specs/guided-console/spec.md`、`specs/project-workbench/spec.md`，以及对 `project-isolation` 与 `reproducible-verification` 的 delta。

## Goals / Non-Goals

**Goals:**

- 用一张稳定路由表把“公开控制台 → 登录 → 我的项目 → 项目详情/工作台阶段 → 历史”串起来。
- 用单一阶段注册表同时驱动阶段导航、深链接、进入条件、双语名称与空态文案，避免五处硬编码。
- 让布局、语言、项目与阶段都能从 URL 恢复，刷新和复制地址不丢上下文。
- 把“没有数据”和“服务故障”做成不同的可见状态，并明确当前版本的承诺边界。
- 把可由 HTTP/构建验证的断言交给 `make verify` 与 `npm run build/typecheck`，把布局、语言、截图与历史行为留给人工走查。

**Non-Goals:**

- 不实现材料上传/入库、证据图谱计算、角色与环境配置、双平台运行、报告生成、深度互动或案例回放。
- 不新增后端业务接口、数据库表、迁移或配置项；不改变 API 的 401/404/503 契约。
- 不引入 Pinia、i18n 库、CSS 框架、端到端浏览器测试框架或新的运行时依赖。
- 不做完整移动端适配；本次只承诺 `1280×720` 与 `1440×900` 桌面视口的验收。
- 不把控制台做成营销落地页；它只承担状态说明、阶段导航与“开始”入口。

## Decisions

### 1. 路由表与访问边界

路由保持 Vue Router 4 的 history 模式，后端静态回退无需改动。路由与页面职责如下：

| 路径 | 访问 | 页面/行为 |
| --- | --- | --- |
| `/` | 公开 | 中文控制台；不展示项目列表，不强制登录 |
| `/login` | 公开 | 登录页；已登录访问时跳 `/projects` |
| `/projects` | 私有 | 我的项目 + 创建表单；登录默认落点 |
| `/projects/:projectId` | 私有 | 项目详情；提供进入第一阶段工作台的链接 |
| `/projects/:projectId/workbench` | 私有 | 重定向到 `evidence-graph`，保留查询参数 |
| `/projects/:projectId/workbench/evidence-graph` | 私有 | 第一阶段 |
| `/projects/:projectId/workbench/roles-environment` | 私有 | 第二阶段 |
| `/projects/:projectId/workbench/dual-platform-run` | 私有 | 第三阶段 |
| `/projects/:projectId/workbench/report` | 私有 | 第四阶段 |
| `/projects/:projectId/workbench/interaction` | 私有 | 第五阶段 |
| `/history` | 私有 | 历史；条目链接到 `/projects/:projectId` |
| `/:pathMatch(.*)*` | 公开 | 重定向 `/` |

守卫规则：

- 公开路由（`/`、`/login`）不因未登录而跳转；访问 `/login` 时若已有会话，跳 `/projects`。
- 私有路由先调用 `ensureSession()`；无会话时跳 `/login?next=<完整 fullPath>`。`next` 只接受以单个 `/` 开头的站内路径，拒绝 `//host` 与绝对 URL，避免开放重定向；无合法 `next` 时登录成功进入 `/projects`。
- 会话查询返回 503 时允许进入私有页面，由页面显示“服务暂时不可用”并提供重试；不把暂时故障误判为退出登录。
- 工作台阶段路由仍通过 `GET /api/projects/:projectId` 解析项目；他人项目、不存在项目、非法 UUID 的 API 404 统一进入“项目不存在”，只有项目解析成功后才判断阶段是否合法。
- 未知路径由 catch-all 送回公开控制台；非法阶段不交给 catch-all，因为它匹配 `:stage` 参数，需在工作台内显示“阶段不存在”。

理由：保留既有 `/projects/:id` 与 `/history` 链接，避免重写项目 API；把列表迁到 `/projects` 后，`/` 可以安全地作为公开入口。备选方案是使用 `/workspace/:id/:stage`，但会制造两套项目地址，增加历史与详情链接的迁移成本，放弃。

### 2. 项目列表迁移与登录落点

现有 `ProjectsView` 从 `/` 移到 `/projects`；`/` 使用新的 `ConsoleView`。`LoginView` 的 `nextPath()` 从“默认 `/`”改为“合法 `next` 或 `/projects`”，并加强站内路径校验。项目列表、项目详情与历史页内部链接统一更新：

- 列表条目：`/projects/:id`（不变）。
- 历史条目：`/projects/:id`（不变）。
- 详情页“返回项目列表”：`/projects`（由 `/` 改为新地址）。
- 详情页新增“进入工作台”：`/projects/:id/workbench/evidence-graph`。
- 工作台“返回项目”/“查看详情”：`/projects/:id`；“查看历史”：`/history`；“返回控制台”：`/`。

登录成功无 `next` 时进入 `/projects`；从控制台“开始”触发登录时显式带 `next=/projects`，因此登录后直接看到创建入口或项目列表，而不是回到控制台。

### 3. 公开控制台的信息架构与状态

`ConsoleView` 使用两栏布局：

- 左栏：品牌/标题、系统状态（`检查中 / 可用 / 降级 / 不可达`）、账户状态（`访客 / 已登录`）、五个阶段的编号、名称与一句说明。
- 右栏：材料入口卡片（说明材料入库将在后续变更开放，不提供上传控件）、至少三个静态推演问题、“开始”主按钮与按钮状态说明。
- 页面底部或右栏底部可放“当前版本能力边界”说明，明确不能上传材料、运行推演或生成报告。

系统状态只由 `GET /health` 驱动，并保留“检查中”这一独立状态；账户状态由 `ensureSession()` 驱动，二者不互相推断。`/health` 503 时页面仍完整可读，不白屏、不跳登录。页面不请求项目列表，除非用户已登录且需要决定“开始”的去向。

“开始”按钮使用可枚举的状态机，而不是点击时临时猜测：

| 状态 | 按钮表现 | 点击结果 |
| --- | --- | --- |
| 会话检查中 | 禁用或显示“准备中” | 不导航 |
| 访客 | 可点击“开始” | `/login?next=/projects` |
| 已登录，项目列表加载中 | 禁用或显示“准备中” | 不导航 |
| 已登录，项目数为 0 | 可点击“开始” | `/projects?intent=create` |
| 已登录，项目数 ≥ 1 | 可点击“开始” | `/projects/<最近创建项目 ID>/workbench/evidence-graph` |
| 已登录，项目列表 503/网络失败 | 可点击但文案提示服务不可用 | `/projects`，由列表页显示错误 |

“最近创建”直接使用现有 `GET /api/projects` 已按 `created_at desc` 返回的第一项，不新增接口。`/projects?intent=create` 由项目列表页读取一次查询参数：滚动创建表单到视口并聚焦名称输入框，不自动创建，也不清除 `intent` 之外的现有状态。

材料入口使用页内锚点 `#materials`；点击后定位到材料说明卡片，文案明确“材料入库尚未开放”，不出现上传控件、成功提示或需要登录后才能使用的假入口。推演问题为静态文本，不写入数据库。

### 4. 阶段注册表作为单一事实来源

新增前端模块（建议 `web/src/workbench/stages.ts`）声明五个阶段：

| id | slug | 中文 | English | 进入条件 | 缺少时继续到 |
| --- | --- | --- | --- | --- | --- |
| 1 | `evidence-graph` | 构建证据图谱 | Build evidence graph | 至少一份材料 | 控制台材料入口 |
| 2 | `roles-environment` | 准备角色与环境 | Prepare roles and environment | 阶段 1 已构建 | `/workbench/evidence-graph` |
| 3 | `dual-platform-run` | 双平台运行 | Dual-platform run | 阶段 2 已准备 | `/workbench/roles-environment` |
| 4 | `report` | 生成报告 | Generate report | 阶段 3 已完成 | `/workbench/dual-platform-run` |
| 5 | `interaction` | 深度互动 | Deep interaction | 阶段 4 已生成 | `/workbench/report` |

每个条目至少包含 `id`、`slug`、`order`、`title.zh`、`title.en`、`purpose.zh`、`purpose.en`、`prerequisite` 与 `continueTo`。阶段导航、深链接校验、控制台五阶段列表、工作台标题与空态文案都从该表派生，避免控制台与工作台顺序不一致。

当前版本没有阶段数据接口，注册表额外标记本阶段“数据尚未接入”。工作台据此渲染空态/缺少前置条件，不能显示示例材料、虚假节点、完成百分比、运行日志或报告下载。未来变更只需替换阶段数据源，不改变路由与进入条件语义。

### 5. 工作台外壳、三种布局与区域

新增 `WorkbenchView`（或 `WorkbenchShell` + 阶段内容组件），外层负责项目解析、阶段解析、状态机、布局与语言；内层只渲染当前阶段内容。根元素写入 `data-layout` 与 `data-stage`，供浏览器走查与将来端到端测试定位；这不是对外 API，但能让“当前布局/阶段”可检查。

| 区域 | 图谱 | 双栏（默认） | 工作台 |
| --- | --- | --- | --- |
| 顶部工具条 | 显示 | 显示 | 显示 |
| 阶段导航 | 显示 | 显示 | 显示 |
| 项目/阶段侧栏 | 不显示 | 不显示 | 左侧显示 |
| 主内容/画布 | 全宽画布 | 左侧主区 | 中央主区 |
| 材料与问题上下文 | 折叠为工具条抽屉 | 右侧栏 | 右侧栏 |
| 阶段摘要 | 画布下方摘要条 | 左侧主区内 | 左侧或底部 |
| 底部状态栏 | 不显示 | 不显示 | 显示 |

实现上用同一 DOM 结构与 CSS Grid 区域切换，布局切换只改变 grid template / 区域显隐，不重新挂载阶段页面，从而保留滚动位置以外的当前阶段与 URL。材料/问题抽屉在图谱布局中默认关闭，打开时覆盖在画布右侧，不挤压画布宽度。顶部工具条在三种布局中保持 sticky，并在 `1280×720`、`1440×900` 下不遮挡主内容。

### 6. URL 状态、历史与刷新

- `layout` 取值 `graph|split|workbench`，默认 `split`；`lang` 取值 `zh|en`，默认 `zh`。缺失或非法值只影响有效状态，不报错、不跳转。
- 用户切换布局/语言时用 `router.replace` 更新当前路由的 `query`，保留 `params` 与另一个查询参数；因此不会新增后退步骤。
- 阶段导航用 `router.push`，使浏览器后退能回到上一阶段，且 `router` 自动保留当前查询参数。
- `/workbench` 无 slug 时由路由重定向到 `evidence-graph`，保留 `query`。
- 刷新时 `useRoute()` 重新解析 `layout`、`lang`、`projectId`、`stage`，所有状态从 URL 恢复，不依赖 `localStorage`。
- “返回控制台”使用 `router.push('/')`；浏览器后退回到离开前的完整工作台地址。
- 切换语言时更新 `document.documentElement.lang`；离开工作台回到中文控制台时恢复 `zh`。
- 非法阶段不重定向、不写回默认值，页面显示“阶段不存在”并列出五个有效阶段链接；这样用户能理解地址错误，而不是被静默送回首页。

理由：查询参数比路径段更适合“视图设置”，复制链接即可复现；`replace` 避免布局切换污染历史；`push` 用于阶段导航与返回控制台，保证后退符合用户对“页面跳转”的预期。备选方案是把布局/语言放进路径，但会让五个阶段地址膨胀成多条组合路径，放弃。

### 7. 四态与错误分类

工作台在项目解析和阶段解析后进入明确的状态机：

| 状态 | 触发 | 可见表现 | 是否保留 URL |
| --- | --- | --- | --- |
| 加载中 | 项目或阶段数据请求进行中 | 加载提示/骨架；不显示空数据或错误 | 是 |
| 空数据 | 项目成功加载，但阶段缺材料或前置阶段 | “还没有材料”或“缺少前置条件”，并给出继续入口 | 是 |
| 错误 | 401、404、503、非法阶段、网络失败 | 按原因显示对应文案与操作 | 是（401 跳登录除外） |
| 正常 | 阶段所需数据存在且请求成功 | 阶段内容与下一步操作 | 是 |

具体映射：

- 401：清除前端会话状态，跳 `/login?next=<当前完整地址>`；数据库不可达但无 Cookie 时仍先 401，符合既有契约。
- 404：显示“项目不存在”（英文 `Project not found`）；他人项目、随机 UUID、非法项目 ID 必须完全一致。只有项目成功解析后，非法 `stage` 才显示“阶段不存在”（英文 `Stage not found`）。
- 503：显示“服务暂时不可用”（英文 `Service temporarily unavailable`）与“重试”；不清 Cookie、不跳登录。重试重新执行项目解析。
- 网络失败：与 503 同属“服务不可用”类，但文案区分“无法连接”，同样提供重试。
- 空数据：使用中性样式与“继续”链接，不使用错误红色；必须能让用户说出“还没有材料”与“服务暂时不可用”的区别。

当前版本没有阶段数据源，因此正常分支只保留渲染契约；实际项目会稳定落在空数据态。实现时不得用 `setTimeout` 或示例数据伪造“正常”状态。

### 8. 中英文界面

采用项目内轻量字典（建议 `web/src/i18n.ts`），不引入 i18n 库。字典按工作台外壳键组织：工具条、阶段标题/说明、布局名、材料/问题标题、按钮、加载/空/错误/重试、404/503/非法阶段。控制台本身保持中文；从英文工作台返回控制台时恢复中文与 `documentElement.lang='zh'`。

项目名称、项目 ID、阶段 slug 不翻译。已知的 401/404/503 与网络错误使用当前语言映射；不直接拼接后端中文 `detail` 作为主提示，避免英文界面出现中英混排。后端响应仍保持既有中文契约，不影响 API 消费者。

### 9. 响应式与可核查标记

控制台在宽屏使用两栏 Grid，右栏的“开始”按钮放在粘性操作区，保证 `1280×720` 首屏可见；阶段列表使用紧凑行高与不超过两行的说明。工作台在 `1280×720` 与 `1440×900` 下：

- 图谱布局只保留工具条、阶段导航、画布、摘要条，避免右栏压缩画布。
- 双栏布局右栏宽度设置最小值，主区 `min-width: 0` 防止画布溢出。
- 工作台三栏使用固定侧栏 + 可伸缩中央区，底部状态栏不遮挡内容。
- 全页 `overflow-x: hidden` 只作为兜底；验收仍要求无横向滚动。

可核查标记：控制台根元素带 `data-view="console"`，工作台根元素带 `data-layout` 与 `data-stage`；主按钮带稳定的可访问名称（中文“开始”，英文“Start”）；阶段导航当前项带 `aria-current="step"`；布局与语言按钮带 `aria-pressed`。这些标记不替代可见文案，只让浏览器走查和未来自动化更可靠。

### 10. 验收分工：自动化、浏览器与截图

**自动化可验证（`make verify` / 构建）：**

- `npm ci && npm run typecheck && npm run build` 通过，构建产物包含控制台与工作台路由代码。
- `make verify` 在创建项目后追加 HTTP 场景：`/`、`/projects` 与五个工作台阶段深链接均返回 200 且正文包含 `EchoSim`；`/api/projects` 仍返回 JSON/既有状态码，未被 SPA 回退吞掉。
- 保留 Change 01/02 全部既有场景：首页、`/health` 200/503/200、`/livez`、容器身份不变、A/B 隔离、停库 401/503、恢复后同一 Cookie、退出失效、重新登录仍可见、连续执行。
- 自动化只证明“URL 能交付前端入口”和既有 API 回归，不证明布局、语言、截图或浏览器历史。

**浏览器人工走查（实施后写入 `docs/acceptance/`）：**

- `1280×720` 与 `1440×900` 打开控制台，核对左右栏、五阶段、材料/问题、主按钮可见可操作，并保存两种尺寸的原创截图。
- 在同一自有项目的非首页阶段，中英文各走一次「图谱」「双栏」「工作台」，记录切换后的预期 URL、当前阶段与可见区域；再刷新、点击阶段导航后退、返回控制台再后退。
- 通过深链接打开缺少前置数据的阶段，核对提示与继续链接，再返回控制台继续。
- 覆盖非法阶段、匿名访问私有地址、项目不存在、访问他人项目、数据库停止后的 503、恢复后重试。
- 保留 Change 01/02 仍适用的浏览器回归：登录、刷新保持登录、关闭重开需重新登录、退出后旧会话失效、B 看不见 A 的项目、他人与不存在项目页面一致。

### 11. 能力—场景—验证方式对应表

| 能力 | 场景 | 验证方式 |
| --- | --- | --- |
| guided-console | 访客打开 `/` 看到公开中文控制台，不跳登录 | 浏览器走查 |
| guided-console | 五阶段顺序与说明 | 浏览器走查；代码审查阶段注册表 |

## Risks / Trade-offs

- [书签或文档仍把 `/` 当项目列表] → 在 README 明确 `/` 改为控制台、`/projects` 为列表；登录默认落点与详情页“返回项目列表”同步修改；验收覆盖旧链接。
- [公开控制台需要额外请求项目列表来区分“有项目/无项目”，增加首屏请求] → 仅在已登录时请求，加载期间禁用“开始”；503 时回退 `/projects`，不猜测。
- [布局与语言行为只能人工验证，回归成本高] → URL 作为唯一状态源，`data-layout`/`data-stage` 提供稳定标记；本轮不引入浏览器自动化，后续可在此标记上增加 Playwright。
- [五阶段当前全为空态，容易被误认为功能损坏] → 空态文案明确“当前版本未接入”，给出材料入口或前置阶段链接，并在控制台说明能力边界。
- [英文翻译遗漏导致中英混排] → 使用单一日志字典并覆盖工具条、阶段、布局、按钮与错误；人工中英文各走一轮三种布局；后端 `detail` 不作为主提示。
- [`next` 参数可能被构造成外部跳转] → 只接受单 `/` 开头且非 `//` 的站内路径，非法时回退 `/projects`；补单元/手动检查。
- [图谱布局隐藏上下文栏可能导致用户找不到材料/问题] → 工具条保留显式入口，打开为覆盖抽屉；验收检查入口可发现。
- [三种布局共用 DOM 但 CSS 区域不同，可能出现溢出或遮挡] → 在 1280×720 与 1440×900 实机核对，主区 `min-width: 0`，工具条 sticky，必要时缩短阶段说明。
- [SPA 回退让所有深链接都返回 200，HTTP 验收无法证明页面内容] → 自动化只声明路由可访问，页面布局、鉴权与状态由浏览器走查；报告中明确区分。

## Migration Plan

1. 合并前完成前端路由与页面改造，运行 `npm ci && npm run typecheck && npm run build`。
2. 合并后 `make up` 重建前端静态产物；无数据库迁移、无配置变更。旧数据卷不受影响。
3. 既有用户书签 `/` 会看到公开控制台；项目列表迁移到 `/projects`，详情与历史地址不变。README 与人工走查步骤同步更新。
4. 回滚：回退前端镜像/提交即可恢复 `/` 为项目列表；无数据迁移需要撤销，后端接口保持兼容。
5. 验收：提交后在干净工作树连续执行两次 `make verify`，再按人工走查步骤记录两种尺寸截图、中英文三种布局、刷新/后退/返回与异常边界，并把记录与同一 SHA 对齐。本轮只交付规约，不执行上述实施与验收。
