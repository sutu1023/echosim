# Spec Delta

## Purpose

让 EchoSim 的项目拥有明确所有者，并保证任何用户只能看到、打开自己创建的项目与历史；越权访问与项目不存在对外完全等价，为后续材料、运行与报告提供统一可复用的隔离边界。

## ADDED Requirements

### Requirement: 创建项目

已登录用户 SHALL 能创建项目，项目创建者即成为唯一所有者；项目名称 MUST 去除首尾空白后长度在 1–80 字符之间，描述可选且不超过 500 字符。非法输入 MUST 返回 422 且不写入任何项目或历史记录。

#### Scenario: 创建成功并写入历史

- **WHEN** 已登录用户 A 提交名称 `城市韧性推演` 与一段描述
- **THEN** 返回 201，响应包含新项目 `id`、`name`、`description` 与创建时间
- **AND** 该项目的所有者是 A
- **AND** 历史入口中新增一条该项目的事件记录

#### Scenario: 名称被规范化

- **WHEN** 用户提交名称 `  城市韧性推演  `
- **THEN** 存储与返回的名称是去除首尾空白后的 `城市韧性推演`

#### Scenario: 非法输入不落库

- **WHEN** 用户提交空名称、仅含空白的名称、超过 80 字符的名称、超过 500 字符的描述或非字符串字段
- **THEN** 返回 422 并指出校验失败的字段
- **AND** 项目列表与历史记录的数量保持不变

### Requirement: 项目列表仅包含自有项目

项目列表 SHALL 只返回当前登录用户拥有的项目，按创建时间倒序排列；不得返回数量、名称或标识等他人项目的任何信息。

#### Scenario: 两个用户互相不可见

- **WHEN** 用户 A 创建项目后，用户 B 请求项目列表
- **THEN** B 的列表不包含 A 的任何项目，也不包含 A 项目的数量统计
- **AND** B 创建自己的项目后，B 只能看到自己的项目，A 的列表也只包含 A 的项目

#### Scenario: 刷新后列表仍可见

- **WHEN** A 创建项目后在浏览器刷新项目列表页
- **THEN** 页面重新请求列表接口并展示该项目
- **AND** 项目名称、描述与创建时间与创建时一致

### Requirement: 项目详情仅所有者可见

项目详情 SHALL 仅对项目所有者返回 200；对已认证但不是所有者的用户，以及不存在或格式非法的项目 ID，MUST 返回完全相同的 404 状态码与响应体，不得区分“无权访问”与“不存在”。

#### Scenario: 所有者打开详情

- **WHEN** A 请求自己项目的详情
- **THEN** 返回 200，响应包含该项目的名称、描述与创建时间

#### Scenario: 他人访问与不存在等价

- **WHEN** B 请求 A 的项目 ID，随后请求一个从未存在的合法 UUID
- **THEN** 两次响应状态码均为 404，响应体字节相同，均为 `{"detail":"项目不存在"}`
- **AND** 两次响应都不包含项目名称、所有者信息或“无权访问”之类的差异提示

#### Scenario: 非法项目 ID 与不存在等价

- **WHEN** 已登录用户请求格式非法的项目 ID（例如 `not-a-uuid` 或超长字符串）
- **THEN** 返回 404 与同一 `{"detail":"项目不存在"}` 响应体
- **AND** 不返回 500，也不暴露 ID 解析细节

### Requirement: 历史入口只聚合自有项目事件

系统 SHALL 提供跨项目的最近历史入口，只返回当前用户自有项目的事件，按发生时间倒序并限制最大条数；历史条目 MUST 能跳转到对应项目详情。

#### Scenario: 历史包含自有项目事件

- **WHEN** A 创建项目后打开历史入口
- **THEN** 历史列表包含该项目的一条创建事件，含项目名称、事件类型与发生时间
- **AND** 每个条目都能导航到该项目详情

#### Scenario: 历史不泄露他人项目

- **WHEN** B 在 A 创建项目后打开历史入口
- **THEN** B 的历史列表不包含 A 的项目名称、项目 ID 或事件
- **AND** 即使 B 知道 A 的项目 ID，也无法通过历史条目或跳转取得该项目数据

#### Scenario: 匿名无法读取历史

- **WHEN** 未登录客户端请求历史接口
- **THEN** 返回 401 与统一未认证文案，而不是空列表

### Requirement: 服务层统一归属校验

项目归属校验 SHALL 集中在服务层的单一入口，按“当前用户 + 项目 ID”解析出可访问项目；接口层不得自行拼装归属过滤条件，后续材料、运行与报告能力 MUST 复用同一入口。

#### Scenario: 一切项目访问都经过同一校验

- **WHEN** 审查项目详情、列表、历史以及后续资源接口的实现
- **THEN** 单个项目的读取都调用同一归属解析入口
- **AND** 列表与历史在查询层即按当前用户过滤，不依赖调用方二次筛选

#### Scenario: 归属校验失败不区分原因

- **WHEN** 归属解析入口收到“属于他人”“不存在”“ID 非法”三种输入
- **THEN** 三种情况都产生同一种对外 404 结果
- **AND** 调用方无法从异常或响应中判断项目是否真实存在

### Requirement: 未认证优先于归属判断

所有项目与历史接口 SHALL 先完成身份校验，再执行归属解析，使匿名请求无论携带何种项目 ID 都得到统一的 401。

#### Scenario: 匿名请求任意项目 ID

- **WHEN** 未登录客户端分别请求 A 的真实项目 ID、随机 UUID 与非法字符串
- **THEN** 三个请求都返回 401 与统一未认证文案
- **AND** 响应体不透露任何项目是否存在的信息

### Requirement: 页面入口与可见性

前端 SHALL 提供登录页、项目列表页（含创建表单）、项目详情页与历史页；未登录访问私有页面 MUST 跳转到登录页，已登录访问登录页 MUST 跳转到项目列表。

#### Scenario: 已登录浏览项目路径

- **WHEN** A 登录后打开项目列表、创建项目、打开详情、打开历史
- **THEN** 页面展示的数据全部来自 A 自有项目
- **AND** 直接访问 `/projects/<A 的项目 ID>` 刷新后仍展示同一项目

#### Scenario: 未登录访问私有页面被重定向

- **WHEN** 未登录用户在地址栏直接访问项目列表、项目详情或历史页
- **THEN** 页面跳转到登录页，并在登录成功后回到原路径

#### Scenario: 他人项目与不存在项目的页面表现一致

- **WHEN** B 在地址栏输入 A 的项目详情地址
- **THEN** 页面展示与访问随机不存在的 ID 相同的“项目不存在”提示
- **AND** 页面不展示项目名称、创建时间或“无权访问”提示
