# Spec Delta

## Purpose

让 EchoSim 用本地账户建立可信身份：登录后在服务端持有会话、在浏览器只持有 HttpOnly Cookie，使刷新、重启浏览器与后端重启都不会丢失登录态，而退出或会话过期后旧凭据立即失效。

## ADDED Requirements

### Requirement: 本地账户凭据登录

系统 SHALL 接受邮箱与密码的本地凭据登录，成功时建立会话并返回当前用户信息；不提供自助注册，账户只能由管理命令创建。凭据错误时 MUST 返回与“邮箱不存在”完全相同的状态码与响应体，不得暴露账户是否存在。

#### Scenario: 有效凭据登录成功

- **WHEN** 已存在账户 `a@example.com` 的客户端提交正确的邮箱与密码到登录接口
- **THEN** 返回 200，响应体包含该用户的 `id` 与 `email`
- **AND** 响应通过 `Set-Cookie` 下发 `HttpOnly` 会话 Cookie，响应体与 Cookie 均不包含密码或其哈希

#### Scenario: 错误凭据与不存在账户不可区分

- **WHEN** 客户端以“存在的邮箱 + 错误密码”登录，随后以“不存在的邮箱 + 任意密码”登录
- **THEN** 两次响应状态码均为 401
- **AND** 两次响应体字节相同，且不提示是密码错误还是账户不存在
- **AND** 两次响应都不下发会话 Cookie

#### Scenario: 无自助注册入口

- **WHEN** 客户端尝试调用任何注册类接口，或在登录页寻找注册入口
- **THEN** 系统不提供创建账户的 HTTP 接口，登录页只有登录表单
- **AND** 只有持有数据库访问权限的管理命令才能新增账户

### Requirement: 服务端会话与 HttpOnly Cookie

登录态 SHALL 由服务端会话记录维持，Cookie 只携带不可猜测的随机会话令牌；会话记录 MUST 持久化在数据库中，且数据库不存储令牌明文。刷新页面、关闭并重开浏览器、重启后端进程都不得导致未过期的会话失效。

#### Scenario: 刷新后仍保持登录

- **WHEN** 已登录用户在浏览器刷新项目列表页
- **THEN** 前端通过会话查询接口得到 200 与同一用户信息
- **AND** 用户无需重新输入凭据

#### Scenario: 关闭并重开浏览器后仍保持登录

- **WHEN** 已登录用户完全关闭浏览器进程，并在会话有效期（默认 7 天）内重新打开站点
- **THEN** 浏览器按 `Max-Age` 继续携带会话 Cookie，站点直接展示项目列表
- **AND** 若用户使用的是退出时会清除 Cookie 的无痕窗口或手动清除 Cookie，重开后站点回到未登录状态并跳转登录页

#### Scenario: 后端重启不丢失会话

- **WHEN** 用户在登录状态下重启后端容器，随后重新请求会话查询接口
- **THEN** 该请求携带同一 Cookie 并返回 200 与同一用户信息
- **AND** 会话记录在重启前后都存在于数据库中

#### Scenario: Cookie 属性限定作用范围

- **WHEN** 检查登录响应下发的会话 Cookie
- **THEN** 该 Cookie 带有 `HttpOnly`、`SameSite=Lax`、`Path=/` 与 `Max-Age`
- **AND** 前端脚本无法通过 `document.cookie` 读取该 Cookie 的值
- **AND** 本地 HTTP 环境下不设置 `Secure`，该差异在 README 中明确说明

### Requirement: 退出登录使旧会话立即失效

退出登录 SHALL 在服务端删除当前会话记录并清除浏览器 Cookie，使退出前捕获的会话凭据在之后的请求中一律返回 401；退出只影响当前会话，不影响同一账户在其他浏览器的会话。

#### Scenario: 退出后旧会话返回 401

- **WHEN** 用户 A 退出登录，随后使用退出前捕获的 Cookie 请求任一私有接口
- **THEN** 每个请求都返回 401，响应体为统一的未认证文案
- **AND** 这些请求不返回任何项目、历史或用户数据

#### Scenario: 退出清理客户端状态

- **WHEN** 已登录用户点击页面上的“退出登录”
- **THEN** 前端调用退出接口并收到 204，随后跳转到登录页
- **AND** 响应清除会话 Cookie，再次访问私有页面会跳转登录页

#### Scenario: 重复退出保持幂等

- **WHEN** 未登录或会话已失效的客户端调用退出接口
- **THEN** 返回 204，不返回 401 或 500
- **AND** 不创建新会话、不修改其他用户的会话

### Requirement: 会话过期与失效统一处理

会话 SHALL 具有服务端可控的绝对有效期（默认 7 天，从登录时刻计算）；过期、被删除或令牌无法匹配任何记录时，私有接口 MUST 返回 401，并清除浏览器中的失效 Cookie。

#### Scenario: 过期会话被拒绝

- **WHEN** 客户端持有一个已超过有效期或被服务端删除的会话 Cookie 请求私有接口
- **THEN** 返回 401 与统一未认证文案
- **AND** 响应清除该 Cookie，前端收到 401 后跳转登录页

#### Scenario: 伪造或篡改的令牌被拒绝

- **WHEN** 客户端提交随机生成或篡改过的会话 Cookie 值
- **THEN** 返回 401，且不泄露任何用户或项目信息
- **AND** 服务端不因该请求创建会话或写入业务数据

### Requirement: 未认证请求的响应契约

所有需要登录的接口 SHALL 在鉴权阶段先于任何项目查找返回 401，因此匿名客户端无法通过响应差异探测某个项目 ID 是否存在。

#### Scenario: 匿名访问私有接口

- **WHEN** 未携带 Cookie 的客户端请求会话查询、项目列表、项目详情、历史或创建项目接口
- **THEN** 每个请求都返回 401 与 `{"detail":"未登录"}`
- **AND** 无论请求中的项目 ID 是真实存在的、属于他人的还是格式非法的，响应状态码与响应体都相同

#### Scenario: 401 响应不含内部信息

- **WHEN** 匿名请求被拒绝，且服务端记录了调试日志
- **THEN** 响应体只包含统一的 `detail` 文案
- **AND** 响应与日志都不包含 Cookie 值、密码哈希、数据库连接串、堆栈或内部主机名

### Requirement: 数据库不可达时的鉴权降级

数据库不可达时，登录、会话查询、退出与所有依赖会话的私有接口 SHALL 返回 503，而不是 500、挂起或错误地放行；响应 MUST 在 5 秒内返回，且不得下发新会话 Cookie。

#### Scenario: 数据库停机时登录失败

- **WHEN** 数据库不可用且客户端以正确凭据调用登录接口
- **THEN** 服务在 5 秒内返回 503 与 `{"detail":"服务暂时不可用"}`
- **AND** 响应不下发会话 Cookie，不修改任何数据

#### Scenario: 数据库停机时私有接口返回 503

- **WHEN** 数据库不可用且已登录客户端请求项目列表或项目详情
- **THEN** 每个请求返回 503 与统一文案，不返回 500 或空列表
- **AND** `GET /health` 仍按既有契约返回 503 `{"status":"degraded","database":"unavailable"}`，`GET /livez` 仍返回 200

#### Scenario: 数据库恢复后无需重新登录

- **WHEN** 数据库从不可用恢复，客户端使用停机前未过期的会话 Cookie 再次请求私有接口
- **THEN** 同一后端进程返回 200 与正确数据，用户无需重新登录

### Requirement: 会话型写请求的来源校验

使用 Cookie 鉴权的写请求 SHALL 校验请求来源：携带 `Origin` 头的非 GET 请求，其来源必须与当前站点同源，否则 MUST 在执行业务逻辑前返回 403 且不产生任何数据变更；不携带 `Origin` 的非浏览器客户端仍需有效的会话 Cookie 才能通过鉴权。

#### Scenario: 跨站来源的写请求被拒绝

- **WHEN** 已登录客户端以 `Origin: https://evil.example` 调用创建项目接口
- **THEN** 返回 403 与统一文案
- **AND** 数据库中没有新增项目或历史记录

#### Scenario: 同源写请求正常执行

- **WHEN** 已登录客户端以与站点同源的 `Origin` 调用创建项目接口
- **THEN** 来源校验通过，请求继续进入鉴权与业务逻辑

### Requirement: 管理命令创建账户

系统 SHALL 提供只在本机执行的管理命令创建或更新账户，用于准备测试与人工验收账号；命令 MUST 校验邮箱格式与密码强度，重复创建 MUST 失败并给出可定位的提示，且不得把密码写入日志或 shell 历史。

#### Scenario: 创建可用于登录的账户

- **WHEN** 管理员执行管理命令并输入邮箱与符合强度要求的密码
- **THEN** 命令以退出码 0 结束并输出已创建的用户邮箱
- **AND** 随后可用该邮箱与密码成功登录

#### Scenario: 重复邮箱被拒绝

- **WHEN** 以已存在的邮箱再次执行创建命令且未显式要求更新密码
- **THEN** 命令以非零退出码结束并说明邮箱已存在
- **AND** 原有账户的密码与会话不被修改

#### Scenario: 弱密码与非法邮箱被拒绝

- **WHEN** 管理员提交格式非法的邮箱或长度不足的密码
- **THEN** 命令以非零退出码结束并输出具体校验原因
- **AND** 数据库中没有新增账户

#### Scenario: 通过标准输入传入密码

- **WHEN** 管理员使用标准输入传递密码执行创建命令
- **THEN** 命令正常创建账户
- **AND** 命令输出与日志中不出现密码明文
