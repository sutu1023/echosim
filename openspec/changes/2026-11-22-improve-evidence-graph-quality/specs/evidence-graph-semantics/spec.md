# Spec Delta

## Purpose

让武大 25 页报告的整份材料进入一张可从工作台浏览的证据图谱：按原文分块写入图谱服务，读回报告中的主要事件、相关方和具体行动，并让每条关系点回支持它的原句。

## ADDED Requirements

### Requirement: 从现有材料重建建图全文与可定位分块

系统 SHALL 在建图时从项目已入库的 `document_chunks` 重建每份材料的建图全文，MUST NOT 要求用户重新上传，MUST NOT 改写材料分块或旧快照。重建 MUST 保留入库清洗后的段落、标题与正文行；同一物理页存在重叠分块时 MUST 按原始 UTF-16 区间裁掉重复前缀；不同物理页之间 MUST 保留跨页衔接。

系统 SHALL 按 500 字目标、50 字重叠切分建图分块，优先在句末切分，其次在空白处切分，只有单句超长时才硬切。每个建图分块 MUST 保存到原始材料的逐字符映射，至少包含物理页码（PDF）、材料内 UTF-16 偏移、来源材料分块序号与段落区间；映射 MUST 与分块文本一起持久化，供读回后的来源定位使用。

#### Scenario: 25 页报告重建为建图全文

- **WHEN** 项目已有 25 页 PDF 的入库分块，用户用该材料新建 build
- **THEN** 建图步骤从现有分块重建全文，保留页间衔接与正文
- **AND** 旧材料分块、旧 build 与旧快照不被改写
- **AND** 不需要用户重新上传

#### Scenario: 每个建图分块可回到原文区间

- **WHEN** 一个建图分块由某页的多个入库分块合并而成
- **THEN** 分块映射记录该页的 UTF-16 起点、终点与来源分块序号
- **AND** 后续关系原句能映射到同一页的正确区间

### Requirement: 模型基于整份报告与问题规划本体

规划步骤 SHALL 把本次选中的整份材料与情景问题交给模型，产出实体类型与关系类型。实体类型 MUST 覆盖报告中的机构、部门、当事方、群体、事件、决定/安排、媒体/平台等可识别对象，MUST NOT 使用“实体”“细节”“关系”“关联”等占位名称。关系类型 MUST 表达原文动作，MUST NOT 使用“关联”“相关”“提及”等泛化谓词作为唯一关系。

系统 MUST NOT 要求在规划阶段登记“首轮最多 24 个主体”的固定名单，MUST NOT 因某主体未在规划名单中出现而禁止后续原文分块贡献该主体。模型 MUST NOT 被要求为每个分块预先抽取节点或关系；实体实例由图谱服务从原文分块中抽取。规划结果 MUST 持久化，供建图本体设置、关系类型映射与界面显示复用。

#### Scenario: 报告后半段的主体也能进入图谱

- **WHEN** 某机构或当事方只在报告后半段出现，且未被规划阶段列为示例主体
- **THEN** 后续原文分块仍可由图谱服务抽取该主体
- **AND** 不因缺少主体白名单而丢弃该主体或其关系

#### Scenario: 占位类型被拒绝

- **WHEN** 模型把实体类型命名为“实体”或把关系类型命名为“关联”
- **THEN** 规划结果以 `invalid_model_output` 失败
- **AND** 不发布使用占位类型构建的图谱

### Requirement: 原文分块作为 episode 写入并读回本次 build 图谱

建图 SHALL 在写入前把规划本体设置到本次 build 的图谱，然后把每个建图分块的原文作为 episode 写入。episode 内容 MUST 是分块原文，MUST NOT 是模型预先抽取的 JSON 清单。每个 episode MUST 带 build 标识与分块键，沿用幂等键、写入响应丢失检索确认和旧租约拒绝。

索引与处理完成后，系统 SHALL 按本次 build 的 episode UUID 分页读回全部节点、边与事实描述，直到没有下一页。发布范围 MUST 只包含与本次 build 的 episode UUID 有交集的读回对象；MUST NOT 把旧 build、旧图谱或验收专用图谱的对象混入新快照。节点与边读回 MUST 允许超过少量抽样，不得在读回阶段按固定数量截断。

#### Scenario: 原文 episode 产生完整读回

- **WHEN** 25 页报告被切分为多个 500 字原文分块并全部写入、索引完成
- **THEN** 读回包含本次 build episode 关联的全部节点与边
- **AND** 读回对象不只限于某个模型清单中的名称
- **AND** 最终快照可以使用读回结果发布

#### Scenario: 旧 build 对象不混入

- **WHEN** 同一项目已有旧 build 或旧图谱
- **THEN** 新 build 的读回只接受本次 episode UUID 关联的对象
- **AND** 旧 build 的节点、边、来源与快照保持不变

### Requirement: 读回节点归并、边去重与支持原句定位

系统 SHALL 在发布前对读回节点按 NFKC 规范化名称归并；同一名称跨页、跨 episode 或重复读回时 MUST 只发布一个节点，并合并其来源与参与关系。不同名称 MUST 保持不同节点。系统 SHALL 按起点、终点、关系类型与规范化事实对边去重；自环边 MUST NOT 发布。

每条发布关系 MUST 关联到贡献它的 episode，并在该 episode 的原文分块中定位支持句。支持句 MUST 同时出现起点主体、动作与对象；允许使用相邻句、明确指代和有依据的简称。只有媒体名单、机构名单或实体名称而没有动作的句子 MUST NOT 作为关系来源。无法定位支持句的关系 MUST NOT 发布，但不得因此丢弃其他已能定位的关系。

#### Scenario: 同一主体跨页只出现一个节点

- **WHEN** 同一主体在不同页的多个 episode 中被读回为多个节点
- **THEN** 最终快照只保留一个同名节点
- **AND** 点选该节点能看到它在不同页参与的不同关系
- **AND** 每条关系保留各自页码与支持原句

#### Scenario: 媒体名单不能证明报道关系

- **WHEN** 一条“报道”关系只能找到媒体名称清单，而清单没有出现报道动作和事件对象
- **THEN** 该句不能作为关系来源
- **AND** 若没有其他同时支持主体、动作与对象的原句，该关系 MUST NOT 发布
- **AND** 不影响其他有效关系的发布

#### Scenario: 读回丰富但发布很少时定位损失

- **WHEN** 图谱服务读回的节点或边数量明显高于最终发布数量
- **THEN** 系统记录读回数、归并后数、去重后数与最终发布数
- **AND** 验收必须定位损失发生在节点归并、边去重、支持句定位还是快照上限
- **AND** 修复损失环节后才允许交付新图

### Requirement: 来源性质区分媒体报道、当事方主张与机构正式决定

每条发布关系 MUST 带 `claimNature`，取值 MUST 为 `media_report`、`party_claim`、`author_recommendation`、`official_decision`、`other_material` 之一。明确转述、媒体来源或“据…报道” MUST 归为 `media_report`；当事方的指控、回应、维权、主张、质疑等 MUST 归为 `party_claim`；作者或报告提出的应做事项 MUST 归为 `author_recommendation`；只有支持句明确出现决策主体与已作出动作（决定、作出、发布、通报、判决、处分等）且没有被建议/转述限定 MUST 归为 `official_decision`；其余材料陈述为 `other_material`。

来源句表达“建议、呼吁、应、提请、引入、建立、撤销、撤回、纠正”等建议或反转时，MUST NOT 被显示成已经发生的正式决定。若正式决定动作前出现“建议/呼吁/应/提请”且没有“决定/作出/已”等已发生表达，系统 MUST 将其归为 `author_recommendation` 或 `party_claim`，MUST NOT 标为 `official_decision`。`party_claim`、`media_report` 与 `author_recommendation` MUST 在快照与界面中分别显示为当事方主张、媒体报道、报告建议，MUST NOT 显示为已证实事实或机构正式决定。

#### Scenario: 建议撤销不被挂到已作出的处分下

- **WHEN** 报告作者建议“撤销处分、公开道歉”，支持句没有显示校方已经作出撤销决定
- **THEN** 该句不能证明“校方已经撤销处分”
- **AND** 若发布相关关系，必须显示为建议或当事方主张
- **AND** 不得显示成机构正式决定

#### Scenario: 媒体报道与正式决定可区分

- **WHEN** 报告分别写到媒体“报道”某一进展与校方“作出决定”
- **THEN** 两条关系分别带有 `media_report` 与 `official_decision`
- **AND** 界面分别显示“媒体报道”与“机构正式决定”

### Requirement: 新 build 使用独立图谱且旧 build 保持可读

真实 provider 的新 build MUST 使用本次 build 自己的图谱或图谱服务中按本次 episode UUID 隔离的写入范围，MUST NOT 复用旧 build 的 episode 或把旧图谱节点混入新快照。绑定创建失败或配置缺失时 MUST 以 `graph_unavailable` 或 `missing_config` 失败，MUST NOT 回退到旧 build、替身图谱或验收专用图谱。

快照 SHALL 保存归并后的节点、边、动作类型、事实摘要与 `claimNature`；节点/边来源 MUST 来自本次 build 的建图分块映射。旧快照缺少 `claimNature` 时 MUST 继续可读，性质为空，MUST NOT 回填或改写成正式决定。

#### Scenario: 旧 build 仍可对照打开

- **WHEN** 用户打开旧 build `f4c9a593-aa36-49e3-84cf-125ccaa88c21`
- **THEN** 页面正常显示旧节点、边与来源
- **AND** `claimNature` 为空，不默认成正式决定
- **AND** 旧快照未被新 build 改写

### Requirement: 平台行动方向与被转述说法的限定

当关系的起点是媒体/平台类型节点、终点是群体/个人类型节点，且动作是维权、讨论、发声、避坑、质疑、投诉、支持、反对、参与等用户行动时，最终边 MUST 改为“用户 → 平台”的方向，并标记为平台行动；界面 MUST 读成“用户在平台上行动”，MUST NOT 读成“平台向用户行动”。

当支持句包含“不实信息、谣言、传闻、据称、被指、涉嫌、所谓”等限定，且被限定对象出现在限定词附近时，系统 MUST 为被转述的说法建立“待核实说法”节点，边 MUST 标记为转述关系；目标节点标签 MUST 明确“报告所称/未证实”。不得把被转述的说法单独画成已发生事件。

#### Scenario: 女性用户在小红书上维权

- **WHEN** 读回边把平台“小红书”作为起点、把“女性用户”作为终点，动作是“维权”，支持句表达女性用户在小红书上维权
- **THEN** 最终边方向为“女性用户 → 小红书”，类型为平台行动
- **AND** 画布读成“女性用户在小红书上维权”
- **AND** 不读成“小红书向女性用户维权”

#### Scenario: 部分账号传播报告所称不实信息

- **WHEN** 支持句写“部分账号传播‘某事件’等不实信息”
- **THEN** 起点为“部分账号”，目标为“某事件（报告所称，未证实）”
- **AND** 边标签说明传播不实信息
- **AND** 不把该事件作为已发生事件单独绘制

### Requirement: 报告建议与机构决定可区分

系统 MUST 将作者或报告提出的应做事项标为 `author_recommendation`，并在界面显示“报告建议”。只有支持句明确出现决策主体与已作出动作时，才可标为 `official_decision`。建议关系 MUST 保留“建议/引入/建立/参照/推动/完善”等动作含义，MUST NOT 使用“已作出”“正式决定”等确定性标签。

#### Scenario: 匿名评审属于报告建议

- **WHEN** 第 22 页支持句写“引入第三方匿名评审机制，对研究生学位论文进行抽检”，没有决策主体已作出该决定的表述
- **THEN** 关系的来源性质为“报告建议”
- **AND** 边标签保留“建议引入”或“建议”语义
- **AND** 不标为机构正式决定

#### Scenario: 已作出的处分仍是机构决定

- **WHEN** 支持句明确写“武汉大学对肖某某作出记过处分”
- **THEN** 关系保持 `official_decision`
- **AND** 不因其它建议语句把该已发生决定降级
