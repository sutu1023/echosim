# Spec Delta

## Purpose

让首次打开 EchoSim 的访客在一个公开、中文、同源的控制台上理解系统状态与五阶段推演路径，并清楚知道“开始”在当前版本会带自己去哪里；控制台不展示任何账户的私有项目数据。

## ADDED Requirements

### Requirement: 公开中文控制台入口

系统 SHALL 在 `/` 提供公开控制台，未登录访客与已登录用户都可以直接打开，不得在进入控制台前强制跳转登录页。控制台 MUST 使用中文，采用左右两栏结构：左栏展示系统状态与五个阶段，右栏展示材料入口、推演问题与“开始”主按钮。控制台不得展示任何项目名称、项目 ID、历史事件或其他账户数据。

#### Scenario: 访客直接打开控制台

- **WHEN** 未登录访客在浏览器打开 `/`
- **THEN** 页面停留在 `/` 并渲染中文控制台，不跳转 `/login`
- **AND** 左栏显示系统状态与五个阶段，右栏显示材料入口、推演问题与“开始”按钮
- **AND** 页面不包含任何项目名称、项目 ID 或历史记录

#### Scenario: 已登录用户打开控制台

- **WHEN** 已登录用户打开 `/`
- **THEN** 页面停留在 `/` 并渲染同一控制台，系统状态区显示当前为已登录
- **AND** 控制台不直接列出该用户的项目，项目列表仍只在 `/projects` 展示

### Requirement: 系统状态来自真实探测

控制台左栏 SHALL 展示可区分的系统状态：检查中、可用、降级、不可达。服务状态 MUST 仅来自对同源 `GET /health` 的真实请求结果，不得使用固定值或仅凭前端缓存推断；项目列表或会话查询失败 MUST NOT 改写已经成功的健康检查结果。账户身份状态 MUST 与控制台的服务状态分开显示：只有会话查询明确返回 401 才视为访客，返回 200 才视为已登录，返回 503 或网络失败时显示“暂时无法确认”并保留 Cookie。状态文案不得回显数据库连接串、凭据、堆栈或内部主机名。

#### Scenario: 服务与数据库可用

- **WHEN** `/health` 返回 200 且响应体为 `{"status":"ok","database":"ok"}`
- **THEN** 控制台系统状态显示“可用”
- **AND** 已登录用户的身份状态单独显示“已登录”，不与服务可用状态混为一谈

#### Scenario: 数据库不可用时显示降级

- **WHEN** `/health` 返回 503 且响应体为 `{"status":"degraded","database":"unavailable"}`
- **THEN** 控制台系统状态显示“降级”，并说明数据库暂时不可用
- **AND** 控制台仍可阅读五阶段说明与材料/问题入口，不白屏、不跳转登录页

#### Scenario: 健康检查不可达后恢复

- **WHEN** 控制台请求 `/health` 失败或超时，随后服务恢复并再次探测成功
- **THEN** 状态先从“不可达”变为“检查中”，再变为“可用”
- **AND** 页面不需要刷新即可完成这次状态更新

#### Scenario: 健康可用但项目列表读取失败

- **WHEN** `/health` 返回 200，但已登录用户的 `GET /api/projects` 返回 503 或网络失败
- **THEN** 系统状态仍显示“可用”，不得显示“降级”或“不可达”
- **AND** 账户状态仍显示“已登录”，按钮按规约进入 `/projects`，由项目页显示读取失败并提供重试

#### Scenario: 会话查询暂时不可确认

- **WHEN** 浏览器已有会话 Cookie，但首次打开控制台时 `GET /api/auth/session` 返回 503
- **THEN** 公开控制台仍完整可读，账户状态显示“暂时无法确认”，不显示“访客”
- **AND** 浏览器 Cookie 不被清除，账户区提供“重试”
- **AND** “开始”按钮不按访客或已登录身份导航，等待身份重新确认

#### Scenario: 会话恢复后重新判断去向

- **WHEN** 会话查询从 503 恢复为 200，且用户已有项目
- **THEN** 控制台用原会话重新确认“已登录”，再读取项目列表
- **AND** “开始”按“已有项目”状态进入最近创建项目的第一阶段
- **AND** 用户不需要重新登录

### Requirement: 五个阶段的固定顺序

控制台左栏 SHALL 按以下固定顺序展示五个阶段，不得缺少、重排或把后续变更的额外阶段插入其中：

1. 构建证据图谱
2. 准备角色与环境
3. 双平台运行
4. 生成报告
5. 深度互动

每个阶段 MUST 同时展示一句可读的阶段目的，且五个阶段都可见。

#### Scenario: 首屏核对阶段顺序

- **WHEN** 访客打开控制台并阅读左栏
- **THEN** 五个阶段按“构建证据图谱 → 准备角色与环境 → 双平台运行 → 生成报告 → 深度互动”的顺序出现
- **AND** 每个阶段都有中文名称与一句说明，不出现仅编号没有名称的占位项

### Requirement: 材料入口与推演问题

控制台右栏 SHALL 提供材料入口与推演问题两个区域。材料入口 MUST 如实说明当前版本尚未开放材料入库，不得提供会失败的上传表单或伪造上传成功；推演问题 MUST 至少展示三个中文问题，用于说明后续推演要回答什么，不要求用户在此输入或保存。

#### Scenario: 材料入口不承诺未实现能力

- **WHEN** 访客点击右栏的材料入口
- **THEN** 页面说明材料入库能力将在后续变更开放，当前版本不能上传或保存材料
- **AND** 页面不出现上传控件、成功提示或需要登录后才能使用的假入口

#### Scenario: 推演问题可见

- **WHEN** 访客阅读右栏
- **THEN** 至少能看到三个中文推演问题
- **AND** 这些问题不需要登录、不会写入数据库，也不改变当前页面

### Requirement: “开始”按钮的三种确定行为

“开始”主按钮 SHALL 根据访客身份与项目数量执行确定的导航，不得停留在当前页或显示无法完成的承诺：

- 访客：进入登录页，并在登录成功后进入私有项目列表；
- 已登录且没有项目：进入私有项目列表的创建入口，让用户可以直接创建第一个项目；
- 已登录且已有项目：进入最近创建项目的第一阶段工作台。

在会话或项目列表尚未加载完成时，按钮 MUST 表明正在准备且不得按未知状态导航。只有明确收到会话 401 才按访客处理；会话 503 或网络失败时 MUST 显示“暂时无法确认”并提供重试，不得猜测身份或项目数量。项目列表读取失败时 MUST 回退到安全的 `/projects`，但不得把系统状态从“可用”改成“降级”。

#### Scenario: 访客点击“开始”

- **WHEN** 未登录访客点击“开始”
- **THEN** 页面进入 `/login?next=/projects`
- **AND** 登录成功后进入 `/projects`，不会自动创建项目
- **AND** 登录页保留返回控制台的路径，用户取消登录仍可回到 `/`

#### Scenario: 已登录且没有项目时点击“开始”

- **WHEN** 已登录用户没有任何项目并点击“开始”
- **THEN** 页面进入 `/projects?intent=create`
- **AND** 项目列表页展示创建表单，并将创建入口滚动到可见区域或聚焦名称输入框
- **AND** 不自动提交创建请求

#### Scenario: 已登录且已有项目时点击“开始”

- **WHEN** 已登录用户至少有一个项目并点击“开始”
- **THEN** 页面进入最近创建项目的 `/projects/<项目 ID>/workbench/evidence-graph`
- **AND** 工作台显示该项目名称与第一阶段“构建证据图谱”，而不是回到控制台或项目列表

#### Scenario: 项目状态不可读取时安全回退

- **WHEN** 已登录用户点击“开始”，但项目列表请求返回 503 或网络失败，而 `/health` 仍为 200
- **THEN** 页面进入 `/projects` 并由该页展示“服务暂时不可用”与重试，不猜测用户是否已有项目
- **AND** 控制台系统状态仍显示“可用”，不显示虚假的项目数量或“降级”

#### Scenario: 会话 503 时不按访客处理

- **WHEN** 浏览器带有会话 Cookie，但会话查询返回 503，用户查看控制台
- **THEN** 账户状态显示“暂时无法确认”而不是“访客”，保留 Cookie 并提供重试
- **AND** “开始”不进入 `/login`，也不进入项目工作台
- **AND** 会话恢复为 200 后，用原会话重新判断访客/已登录及“开始”的去向

### Requirement: 桌面双栏可见性

控制台 SHALL 在 `1280×720` 与 `1440×900` 两个桌面视口中完整呈现左右两栏：左栏的系统状态与五个阶段、右栏的材料入口、推演问题与主按钮 MUST 可见且可操作，主按钮 MUST 完整落在首屏视口内。两种尺寸都不得出现横向滚动、内容互相遮挡或按钮被裁切。

#### Scenario: 1280×720 下核对控制台

- **WHEN** 访客在 `1280×720` 视口打开控制台
- **THEN** 左右两栏同时可见，五个阶段与“开始”按钮无需横向滚动即可操作
- **AND** 该视口的原始截图作为实施后的验收证据保存

#### Scenario: 1440×900 下核对控制台

- **WHEN** 访客在 `1440×900` 视口打开控制台
- **THEN** 左右两栏同时可见，材料入口、推演问题与“开始”按钮完整显示
- **AND** 该视口的原始截图作为实施后的验收证据保存
