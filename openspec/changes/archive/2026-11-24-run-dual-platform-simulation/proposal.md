# Proposal

## Why

Change 08 已经把角色、平台映射、初始话题、首发顺序与轮数冻结成一份只读选择，但第三阶段仍然只是“准备已确认，运行功能待接入”的静态摘要。用户确认成果无法变成可观察的推演，也无法证明两个本地 OASIS 平台真的产生了原生动作。若继续停在占位页，冻结选择只是数据，双平台能力没有任何可验收的行为。

本变更把冻结选择真正跑起来：由独立 worker 在隔离的本地 `twitter` 与 `reddit` 环境中按冻结轮数推进，动作从引擎记录读回并落库，页面用模拟时钟、两条行动流、按平台统计与运行日志呈现结果。默认启动、默认验收与 CI 仍保持零真实模型外呼，真实本地 OASIS 动作只由开发者显式触发并单独记录证据。

## What Changes

- 新增“从冻结选择启动运行”的入口：`POST /api/projects/{projectId}/simulations` 只接受 `selectionId`，问题、角色、轮数、平台映射、初始话题与首发顺序全部来自 Change 08 的 `frozenSelection`，运行开始即把使用到的冻结载荷复制进运行记录，后续准备变化不影响已开始的运行。重复点击开始、终态后重跑与查看旧运行分别有确定的 runId 语义。
- 新增双平台原生动作契约：信息广场 `platform_a/twitter` 支持发帖、转发、点赞；话题社区 `platform_b/reddit` 支持发主题、评论、投票（赞成/反对）。两个平台各有独立的临时目录、SQLite 数据库与执行进程，不共享可变状态；动作必须由引擎实际写入后从引擎记录读回，动作调用返回值不构成证据。
- 新增模拟运行任务：新 run 类型 `simulation.run`、操作键绑定 `selectionId`，固定四步 `bind`、`environment`、`advance`、`publish`，轮次游标按平台持久化。运行由独立 worker 执行，浏览器不直接调用引擎；引擎已写入但 worker 尚未记账就中断时，接手先按原运行标记读回并补记，不重发动作。
- 新增停止与终态冻结：停止在下一个轮次边界生效，已写入引擎的那一轮先读回再进入终态；终态后轮次、动作与计数不再增长；单平台失败时保留另一个平台的全部已有结果并以失败终态结束。
- 新增第三阶段面板：模拟时钟、两个平台的行动流（含动作类型、角色、内容与目标原帖）、按平台统计、运行日志、运行选择与旧运行查看、运行中停止、失败与部分结果展示；刷新、SSE 重连与 worker 接手后，页面计数与持久记录一致。
- 新增证据模式区分：每次运行记录 `engine=double|oasis`，页面与报告明确标注“离线替身运行”或“真实本地 OASIS”。默认 `make up`、默认 `make verify` 与 CI 只使用替身引擎且零真实外呼；真实本地 OASIS 动作由开发者显式命令在隔离引擎镜像内执行并生成 `mode=live` 报告，不写入产品数据库。
- 扩展验收：默认验收新增“无冻结选择不触发运行”的轻量断言；`make verify CHANGE=2026-11-24-run-dual-platform-simulation` 追加原创材料准备与冻结、双平台三轮动作读回、目标原帖定位、停止后计数稳定、同选择重跑新 runId 与旧运行可读、单平台失败的部分结果、匿名/他人/停库边界与 `calls.real=0`。

## Capabilities

### New Capabilities

- `dual-platform-run`: 从冻结选择启动与读取运行、重复开始/重跑/旧运行的 runId 语义、双平台原生动作与隔离环境、引擎执行进程与运行数据位置、动作读回与目标原帖定位、轮次与模拟时钟、停止与终态冻结、中断接手与补记、单平台失败的部分结果、计数一致性、证据模式与访问边界。

### Modified Capabilities

- `dual-platform-simulation`: 保留 Change 06 的连通行探针，并明确双平台运行使用同一“从引擎记录读回”的纪律，探针结论不能替代运行证据，运行证据也不能反向冒充真实联通签收。
- `background-job-queue`: 新增 `simulation.run` run 类型与按 `selectionId` 的操作键、四步步骤事务与按平台轮次游标、停止在轮次边界生效、终态后写入拒绝、单平台失败不阻断另一平台、worker 按 `runs.kind` 声明可执行能力。
- `run-event-stream`: 新增模拟运行事件语义：按平台与轮次提交事件，携带运行/选择/快照标识、轮次、模拟时钟与计数，不携带动作正文或材料正文；刷新与重连以运行详情为准。
- `project-workbench`: 第三阶段从“运行功能待接入”的占位摘要改为真实运行面板，保留阶段深链接、布局/语言、冻结选择摘要与旧运行查看，增加时钟、行动流、平台统计、日志、停止与部分失败展示；同时把“第三至第五阶段没有业务数据”的四态描述收敛为“第三阶段已有真实数据、第四至第五阶段仍为空态”。
- `reproducible-verification`: 新增 Change 09 专属离线场景、`simulation_evidence` 报告字段、默认“运行未触发”断言与零真实外呼约束，并区分离线替身证据与真实本地 OASIS 人工走查结论。

## Impact

- 代码：新增运行服务与路由、worker 模拟执行分支、双平台引擎适配器与替身引擎、动作读回与目标链接、数据库前向迁移、第三阶段面板与运行状态模块；不改变健康检查、会话、项目隔离、材料入库、证据图谱与角色准备语义。
- 数据库：新增 `simulations`、`simulation_platforms`、`simulation_rounds`、`simulation_actions`；扩展 `runs.kind`；运行记录通过复合外键绑定项目、冻结选择、build 与快照。
- 接口：新增开始运行、运行列表、运行详情、动作分页、停止运行；全部先鉴权与项目归属，匿名 401、他人/不存在统一 404，缺冻结选择 409，非法选择 422，数据库不可用 503 且不清除 Cookie；事件流复用既有任务 SSE。
- 配置：新增引擎模式、运行数据目录、每轮动作预算、轮次超时、平台进程超时与替身开关；同步 `.env.example`、`docker-compose.yml`、`app/config.py` 与 README；新增隔离的 `worker-simulation` 构建目标与 Compose profile，默认不启用。
- 依赖：真实本地 OASIS 只在 `worker-simulation` 镜像内安装 `camel-oasis`，不修改 `app`/`worker-graph` 依赖；该组合必须单独完成解析、安装、导入与最小运行四阶段后才可记为 `verified`。
- 验收：默认 `make verify` 增加“无冻结选择不触发运行”的轻量断言；Change 09 专属场景使用原创微型材料与替身引擎，`simulation_evidence.calls.real=0`；CI 复用同一 `make verify` 入口。
- 非目标：不实现报告生成、深度互动、时序记忆写回（留给 Change 10）、平台账号凭据、真实外网平台、跨项目复用运行结果，也不把私有样本、真实动作日志或截图写入仓库。
