# Spec Delta

## MODIFIED Requirements

### Requirement: 加载、空数据、错误与正常四态

工作台 SHALL 分开报告“外壳状态”与“阶段内容状态”，并区分加载中、空数据、错误与正常四种页面状态。加载中 MUST 显示明确的加载提示且不得提前显示空数据文案；项目加载成功 MUST 视为“外壳就绪”，此时项目名、当前阶段高亮、工具条与三种布局都可正常操作，即使阶段内容同时显示“还没有材料”“证据图谱尚未完成”或缺少前置步骤。空数据 MUST 使用非错误文案；错误 MUST 按原因显示“服务暂时不可用”“项目不存在”“阶段不存在”“图谱不存在”“准备不存在”或“运行不存在”，并提供重试、返回控制台或有效阶段入口；正常阶段内容 MUST 只来自真实数据并展示当前阶段结果与下一步操作。用户 MUST 能区分“还没有内容”和“服务暂时不可用”。

第一至第三阶段已有真实数据接口时，产品页面 MUST 只展示真实 API 数据，不得把测试夹具或示例数据放进产品。第二阶段 MUST 分别呈现“图谱未完成”“尚未开始准备”“准备中（含分批预览）”“已就绪待确认”“已确认”“生成失败”与“已取消”，不得把其中任一状态误报为另一状态；预览角色不得显示为最终角色。第三阶段 MUST 分别呈现“尚未确认冻结选择”“运行排队中”“运行中”“已停止”“已失败（含单平台部分结果）”“已完成”与“暂无运行记录”，不得把运行中的部分计数显示为最终结果，也不得把离线替身运行显示为真实本地 OASIS 运行。第四至第五阶段尚无业务数据时，可观察的“正常”证据只是工作台外壳就绪；若保留“阶段已有业务结果”的渲染分支，MUST 只用隔离测试数据验证，并在验收记录中标记为“隔离数据验证”。

#### Scenario: 加载中不误报空数据

- **WHEN** 工作台正在读取项目或阶段信息
- **THEN** 页面显示加载提示或骨架
- **AND** 不显示“还没有材料”“尚未准备角色”“暂无运行记录”或“项目不存在”，直到请求有确定结果

#### Scenario: 空数据与 503 文案不同

- **WHEN** 项目存在但第二阶段尚未开始准备，另一时刻数据库不可用导致请求返回 503
- **THEN** 第一种情况显示“尚未准备角色与环境”与开始入口
- **AND** 第二种情况显示“服务暂时不可用”并提供重试，不把服务故障描述成没有准备

#### Scenario: 正常状态展示阶段内容

- **WHEN** 项目加载成功且阶段所需真实数据存在
- **THEN** 外壳保持就绪，页面展示该阶段的真实内容与下一步操作
- **AND** 不显示错误、空数据或加载提示

#### Scenario: 外壳就绪与阶段空态共存

- **WHEN** 项目所有者打开自己的真实项目第二阶段，项目请求返回 200，但准备尚未开始
- **THEN** 页面显示项目名、当前阶段高亮、工具条与可切换的三种布局，外壳可正常操作
- **AND** 同一页的阶段内容显示“尚未准备角色与环境”与开始入口，不显示示例角色、完成进度或冻结选择
- **AND** 不因阶段空态把整个页面判为项目不存在或服务不可用

#### Scenario: 第二阶段失败与服务不可用可区分

- **WHEN** 准备任务已失败，另一时刻准备读取请求返回 503
- **THEN** 第一种情况显示失败原因、失败步骤与重试入口
- **AND** 第二种情况显示“服务暂时不可用”并提供重试，不把服务故障描述成准备失败

#### Scenario: 第三阶段空态与服务不可用可区分

- **WHEN** 项目所有者打开自己的真实项目第三阶段，冻结选择已确认但尚未开始运行，另一时刻运行详情请求返回 503
- **THEN** 第一种情况显示冻结选择摘要、开始入口与“暂无运行记录”，不显示示例行动流或虚构计数
- **AND** 第二种情况显示“服务暂时不可用”并提供重试，不把服务故障描述成没有运行

#### Scenario: 正常阶段结果只来自真实数据

- **WHEN** 审查产品页面与“阶段正常”渲染分支
- **THEN** 产品页面只请求真实 API，不包含测试夹具或示例阶段结果
- **AND** 若用隔离测试数据验证正常分支，证据类型明确标注为“隔离数据验证”，不得混入浏览器签收证据

## ADDED Requirements

### Requirement: 第三阶段显示双平台运行结果

第三阶段工作台 SHALL 在冻结选择存在时提供开始运行入口，并在运行存在时显示模拟时钟、两个平台各自的行动流、按平台统计与运行日志。模拟时钟 MUST 由服务端返回的模拟时刻派生，显示推演内日期与时刻，MUST NOT 使用浏览器本地时间推算进度。

行动流 MUST 按平台分列，展示原生动作（信息广场：发帖、转发、点赞；话题社区：发主题、评论、投票赞成、投票反对）、角色、内容、轮次与模拟时刻；评论、转发与投票 MUST 显示其目标原帖，并可跳转到同一运行、同一平台的目标动作详情。统计 MUST 展示每平台已完成轮次与总轮数、总动作数与按原生动作类型分解。运行日志 MUST 只展示事件流中的标识、轮次、计数与原因码，MUST NOT 展示动作正文或材料正文。

面板 MUST 标明本次运行的引擎模式：“离线替身运行”或“真实本地 OASIS”。运行处于终态后 MUST 停止订阅事件、禁用停止按钮并使计数冻结；运行中 MUST 提供停止入口并显示停止已请求。阶段链接 MUST 保留 `layout`、`lang`、`build`、`preparation`、`selection` 与 `run`。

#### Scenario: 显示模拟时钟与两条行动流

- **WHEN** 运行已提交至少一轮
- **THEN** 页面显示模拟时钟、两个平台的行动流与各自轮次进度
- **AND** 行动流中的动作来自运行读取接口，顺序与轮次一致
- **AND** 时钟不使用浏览器本地时间推算

#### Scenario: 从评论或转发跳到原帖

- **WHEN** 用户点击一条评论或转发
- **THEN** 页面显示该动作的目标原帖内容、作者、轮次与模拟时刻
- **AND** 跳转只在该运行、该平台内解析目标
- **AND** 目标无法解析时显示“目标未在本运行中定位”，不伪造原帖

#### Scenario: 运行中停止

- **WHEN** 运行处于 `running` 时用户点击停止
- **THEN** 停止按钮显示已请求并禁用
- **AND** 页面在终态后显示“已停止”、冻结的轮次与计数
- **AND** 之后不再出现新的行动或计数变化

#### Scenario: 单平台失败仍显示另一平台结果

- **WHEN** 运行以 `failed` 结束且只有一个平台失败
- **THEN** 失败平台显示原因码与已完成轮次
- **AND** 另一平台的行动流、统计与日志保持可见
- **AND** 页面不把该运行显示为已完成或空运行

#### Scenario: 主动切换运行无需刷新

- **WHEN** 用户从运行记录中从 B 切回 A
- **THEN** 页面立即绑定 A 并显示 A 的计数与行动流，无需刷新
- **AND** 停止请求只发给当前绑定的运行
- **AND** B 的迟到响应与事件被丢弃，不覆盖 A

#### Scenario: 查看旧运行与刷新恢复

- **WHEN** 同一选择已有多条运行，用户选择旧运行或刷新页面
- **THEN** 页面从地址中的 `run` 读取该运行并显示其冻结时钟与计数
- **AND** 未指定 `run` 时显示活动运行，其次显示最近运行
- **AND** 切换运行后，旧运行的迟到响应不覆盖当前运行的行动流

#### Scenario: SSE 重连后计数一致

- **WHEN** 页面在运行中断线并自动重连
- **THEN** 页面先重新读取运行详情，再按游标补齐事件
- **AND** 行动流不重复、不缺口，统计等于运行详情返回的计数

#### Scenario: 离线替身运行有明确标识

- **WHEN** 运行记录 `engine=double`
- **THEN** 面板显示“离线替身运行”
- **AND** 该结果不被描述为真实本地 OASIS 动作

#### Scenario: 阶段链接保留运行上下文

- **WHEN** 用户在第三阶段切换布局或语言、或从阶段导航离开再返回
- **THEN** 地址保留 `layout`、`lang`、`build`、`preparation`、`selection` 与 `run`
- **AND** 返回后仍显示同一运行而不是最近运行或空态
