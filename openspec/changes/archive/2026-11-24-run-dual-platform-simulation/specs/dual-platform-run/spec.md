# Spec Delta

## Purpose

让一次已确认的角色与环境冻结选择变成可观察的双平台推演：由独立 worker 在两个隔离的本地 OASIS 平台上按冻结轮数推进，把引擎实际写入的原生动作读回为持久业务记录，并向用户呈现模拟时钟、行动流、按平台统计与可停止、可重跑、可回看旧运行的结果。

## ADDED Requirements

### Requirement: 从已确认的冻结选择启动运行

运行 SHALL 只从 Change 08 已确认的冻结选择启动。开始请求 MUST 只携带 `selectionId`，服务端 MUST 按项目归属读取该选择，并把其中的 `question`、角色、轮数、平台映射、初始话题、首发顺序与 `buildId`/`snapshotId` 作为本次运行的唯一输入。运行开始时 MUST 把实际使用的冻结载荷复制进运行记录，使后续准备、图谱或平台配置变化都不改变已开始的运行。

服务端 MUST NOT 从当前活动 build、最新图谱、准备工作草稿或前端本地状态重新拼装问题、角色、轮数或平台。缺少 `selectionId`、选择不存在或不属于该项目、选择载荷缺字段时 MUST 拒绝开始且不创建 run、job 或平台记录。

#### Scenario: 从已确认选择开始运行

- **WHEN** 项目所有者用一个已确认的 `selectionId` 开始运行
- **THEN** 响应为 202，返回新的 `runId`、`jobId` 与该 `selectionId`
- **AND** 运行记录保存问题、角色、轮数、平台映射、初始话题与首发顺序的副本
- **AND** job 初始为 `queued`，由 worker 领取后才执行引擎

#### Scenario: 缺少或非法的冻结选择被拒绝

- **WHEN** 请求不带 `selectionId`、`selectionId` 不是合法 UUID、选择属于他人项目或选择数据不完整
- **THEN** 分别返回 409 `selection_missing`、422 `selection_invalid`、404 `推演选择不存在`、409 `selection_invalid`
- **AND** 数据库不新增 run、job、平台或动作记录

#### Scenario: 已开始的运行不跟随新图谱

- **WHEN** 同一项目在运行进行期间完成新的建图或新的准备
- **THEN** 该运行的 `buildId`、`snapshotId`、问题、角色与轮数保持不变
- **AND** 页面不因新 build 出现而切换到另一份角色或轮数

### Requirement: 重复开始、终态后重跑与旧运行可读

同一项目同一 `selectionId` 的活动运行 MUST 最多一个，操作键 MUST 包含 `selectionId`。运行处于 `queued` 或 `running` 时，重复开始 MUST 返回 200 与同一个 `runId`、`jobId`，MUST NOT 新增第二组 run/job。两个并发开始 MUST 得到一个 202 与一个 200，指向同一运行，数据库只新增一组记录。

运行进入终态（`succeeded`、`failed`、`canceled`）后，再次开始 MUST 创建新的 run 与 job 并返回 202 与新 `runId`；旧运行的终态、动作、计数与日志 MUST 保持可读且不被改写。读取接口在未指定运行标识时 MUST 优先返回活动运行，其次返回最近一次运行；指定 `runId` 时 MUST 返回该旧运行。

#### Scenario: 重复点击开始复用同一运行

- **WHEN** 用户在运行进行中再次点击开始
- **THEN** 响应为 200，`runId`、`jobId` 与第一次相同
- **AND** 数据库只有一条该选择的运行与一个 job
- **AND** 页面继续显示同一运行的时钟与计数

#### Scenario: 并发开始只产生一个运行

- **WHEN** 两个开始请求并发到达同一 `selectionId`
- **THEN** 一个返回 202、另一个返回 200，两者 `runId` 相同
- **AND** 只新增一条运行、一个 job 与一条 run

#### Scenario: 终态后重跑得到新 runId 且旧运行仍可查看

- **WHEN** 一次运行已进入 `canceled` 或 `succeeded` 后用户用同一 `selectionId` 重新开始
- **THEN** 响应为 202 且 `runId` 与旧运行不同
- **AND** 旧运行仍可通过其 `runId` 读取动作、计数、模拟时钟与终态
- **AND** 新运行不复用旧运行的轮次游标或动作记录

### Requirement: 两个平台按原生动作执行且环境互相隔离

运行 SHALL 使用稳定别名 `platform_a` 与 `platform_b`，分别对应原生 `twitter` 与 `reddit`。信息广场 `platform_a/twitter` MUST 至少支持发帖（`create_post`）、转发（`repost`）与点赞（`like_post`）；话题社区 `platform_b/reddit` MUST 至少支持发主题（`create_post`）、评论（`create_comment`）与投票（`like_post` 赞成、`dislike_post` 反对）。角色、内容与动作类型 MUST 来自本次运行的角色与话题，动作 MUST 不是空内容或纯占位符。

两个平台 MUST 使用彼此独立的执行进程、临时目录、SQLite 数据库与运行标记，MUST NOT 共享可变数据库、游标或进程内状态。一个平台的环境创建、动作或读回失败 MUST NOT 修改或删除另一个平台已写入的记录。

#### Scenario: 两个平台各自执行原生动作

- **WHEN** 运行推进若干轮
- **THEN** `platform_a` 的动作记录只包含 `twitter` 原生动作，`platform_b` 只包含 `reddit` 原生动作
- **AND** 每条记录都能读到角色、原生平台、原生动作与本次运行标记
- **AND** 平台 B 的评论记录指向本次运行建立的主题帖

#### Scenario: 平台环境互相隔离

- **WHEN** 两个平台同时推进
- **THEN** 各自使用独立的目录、数据库文件与执行进程
- **AND** 平台 A 的数据库或进程故障不影响平台 B 继续写入与读回
- **AND** 清理平台 A 不删除平台 B 的记录

#### Scenario: 平台动作被引擎拒绝

- **WHEN** 某个平台拒绝某次原生动作或返回校验错误
- **THEN** 该动作不计入有效动作，该平台按失败原因码记录
- **AND** 另一个平台继续执行自己的动作

### Requirement: 引擎由独立 worker 执行且运行数据位置固定

引擎执行 MUST 由独立 `worker` 完成，浏览器与 `app` 进程 MUST NOT 直接调用引擎。每轮每个平台 MUST 由一个独立子进程执行引擎动作，worker 负责领取、续租、读回、记账与终态。运行创建时 MUST 持久化 `engine_mode`，领取与接手 MUST 同时匹配 run 类型与 `engine_mode`，使替身 worker 与真实本地 OASIS worker 各领各的任务；未被任何 worker 声明的运行 MUST 保持 `queued`。

运行数据 MUST 保存在由运行标识与平台别名派生的目录下（平台子目录内的引擎数据库、动作日志与状态文件），且该目录 MUST 位于跨 worker 重建仍然存在的持久卷上，使“引擎已写入、worker 尚未记账”的接手能读到同一条原生记录。业务读取 MUST 只使用数据库记录，MUST NOT 依赖用户文件名或原始上传路径。日志、事件与错误响应 MUST 只记录运行标识、平台别名、轮次、动作计数、引擎记录标识与原因码，MUST NOT 记录动作正文、材料正文、完整引擎路径、密钥或凭据。

真实本地 OASIS SHOULD 由隔离引擎镜像执行：worker 通过显式配置的引擎命令把本轮请求交给该镜像，引擎记录写回同一运行目录后再由 worker 读回。该路径 MUST 默认只执行原生手动动作（发帖、评论、点赞、反对、转发），不调用外部模型；需要模型参与时 MUST 由开发者另行显式开启并单独记录调用次数。

#### Scenario: 领取同时匹配 run 类型与引擎模式

- **WHEN** 同一环境同时存在替身 worker 与真实本地 OASIS worker
- **THEN** 替身运行只由替身 worker 领取，真实运行只由真实 worker 领取
- **AND** 未被任何 worker 声明的运行保持 `queued`
- **AND** 接手沿用同一匹配条件

#### Scenario: 运行由 worker 执行

- **WHEN** 运行已创建并处于 `queued`
- **THEN** 只有 worker 领取并执行引擎动作，`app` 进程不发起引擎调用
- **AND** 页面的动作与计数通过受鉴权的运行读取接口获得

#### Scenario: 运行数据在持久卷上

- **WHEN** worker 在“引擎已写入、尚未记账”时被重建
- **THEN** 接手 worker 仍能读取同一运行目录下的引擎记录
- **AND** 不会因为容器重建丢失已写入的原生动作

#### Scenario: 运行数据路径由标识派生

- **WHEN** 检查一次运行的引擎数据位置
- **THEN** 目录与文件名只由运行标识与平台别名派生
- **AND** 数据库只保存运行标记与相对位置，不保存用户文件名或绝对路径

#### Scenario: 日志与事件不含正文

- **WHEN** 检查 worker 日志、运行事件与错误响应
- **THEN** 只出现运行标识、平台别名、轮次、计数、引擎记录标识与原因码
- **AND** 不出现动作正文、材料正文、完整路径或凭据

### Requirement: 动作必须从引擎记录读回后才成为业务记录

每个动作 MUST 在引擎实际写入后，从该平台引擎记录（数据库行或动作日志）读回，MUST NOT 只使用动作调用返回值或进程内对象作为证据。读回记录 MUST 至少包含平台别名、原生平台、原生动作、角色、引擎记录标识与结果；评论、转发、点赞与反对 MUST 还包含目标对象标识。只有带正文的动作（发帖、评论）MUST 校验正文中的运行标记；点赞、反对与转发 MUST 按原生目标记录标识读回，MUST NOT 要求它们带正文标记。

读回成功的一批动作 MUST 与该平台本轮计数、轮次记录与一条运行事件在同一事务内提交。引擎记录标识 MUST 在同一运行与平台内唯一，重复读回 MUST 幂等更新或忽略，MUST NOT 生成重复业务动作。

#### Scenario: 动作通过引擎记录读回

- **WHEN** 某平台一轮执行完成
- **THEN** worker 从该平台引擎记录读回本轮动作
- **AND** 每条业务动作保存引擎记录标识、原生动作、角色、内容与目标对象
- **AND** 本轮计数、轮次记录与事件与这些动作在同一事务提交

#### Scenario: 只有调用返回值没有引擎记录

- **WHEN** 动作调用返回成功但读回找不到匹配记录或字段不一致
- **THEN** 该动作不计入有效动作，该平台以 `platform_a_record` 或 `platform_b_record` 结束
- **AND** 另一个平台不受影响
- **AND** 页面显示该平台的失败原因，不显示虚构动作

#### Scenario: 无正文动作按原生目标读回

- **WHEN** 本轮包含点赞、反对或转发
- **THEN** 读回按原生目标记录标识核对目标，而不是要求正文标记
- **AND** 发帖与评论仍校验正文中的运行标记
- **AND** 目标不一致的动作不计入有效动作

#### Scenario: 重复读回不产生重复动作

- **WHEN** 同一引擎记录被连续读回两次
- **THEN** 业务动作数量不变
- **AND** 该平台计数与事件序号不因重复读回增加

### Requirement: 引擎已执行但尚未记账时按引擎记录接手

worker 中断或租约过期后 MUST 由新 worker 接手同一运行、job 与 run。接手 MUST 先按本次运行标记读回各平台已提交的轮次与动作，补齐尚未记账的轮次，然后从第一个未提交轮次继续；MUST NOT 以“重新执行”代替读回，MUST NOT 产生重复动作。

接手 MUST 区分三种状态：`未开始`（只有计划、基线之后没有任何本角色原生行，可证明未执行，允许重发）、`已执行可补记`（原生行已存在且可按运行标记或原生目标归属，必须先补记再继续）、`不可确认`（基线之后存在本角色原生行但无法归属，或数据目录/记录不可读，必须保留证据并以 `action_unconfirmed` 结束，MUST NOT 重发）。OASIS 的原生动作、trace 与轮次标记可能分次提交，接手以引擎数据库中的原生行与副表状态为准，不以子进程摘要为准。

接手前 MUST 确保旧子进程不能继续写同一平台数据库（进程组终止与平台目录互斥锁），接手后同一引擎记录 MUST 只被补记一次。接手前后的按平台动作计数 MUST 与引擎记录和数据库记录一致。

#### Scenario: 引擎已写入后 worker 中断

- **WHEN** 某轮动作已写入引擎数据库但 worker 在记账前中断，租约过期后由新 worker 接手
- **THEN** `runId`、`jobId` 与运行记录不变，`attempts` 大于 1
- **AND** 接手先读回该轮动作并提交，不重新执行该轮
- **AND** 动作总数与引擎记录一致，无重复

#### Scenario: 无法确认时不重发动作

- **WHEN** 接手时该平台的动作已标记执行，但基线之后存在本角色原生行且无法用运行标记或原生目标归属
- **THEN** 该平台以 `action_unconfirmed` 结束
- **AND** 不重发该轮动作，不生成替代记录
- **AND** 已写入的原生行保留在引擎记录中作为证据

#### Scenario: 可证明未执行时才重发

- **WHEN** 接手时某动作只有计划记录，基线之后没有任何本角色原生行
- **THEN** 可以重发该动作一次
- **AND** 重发成功后该动作只计一次

#### Scenario: 旧子进程不能继续写同一平台库

- **WHEN** 接手的新 worker 与旧子进程可能同时存在
- **THEN** 平台目录用互斥锁串行化写入，旧进程未退出时新进程等待或明确失败
- **AND** 同一原生记录只被补记一次

#### Scenario: 接手后页面计数不跳变

- **WHEN** 刷新页面并重连事件流，run 已由新 worker 接手
- **THEN** 页面显示的轮次与动作计数等于服务端持久记录
- **AND** 不出现回退、翻倍或缺失

### Requirement: 轮次与模拟时钟由服务端推进

运行 MUST 按冻结选择的轮数与每轮分钟数推进，MUST NOT 超出冻结轮数。两个平台 MUST 独立推进：某一平台较慢（引擎慢、网络慢或平台故障）MUST NOT 阻止另一平台提交自己的下一轮，MUST NOT 以“先跑完 A 再跑 B”的串行方式实现。模拟时钟 MUST 由运行起点与已提交轮次派生，MUST 表示推演内时刻而非墙上时钟。运行起点 MUST 取冻结选择中首个首发角色的最早活跃小时（整点），并 MUST 同时用于角色调度、动作时刻、事件与运行详情时钟；运行的真实创建时间只用于审计，MUST NOT 参与推演时钟。

整次运行 MUST 有跨平台共享的动作上限。调用引擎之前 MUST 先原子预留本轮动作预算：预留失败时该平台 MUST 以 `simulation_too_large` 结束且 MUST NOT 调用引擎、MUST NOT 产生超额动作。预留 MUST 在记账或失败后释放，使两个平台合起来不超过上限，且不得重复记账。

每一轮的提交 MUST 在同一事务内写入该平台的轮次记录、该轮动作、按平台计数与一条运行事件；没有产生动作的轮次 MUST 仍然提交轮次记录并使时钟前进。运行详情 MUST 返回当前模拟时钟、每平台已完成轮次与总轮数。

#### Scenario: 时钟从首发时段起算

- **WHEN** 首个首发角色的活跃时段为 18–21 点、每轮 60 分钟、共 3 轮
- **THEN** 运行起点为 18:00，第一轮动作的模拟时刻为 18:00
- **AND** 三轮结束时详情时钟为 21:00
- **AND** 刷新后读回的起点与结束时钟不变

#### Scenario: 三轮推进与时钟

- **WHEN** 冻结选择为 3 轮、每轮 60 分钟，运行完成
- **THEN** 两个平台各自记录 3 个已提交轮次
- **AND** 模拟时钟从运行起点前进 3 轮，事件中的模拟时刻与轮次对应
- **AND** 运行详情的已轮数与总轮数一致

#### Scenario: 无动作轮次仍推进时钟

- **WHEN** 某平台某轮没有产生任何动作
- **THEN** 该平台仍提交该轮次记录与进度事件
- **AND** 模拟时钟与该平台已完成轮次前进，动作计数不变

#### Scenario: 轮次不超过冻结值

- **WHEN** 运行达到冻结轮数
- **THEN** 不再执行新的轮次
- **AND** 终态后的运行时钟与轮次不再变化

### Requirement: 回复与转发可定位同一运行同一平台的原帖

评论、转发与投票类动作 MUST 保存目标对象引用：目标所在平台别名、原生动作、引擎记录标识与本运行内的动作标识。目标 MUST 只能解析到同一运行、同一平台内已提交的动作；跨运行、跨平台或不存在于本运行的目标 MUST 标记为未解析，MUST NOT 建立链接。

运行详情与动作读取接口 MUST 返回足够信息，使页面可以从一条评论或转发跳回其原帖，并读到原帖的角色、内容、轮次与模拟时刻。

#### Scenario: 评论回到同一运行的原帖

- **WHEN** 平台 B 的评论指向本运行建立的主题帖
- **THEN** 该评论的目标引用指向同一运行、同一平台的动作标识
- **AND** 页面可从评论跳到原帖并读到原帖内容、角色与轮次
- **AND** 服务端计数中该评论计入评论数，原帖计入发主题数

#### Scenario: 转发回到同一运行的原帖

- **WHEN** 平台 A 的转发指向本运行的一条帖子
- **THEN** 转发记录保存原帖引用
- **AND** 页面可跳回原帖并显示转发者与原帖作者不同

#### Scenario: 跨运行或跨平台目标不被链接

- **WHEN** 动作引用的目标属于另一运行、另一平台或不存在
- **THEN** 记录标记目标未解析，不建立跳转链接
- **AND** 不为此改写目标动作或伪造一条原帖

### Requirement: 停止在轮次边界生效且终态后结果冻结

停止请求 MUST 返回 200 与该运行 `runId`，并只记录“停止请求”（`cancel_requested_at`），MUST NOT 立即写终态或终态事件。worker MUST 在下一个轮次边界生效：正在执行的那一轮若已写入引擎，MUST 先读回并记账，然后不再开始新轮并在单个事务内写入运行 `canceled`、job 终态与终态事件。同一运行 MUST 只有一个终态：完成先提交时保持 `succeeded`，取消先提交时保持 `canceled`；后到的一方 MUST 观察到既有终态且 MUST NOT 追加第二个终态事件。

终态提交后，该运行的轮次、动作与计数 MUST NOT 再增长：迟到的引擎结果 MUST 被丢弃，MUST NOT 写入业务记录，MUST NOT 追加事件。重复停止或对终态运行停止 MUST 幂等返回同一 `runId`，不改变终态、计数或事件。

#### Scenario: 停止请求与取消终态分开

- **WHEN** 运行中请求停止
- **THEN** 第一次请求只写入停止请求，运行仍为 `running`，详情返回 `stopRequested=true`
- **AND** worker 在下一个轮次边界读回在途动作并记账后写入 `canceled` 终态
- **AND** 重复请求返回 200 但不再产生终态事件

#### Scenario: 完成与取消只有一个终态

- **WHEN** 同一运行先后或并发地尝试写入 `succeeded` 与 `canceled` 两个终态
- **THEN** 只有先提交的一方生效，运行 `phase` 与 job 状态一致
- **AND** 终态事件恰好一条
- **AND** 失败方观察到既有终态，不追加事件、不改写计数

#### Scenario: 运行中停止

- **WHEN** 运行处于 `running` 时用户点击停止
- **THEN** 响应为 200 并返回同一 `runId`
- **AND** worker 在下一个轮次边界停止，已写入引擎的那一轮先读回再记账
- **AND** 运行以 `canceled` 结束，终态事件计入连续序号

#### Scenario: 终态后计数不再增长

- **WHEN** 运行已进入 `canceled`、`failed` 或 `succeeded` 后再次读取
- **THEN** 轮次、动作与按平台计数保持不变
- **AND** 迟到的引擎结果不产生新记录或新事件

#### Scenario: 重复停止保持幂等

- **WHEN** 对已终态运行再次请求停止
- **THEN** 返回 200 与同一 `runId`
- **AND** 终态、事件序号与计数不变

### Requirement: 单平台失败保留另一平台已有结果

平台失败 MUST 按平台与原因码分别记录（环境、动作、读回或清理）。一个平台失败时，另一个平台 MUST 继续完成剩余轮次，运行 MUST 以 `failed` 结束并列出失败平台与原因码。运行 MUST 标记为部分结果，另一平台的轮次、动作、计数与日志 MUST 保持可读且不被删除或改写。两个平台都失败时 MUST 同时列出两个平台并分别保留原因码与已确认动作。

#### Scenario: 平台 A 失败但平台 B 完成

- **WHEN** 平台 A 的环境或动作失败
- **THEN** 平台 B 继续执行剩余轮次并提交自己的记录
- **AND** 运行以 `failed` 结束，记录失败平台与原因码
- **AND** 页面保留平台 B 的行动流与统计，并标明平台 A 的失败原因

#### Scenario: 慢平台不阻塞另一平台

- **WHEN** 一个平台的引擎明显变慢
- **THEN** 另一平台仍能继续提交自己的下一轮
- **AND** 运行最终按各自轮次完成或失败，不因串行等待而丢轮

#### Scenario: 共享动作预算在调用引擎前生效

- **WHEN** 两个平台合计的下一轮动作会超过整次运行上限
- **THEN** 预留失败的平台以 `simulation_too_large` 结束
- **AND** 该轮不调用引擎、不写入业务动作
- **AND** 已记账动作总数不超过上限，引擎原生记录与业务记录一致

#### Scenario: 单轮超时也先读回已写入的动作

- **WHEN** 某平台单轮执行超出预算
- **THEN** 该轮已写入引擎且可归属的动作先读回并记账，轮次标记为未正常完成
- **AND** 平台以 `simulation_timeout` 结束，不重复记账

#### Scenario: 两个平台都失败

- **WHEN** 两个平台都失败
- **THEN** 运行以 `failed` 结束并列出两个平台
- **AND** 已提交的轮次与动作仍可读取

#### Scenario: 失败后仍可查看部分结果

- **WHEN** 用户在运行失败后刷新或重新打开该运行
- **THEN** 页面显示已完成平台的行动流、计数与模拟时钟
- **AND** 不把失败平台显示为空运行或已完成

### Requirement: 计数以持久记录为准且三方一致

按平台计数 MUST 由已提交的动作记录派生，MUST NOT 由前端累加、计划数、角色数或事件条数推算。运行详情 MUST 返回每平台的总动作数与按原生动作类型的分解，并返回每平台已提交轮次。刷新、SSE 重连与 worker 接手后，页面显示 MUST 等于服务端记录，服务端计数 MUST 等于引擎记录中的有效动作数。

#### Scenario: 刷新后计数一致

- **WHEN** 页面在运行中或终态后刷新
- **THEN** 页面显示的动作数与按类型分解等于运行详情返回的值
- **AND** 等于该平台已提交动作记录数

#### Scenario: 事件流重连后计数一致

- **WHEN** 客户端断线后以游标重连
- **THEN** 补发与实时事件不重复、不缺口
- **AND** 事件中的累计计数与运行详情一致

#### Scenario: 页面、服务端与引擎三方一致

- **WHEN** 逐个平台核对引擎记录、运行详情与页面显示
- **THEN** 三者动作数相同，按原生动作类型的分解也相同
- **AND** 报告记录三方数值与该平台的引擎记录标识

### Requirement: 证据模式必须显式区分

每次运行 MUST 记录本次实际使用的引擎模式（`double` 离线替身或 `oasis` 本地 OASIS）。运行详情、事件与页面 MUST 显示该模式，使离线替身结果不能被读成真实本地 OASIS 动作。配置为 `oasis` 但运行环境缺少引擎依赖时 MUST 以稳定原因码失败，MUST NOT 静默回退到替身。

默认 `make up`、默认 `make verify` 与 CI MUST 只使用替身引擎且不发起真实模型调用。真实本地 OASIS 动作证据 MUST 只来自开发者显式执行的独立运行，并单独记录为该运行的引擎记录与报告；真实运行默认只执行原生手动动作，外部模型调用 MUST 单独统计并可为 0，MUST NOT 把本地 OASIS 动作数当作模型调用数。

#### Scenario: 默认为替身引擎且零真实外呼

- **WHEN** 以默认配置启动并使用默认验收执行运行
- **THEN** 运行记录 `engine=double`，页面显示“离线替身运行”
- **AND** 真实模型与引擎外呼计数为 0

#### Scenario: 缺少引擎依赖时失败而非回退

- **WHEN** 配置指定本地 OASIS 但运行环境无法加载引擎依赖
- **THEN** 运行以 `engine_unavailable` 结束
- **AND** 不创建替身动作，也不把失败运行标记为已完成

#### Scenario: 真实证据只来自显式运行

- **WHEN** 开发者显式执行真实本地 OASIS 双平台运行
- **THEN** 证据只来自该运行自身读回的引擎记录
- **AND** 产品数据库中的运行不被标为真实 OASIS
- **AND** 报告区分离线与真实两类结论

### Requirement: 运行接口沿用项目鉴权与访问边界

所有运行接口 MUST 复用项目归属校验，顺序为“身份 → 项目归属 → 资源归属”。匿名请求 MUST 返回 401 且不访问运行数据；他人项目、不存在项目与非法项目标识 MUST 返回相同的 404 `项目不存在`；他人或不存在运行 MUST 返回 404 `运行不存在`，与“无权访问”不可区分。数据库不可达但会话存在时 MUST 返回 503 且不清除 Cookie。

#### Scenario: 匿名访问运行接口

- **WHEN** 未携带会话 Cookie 的请求访问开始、详情、动作或停止接口
- **THEN** 返回 401
- **AND** 不读取运行、动作或选择数据

#### Scenario: 他人项目与不存在运行等价

- **WHEN** 用户 B 访问 A 项目的运行或一个不存在的运行标识
- **THEN** 前者返回 404 `项目不存在`，后者返回 404 `运行不存在`
- **AND** 响应不包含动作正文、角色、路径或运行内部标识

#### Scenario: 停库时保留会话

- **WHEN** 数据库不可达时携带会话请求运行详情
- **THEN** 返回 503
- **AND** 响应不清除 Cookie，恢复后同一会话可继续读取
