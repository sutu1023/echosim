# Design

## Context

见proposal.md。现有准备结构只含文本和三角色，没有图谱数据或检索索引；当前前端也没有图组件。前置adoption定义带来源/visibility的story_facts及原子revision，本设计直接读取该契约。不是GraphRAG，也不引入向量检索或新图数据库。

## Goals / Non-Goals

Goals：确认后建立初始图，采纳后图谱与正式剧情同版本，单个界面可追溯关系。
Non-Goals：每事件图动画、历史图切换、图编辑、人工别名修正、跨作品关联、自动推断隐藏知识。

## Decisions

### 1. 基线构建是可恢复任务

准备确认仍是无模型调用原子操作；同时记录graph_baseline任务需求，再由worker创建/领取绑定确认版本和有效配置的任务。为避免确认API因构建失败回滚已确认设定，图谱状态独立为queued/running/ready/failed，明确显示就绪前不能启动新推演。重复确认不重复构建，同版本失败可显式重试。构建请求与确认指针同事务存储，不能靠浏览器可靠性触发。

沿用60秒调用、两次重试、1/2秒退避、总240秒、租约/fence与作品互斥；所有模型调用事务外。模型只提取输入确有依据的实体关系，三角色服务器直接锚定，私密属性仅供创作者及获准角色读取，不成为其他角色的公共知识。生成的source引用必须定位原字段/片段，含歧义的结果拒绝；没有地点/物品时只呈现已有角色，不造关系填空。若确认版本已变，旧任务不能发布；部署前已有canon的作品直接读取该权威事实快照，不重建覆盖；只有确认设定且无canon/基线的旧作品显示missing并提供显式构建，不伪称空图正确。

### 2. 一套权威事实，读取确定性投影

graph endpoint在一个一致性读事务中获取confirmed_version_id、canon_revision、graph_revision和完整事实投影。graph_revision使用(confirmed_version_id, canon_revision)，避免首次采纳前重确认仍为revision=0的歧义。节点/边按稳定ID映射，无第二次模型生成、异步合并或采纳后补写。adoption提交的事实快照已经足够绘图，API不能先返回新revision再返回旧边。

将图谱投影器放service/domain纯函数，授权与事务在服务，查询在adapter；图谱不直接给角色提供上下文。初始构建与采纳提取复用同一事实验证器和证据契约。已采纳事件改变持有关系时retire旧边、增加新当前边，来源历史保留在详情。未知关系不生成；角色“怀疑”只能作为来源中的表述，不成为确定事实。

### 3. API与前端

GET /api/v1/works/{work_id}/story-graph返回state、version_id、canon_revision与content（entities、relations、sources）；来源详情随同一经过作品授权的有界响应返回，禁止通用裸source_id越权读取。POST /story-graph/builds用于幂等重试，返回202；自动构建也遵循同一服务授权/配置引用合同。无确认返回missing状态且version_id为空，未就绪返回任务状态和安全错误码，模拟提交409 GRAPH_NOT_READY。各响应有界，超容量明确错误，不悄悄删点。

Simulation页侧栏可展开图谱，页面只有这一张；历史选择不改变图。采用React+SVG和文本详情，稳定布局位置保存在客户端同一work的缓存；不持久化权限信息到不安全存储。节点用图标/形状/文字区分类别，边有语义标签，支持选择、缩放、平移、适配视口和键盘可达的实体/关系文本列表。文字不作为HTML解释；不为“Galgame”引入立绘依赖。

模拟新事件和播放光标不触发图更新。采纳成功消息只触发取最新图，返回后整体替换并短暂突出新增/变化关系；若失败保留旧图并标明“已采纳，图谱显示待刷新”，这只是读取失败而非数据库部分提交。跨标签页定期查询版本（复用2秒状态轮询），每次取有界完整快照，只有版本变化时替换显示；当前100实体/200关系边界内省去第二次读取的竞态；按work/request generation与revision丢弃乱序旧响应。

### 4. 验证

固定12项提取评测：确认来源、没有物品、人物同名、物品同名、明确别名、持有转移、地点变更、关系终止、猜测、私密信息、指令注入、无效来源。必要确定性安全/来源检查零误放，语义结果逐例评阅，失败保留；同名不够证据不得合并。浏览器以完整任务验证初始→生成/播放不变→等待采纳不变→采纳一次更新→继续推演，并覆盖失败、放弃、主动停止、刷新/乱序读取和B访问A拒绝。事实原子性沿用adoption的隔离数据库故障注入，不只测图形截图。

## Risks / Trade-offs

- [图谱增长与可读性] → 支持缩放/查找式选择和文本列表，固定100节点/200边夹具验证可访问性；这不是承诺任意长篇规模。超已验证容量明确提示，不丢事实。
- [读失败造成看似不一致] → 显示旧版本及待刷新状态，重试原子读取，不回滚已经完成的采纳。
- [500行业务逻辑预算] → 复用采纳事实schema、原生SVG和现有任务；超限按delivery规范拆分，不新增复杂图编辑依赖。

## Migration Plan

在006之后追加007，仅增加基线任务/状态与必要查询索引，复用事实表。所有新旧事实字段有版本；上线时先运行兼容读路径，再启用基线任务与模拟就绪检查。不改旧migration、不覆盖已采纳事实。回退可隐藏图UI而保留事实和采纳事务；若回退worker，先禁用新graph_baseline任务并排空，不能交给旧else分支执行推演。顺序归档三个change，当前主规约在实现验证前保持不变。
