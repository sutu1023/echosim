# Design

## Context

见proposal.md。现有services/simulation.py用三轮循环、每轮三人order、单一visibility和action/dialogue/result；API游标最多9，004迁移也限定sequence≤9。Simulation.tsx每2秒轮询并接收SSE，没有独立播放状态。已有测试验证秘密和拒绝候选隔离，但evaluate_simulation.py只测单步；真实9事件曾耗时约6分50秒。本设计保留S4–S6的停止、授权、租约及45分钟上限。

## Goals / Non-Goals

Goals：将可读事件、独立角色回应和有界调度组合为可验证的叙事；播放速度不影响服务端进度。
Non-Goals：立绘/配音/图片生成、用户运行中指导、全知角色、更多角色或跨场景；采纳和图谱由后续change承担。

## Decisions

### 1. 版本化有序段落

新content.schema_version=2，包含actor_id、segments、references及progress。段落为稳定segment_id、kind(narration/dialogue)、text、speaker_id(仅dialogue)、visibility。对白speaker必须是本次actor；旁白不得替其他角色决定自主反应。3–6段是结构约束，所有text相加约200–400 Unicode code points是目标，不能用拉长无意义对白通过质量门槛；单事件绝对上限1200字、单段600字防止异常输出，低于目标交质量校验而非单凭长度放行。progress给出新增信息/局势变化/有后果选择及源事件引用，只在授权服务中使用。

角色上下文先按段落visibility过滤再组装，references仅可引用至少一个对该角色可见的段落；不附带已过滤段落的摘要、总progress或秘密引用。架构只读公共段落。创作者读取完整事件，但前端不展示权限标签。相比事件共用visibility，这避免一句私下动作把整段公开对白都变成私有；代价是增加段落级测试。

### 2. 每事件选择下一行动者

将固定order换成next_actor、公开scene、未解决事项与结束建议。协调者只依据公共上下文提出下一行动机会，不替角色生成回应；角色看到自身目标和可见历史后自主生成。允许A→B→A、A→A以及旁观。选择及结束理由用公开事实校验，绝不把隐藏目标传给其他角色。

每个候选先做结构/授权/引用校验，再做语义一致性与推进校验；拒绝原因只以角色有权获知的代码或意见反馈到该角色本次重试，拒绝文本不进入故事。语义校验不能替代确定性权限。调度目标12–18；达到有证据的阶段性结果可提前结束，否则继续至24并返回ending_reason=event_limit和未完待续提示。正常收束为resolved，主动停止为user_stopped；deadline/crash属于failed，不伪装自然结尾。

### 3. 调用与任务边界

沿用每次调用60秒、最多两次重试、退避1/2秒、每事件240秒和总45分钟。将一次调度+候选生成+校验计入同一事件预算，禁止嵌套重试使事件无限延长。默认角色/校验4096 token、调度2048，版本化记录，变更须真实评测。保留现有worker每5秒续租、30秒租约及恢复界限，阶段信息只记录planning/generating/validating等枚举，不传推理或内部提示。

收到停止后不启动下一事件；已在途事件至多提交一次，超时则直接stopped。数据库原子提交整条事件与序号，网络调用均在事务外。失败保留完整事件，不能续跑失败任务。

### 4. 前端播放为独立状态

服务端SSE仍发整条校验后事件，不提供token流。客户端按task_id/event_id/segment_id排队，默认约30字/秒（可调样式参数，不是服务端承诺），提供立即显示本事件和减少动画支持。任务终态不丢弃尚未播放队列，停止生成按钮不等于停止阅读。

首次加载的历史直接完整显示，避免刷新重播整本；同一会话新到事件仅播放一次。轮询与SSE共用去重归并；切换作品/历史清理旧队列、计时器和过时请求。上翻暂停自动滚动，显示新内容提示，回到最新恢复；终态可“显示剩余剧情”后决定是否采纳。只按段落完成宣读aria-live，避免每字打断辅助阅读。沿用React文本节点，不解释模型HTML。

### 5. 可检验的质量基线

固定18案例：12项安全/结构/秘密/重复/拒绝及6项叙事场景，其中至少3项运行完整任务（对峙、共同解题、秘密披露）。完整任务按因果回应、角色目标、非重复、动作对白可读性、自然收束五维0–2分人工审阅，公开逐项证据；每项≥1且每任务≥8/10才通过，安全固定违规误放必须为0。统计长度分布，至少80%的新事件落在200–400字目标；例外须有阅读价值说明，不能放宽断言隐藏不足。保留候选拒绝/超时结果及首事件、事件间隔、总时长实测。不把模型自评accept当成人工质量分，不宣称45分钟是体验目标。

## Risks / Trade-offs

- [更长事件与逐事件协调增加耗时] → 有界预算、可观察阶段和真实计时；不流出未校验内容换取速度。
- [模型校验无法证明任意输入质量] → 确定性秘密过滤、完整任务人工rubric和违规回归并行。
- [500行业务逻辑预算] → 复用任务/SSE，拆出小型事件契约与播放组件，完成前统计本change全部业务新增/修改；超过阈值按delivery规范进一步拆分，不按文件拆分冒充满足。

## Migration Plan

追加005迁移扩大sequence到24，保留旧行和原ID；通过schema_version区分旧格式，读适配器从绑定设定解析姓名并映射action/dialogue/result为段落。不改004历史迁移。先停止领取并等待旧活跃任务结束，再迁移和部署读兼容版本，再启用新生成。回退必须使用能读v2事件的上一兼容版本；不可直接退到仅支持9条的旧worker，也不删新历史。严格校验本delta后按顺序同步，不覆盖后续change的S10。
