# Proposal

## Why

材料入库已经能证明“原文、页码与段落位置是真的”，后台任务与事件流也已经能证明“长任务可排队、可接手、可重放”，但第一阶段仍只显示“待构建”。项目所有者无法把已就绪材料和一个情景问题变成可检查的证据图谱，也无法从任一节点或边回到支持它的原文位置。若直接进入角色准备与双平台推演，后续结论将缺少可追溯的证据底座。

本变更把“用户主动发起一次业务建图、观察真实进度、检查可回溯的节点与边”做成第一阶段可交付能力，同时保持默认启动、自动化验收与 CI 零真实外呼，并继续把验收专用图谱留给 `make smoke-live`。

## What Changes

- 新增业务建图入口：已登录的项目所有者选择本项目已解析就绪的材料（首版单次最多 5 份），输入一个非空情景问题，发起建图；请求只创建持久化任务并立即返回，不在 HTTP 请求内调用模型或 Zep。
- 新增项目隔离的图谱绑定：按 `zep-cloud==4.1.0` 的 `graph.create` 实际签名，在调用前持久化项目专用创建幂等键与稳定 `name`/`description`/`time_zone`，成功后保存服务端返回的 `Graph.uuid_`；不向 `graph.create` 传客户端图谱 UUID 或通用 metadata。创建响应丢失、响应已返回但数据库未提交、接手后都只绑定一个图谱。`ZEP_ACCEPTANCE_GRAPH_ID` 仍只属于 `make smoke-live`，业务 worker 不接收该变量，也不得写入验收图谱。
- 新增业务建图 worker 执行：复用现有 `worker`、`jobs`/`runs`、租约、步骤事务与 SSE。模型与 Zep 调用只发生在 worker 进程；模型使用标准库 HTTP，Zep 客户端按需延迟加载。建图固定为 `bind`、`plan`、`extract`、`write`、`readback`、`publish` 六步。
- 新增可观察进度与读回证据：分别记录写入受理、episode 匹配、处理完成、节点和边读回。等待索引表示写入已受理但尚无检索匹配；增量绘图表示至少一个 episode 已匹配但尚未全部处理并读回可用边；完成要求全部计划 episode 已匹配处理、节点/边分页读回稳定、最终快照在发布事务中原子发布。
- 新增同版本快照读模型：节点数、边数与画面来自同一份已发布快照；刷新后读取最近一次已发布快照；写入响应丢失、重复点击与 worker 中断接手都不能产生重复 episode 或重复逻辑事实。第 6 步发布事务提交前，候选快照不可见。
- 新增节点与边的材料溯源：文本来源按解码后完整原文的 UTF-16 偏移定位，PDF 来源按对应物理页原始抽取文本的偏移定位；复用现有分块、物理页码、段落区间与清洗前原文映射；区分材料中的陈述与用户输入的情景假设；歧义引文不得取第一次匹配。
- 新增第一阶段工作台图谱面板：保留现有材料面板与测试任务面板，增加 D3 力图、图例、缩放、拖动、边标签开关、刷新、最大化、点选详情与“进入下一阶段”入口；默认显示最近 build，旧 build 可按 ID 查询；本变更做到建图完成和下一阶段入口为止，不实现角色与环境配置。
- 新增规模上限：单次 5 份材料、200 个节点、400 条边、每项 5 条来源；材料超限在开始请求内 422，节点/边/来源超限以明确原因失败，不静默截断。
- 扩展验收与规则：`make verify CHANGE=2026-11-22-build-evidence-graph` 用原创小材料和测试替身覆盖业务建图全链路，报告记录 `calls.real=0`；默认 `make up`、默认 `make verify` 与 CI 不触发真实模型或 Zep 调用。人工验收使用作者私有 25 页报告与另一份原创校园接驳车材料各跑一次，私有样本、正文、外部品牌名、链接、代码、截图与回放数据留在仓库外。

## Capabilities

### New Capabilities

- `evidence-graph-build`: 业务建图入口、项目图谱幂等绑定、模型与 Zep 调用边界、worker/租约/SSE 接入、六步原子发布、写入受理/匹配/处理/读回证据、等待索引/增量绘图/完成三态、快照读模型、重复点击、响应丢失与中断接手、规模上限与最近/旧 build 选择。
- `evidence-graph-provenance`: 节点与边的材料来源、文本全量原文与 PDF 页内原文的 UTF-16 定位、既有材料复用、清洗前后映射与歧义引文处理、材料陈述与用户假设的区分、空问题/未就绪材料/匿名/跨项目/依赖不可达边界。

### Modified Capabilities

- `project-workbench`: 第一阶段保留材料面板与测试任务面板并增加证据图谱面板、默认最近 build/旧 build 查询、三态进度、D3 交互、详情与原文跳转、完成后的下一阶段入口；修改“材料就绪不改变图谱状态”的既有表述，使图谱状态只由真实建图结果改变。
- `background-job-queue`: 新增 `evidence.graph.build` run 类型与建图操作键，复用既有领取、租约、步骤事务与终态语义；建图固定六步，第 6 步原子发布；建图任务不得混入测试任务面板。
- `run-event-stream`: 建图进度事件与已发布快照版本在同一事务边界内推进；SSE 事件只引用快照版本，不把整张图塞进事件；候选快照不进入事件；重连后按版本读取最新已发布快照。
- `evidence-graph-access`: 明确验收专用图谱只服务 `make smoke-live`，业务建图通过项目幂等绑定创建并使用自己的图谱，不得读取、写入或复用验收图谱。
- `live-engine-smoke`: 修改“唯一真实调用入口”与 worker 凭据条款，明确业务建图是用户主动产品路径、不是验收入口；验收图谱标识只注入 `engine`，业务 worker 只接收业务配置且不接收验收图谱标识。
- `reproducible-verification`: 新增 Change 07 专属离线验收场景、业务建图报告字段、零真实外呼断言、创建响应丢失/旧 build 串入/引文错位等回归，以及两轮人工验收边界。

## Impact

- 代码：新增建图路由与服务、worker 建图执行分支、Zep/模型业务适配器、节点/边/证据/快照持久化、前端图谱面板与 D3 依赖；不改变既有健康检查、会话、项目隔离、材料解析与测试任务语义。
- 数据库：新增前向迁移，扩展 `runs.kind`，新增项目图谱绑定、建图任务、建图 episode 幂等记录、已发布/候选快照、节点、边与来源表；不使用 `create_all()`。
- 依赖：worker 镜像在应用运行时之上只增加 Zep 客户端依赖；模型调用不新增第三方依赖。验收专用 `engine` 镜像与候选依赖基线不变。
- 配置：新增建图 provider 模式、5/200/400/5 规模上限、问题长度与批次参数；同步 `.env.example`、`docker-compose.yml`、`app/config.py` 与 README；业务密钥只注入需要外部调用的 worker，`engine` 继续独占验收图谱标识。
- 接口：新增业务建图开始、默认最近 build/按 ID 旧 build、快照读取接口；开始接口 202/200，空问题与非法选择 422，超过 5 份材料 422，未就绪材料 409，匿名 401，跨项目与不存在资源统一 404，依赖不可达进入失败终态。
- 验收：默认 `make verify` 保持既有场景并保持零真实外呼；Change 07 场景使用测试替身写出 `graph_evidence`；CI 复用同一 `make verify` 入口，不注入真实密钥。
- 非目标：角色与环境配置、正式双平台推演、报告生成、深度互动、图算法与实体消歧的生产级优化、跨项目图谱共享、验收专用图谱的业务化、把私有样本或人工截图写入仓库。
