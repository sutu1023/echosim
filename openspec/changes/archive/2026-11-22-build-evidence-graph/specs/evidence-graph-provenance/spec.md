# Spec Delta

## Purpose

让证据图谱中的每个节点和每条边都能回到支持它的材料原文位置，并明确区分材料中的陈述与用户输入的情景假设，使后续阶段引用的是可核查的证据而不是无法回溯的摘要。

## ADDED Requirements

### Requirement: 原文定位坐标与现有材料可用性

系统 SHALL 使用材料入库时已确定的坐标语义：

- Markdown/TXT：`sourceStart`/`sourceEnd` 是**解码后完整原文**的 UTF-16 代码单元偏移，区间左闭右开，记录于换行归一与空白清理之前。
- PDF：`sourceStart`/`sourceEnd` 是**对应物理页原始抽取文本**的 UTF-16 代码单元偏移，区间左闭右开，不是跨页拼接文本或清洗后文本的偏移。

`document_chunks.text` 是清洗后的分块文本。服务端 MUST 在发布快照前把候选引文映射回上述原文坐标，MUST NOT 把清洗后文本的字符下标直接当作原文偏移。映射 MUST 同时适用于新解析材料和已经入库的既有材料，不需要重新上传或重新解析材料即可定位。

服务端 SHALL 按需从原件重新解码/抽取原文并重建“清洗文本到原文偏移”的映射；MUST NOT 修改已入库分块、材料哈希或原文视图。原件不可读取或无法重新抽取时 MUST 以 `source_unavailable` 失败，不得用清洗文本冒充原文。

#### Scenario: 含 emoji、连续空格与 CRLF 的文本可定位

- **WHEN** 一份 TXT 同时包含 emoji、连续空格与 CRLF 换行，模型引用其中一个含 emoji 的片段
- **THEN** 服务端按 UTF-16 代码单元映射回解码后完整原文的起止偏移
- **AND** 浏览器用同一对偏移在 `/source` 原文中高亮该片段，emoji 不造成偏移错位
- **AND** 连续空格与换行归一不改变已记录的原文字符位置

#### Scenario: 含重复页眉的多页 PDF 可定位

- **WHEN** 一份多页 PDF 的每页有重复页眉，模型引用第 3 页正文中的片段
- **THEN** 服务端从第 3 页原始抽取文本重建清洗位置，并映射回该页的 UTF-16 偏移
- **AND** 来源显示 `pageNo=3`，打开原件定位到 `#page=3`
- **AND** 被清洗掉的页眉不改变正文片段的页内偏移语义

#### Scenario: 已入库材料无需重新解析即可定位

- **WHEN** 建图选择一份在本次变更前已入库并处于 `ready` 的材料
- **THEN** 服务端使用该材料现有分块文本、页码/段落与偏移范围完成映射
- **AND** 不要求重新上传、重新解析或修改材料记录
- **AND** 映射结果与重新解析该原件得到的定位一致

#### Scenario: 原件不可读取时明确失败

- **WHEN** 材料记录存在但原件缺失或无法重新抽取
- **THEN** 建图以 `source_unavailable` 失败，不发布包含该来源的快照
- **AND** 不使用清洗后的分块文本替代原文定位

### Requirement: 引文映射与歧义处理

系统 SHALL 先把候选引文在分块清洗文本中的出现位置映射到原文字符区间，再校验引文是否确实支持该节点或边。映射 MUST 处理清洗造成的空白折叠、换行归一、页眉页脚移除与 PDF 页内偏移。

同一引文在分块中出现多次，或映射到多个互不相同的原文区间时，系统 MUST NOT 直接取第一次匹配。系统 MUST 要求模型提供 `sourceStart`/`sourceEnd` 指定候选区间，并用该区间重新校验引文；若仍不能唯一确定，MUST 以 `ambiguous_source` 失败。引文在分块中不存在或与指定区间切片不一致时 MUST 以 `source_mismatch` 失败。

#### Scenario: 同一引文出现多次不取第一次匹配

- **WHEN** 候选引文在同一分块中出现两次，模型未提供可消歧的偏移
- **THEN** 系统以 `ambiguous_source` 失败
- **AND** 不默认使用第一次出现的位置，不发布该来源
- **AND** 错误信息说明引文存在歧义

#### Scenario: 模型偏移可消歧时通过

- **WHEN** 候选引文出现多次，但模型提供 `sourceStart`/`sourceEnd` 指向其中一个唯一区间
- **THEN** 系统只校验该区间，切片与引文一致时通过
- **AND** 来源保存该唯一原文区间，不保存另一个匹配位置

#### Scenario: 引文不在分块中

- **WHEN** 候选引文不是分块清洗文本的子串
- **THEN** 建图以 `source_mismatch` 失败
- **AND** 不把该引文写入节点、边或快照

#### Scenario: 清洗文本与原文不一致时仍按原文校验

- **WHEN** 分块文本因空白折叠或页眉清理与原文表面不同
- **THEN** 系统先建立清洗字符到原文字符的映射，再用原文切片校验引文
- **AND** 不要求原文表面与清洗文本逐字相同

### Requirement: 每个节点和每条边携带可定位的材料来源

系统 SHALL 为图谱中每个 `origin=material` 的节点和边至少保存一条材料来源。每条来源 MUST 包含材料标识、分块序号、PDF 物理页码或文本原始段落区间、UTF-16 原文起止偏移与原文引用；区间 MUST 左闭右开，且引文 MUST 等于映射后的原文切片。

服务端 MUST 在发布快照前逐条校验来源：材料 MUST 属于当前项目且被本次建图选中，分块 MUST 属于该材料，偏移 MUST 在原始文本或对应物理页范围内，引文 MUST 与原文切片一致。校验失败 MUST 使建图以 `source_mismatch`、`ambiguous_source`、`too_many_sources` 或 `source_unavailable` 失败，MUST NOT 发布包含无效来源的完成快照。PDF 来源 MUST 带从 1 开始的物理页码，文本来源 MUST 带原始段落区间；页码与段落信息 MUST 取自材料解析结果或按需重抽取结果，不得由模型自行编造。

#### Scenario: PDF 节点来源带物理页码

- **WHEN** 一个材料来源的节点来自三页 PDF 的第 3 页
- **THEN** 该节点来源包含 `pageNo=3`、分块序号、页内 UTF-16 偏移与引文
- **AND** 查看来源时打开该材料原件并定位到 `#page=3`
- **AND** 页码来自分块记录或重抽取结果，而不是模型返回的页码字段

#### Scenario: 文本边来源带全量原文偏移

- **WHEN** 一条材料来源的边来自 Markdown 或 TXT 的第 12 段
- **THEN** 该边来源包含 `paragraphStart`、`paragraphEnd`、解码后完整原文的 UTF-16 偏移与引文
- **AND** 原文视图能用同一对偏移高亮该段落，且高亮内容取自原件而非清洗后的分块文本

#### Scenario: 引文与原文切片不一致时失败

- **WHEN** 模型返回的 `quote` 与映射后的原文切片不一致
- **THEN** 建图以 `source_mismatch` 失败，不发布完成快照
- **AND** 页面显示来源校验失败原因，不把该节点或边展示为可用证据

#### Scenario: 来源来自未选中或他人材料时失败

- **WHEN** 模型返回的来源指向本次未选中的材料、其他项目的材料或不存在的分块
- **THEN** 建图失败且不发布该来源
- **AND** 不泄露他人材料的名称、正文、页码或存在性

#### Scenario: 空材料来源不构成材料证据

- **WHEN** 一个节点或边声明 `origin=material` 但来源列表为空
- **THEN** 建图 MUST NOT 把该节点或边计为材料证据
- **AND** 完成判定失败，页面显示来源不足原因

### Requirement: 材料陈述与用户情景假设可区分

系统 SHALL 为每个节点和边保存来源类型，取值 MUST 为 `material` 或 `hypothesis`。`material` 表示该内容由所选材料中的陈述支持，MUST 至少有一条通过校验的材料来源；`hypothesis` 表示该内容来自用户输入的情景问题或由其推导，可以没有材料来源，但 MUST NOT 被展示为材料中的事实。

模型提示与结果校验 MUST NOT 把用户问题本身当作材料正文，也 MUST NOT 为用户假设编造材料引文。若一个 `hypothesis` 节点或边同时引用材料，其来源仍 MUST 通过与 `material` 相同的引文与偏移校验。工作台图例、节点样式与详情 MUST 明确区分两种来源类型；材料来源数量与假设数量 MUST 可分别观察。

#### Scenario: 材料中的陈述标记为 material

- **WHEN** 材料明确写有一个组织和一项安排，模型据此生成节点与边
- **THEN** 对应节点与边标记为 `origin=material`，并各自至少有一条材料来源
- **AND** 详情显示材料名称、页码或段落与原文引文

#### Scenario: 问题引入的假设标记为 hypothesis

- **WHEN** 用户情景问题引入一个材料中不存在的假设角色或假设行动
- **THEN** 对应节点或边标记为 `origin=hypothesis`，并可没有材料来源
- **AND** 界面使用与材料陈述不同的图例或样式，并说明它来自用户假设
- **AND** 不把它计入材料陈述数量或作为材料事实引用

#### Scenario: 假设引用材料时仍须通过校验

- **WHEN** 一个 `hypothesis` 节点或边选择引用一条材料陈述
- **THEN** 其来源仍须通过材料归属、分块、原文偏移与引文一致性校验
- **AND** 校验通过后来源类型仍为 `hypothesis`，不得改写成材料事实

#### Scenario: 图例分别统计两种来源

- **WHEN** 图谱同时包含材料陈述与用户假设
- **THEN** 图例分别显示两种类型与各自数量
- **AND** 只显示真实存在的类型，不把测试夹具或示例节点混入产品图例

### Requirement: 点选节点或边可回到支持它的原文

系统 SHALL 在节点与边详情中返回该条目的类型、来源类型、摘要与全部材料来源。每个来源 MUST 提供可执行的材料定位入口：PDF 打开原件并定位到物理页码，Markdown/TXT 打开原文视图并用 UTF-16 偏移高亮对应区间。详情与来源跳转 MUST 保留当前项目、阶段、`layout`、`lang` 与已选材料查询参数。

来源跳转 MUST 以纯文本或 PDF 方式展示材料，MUST NOT 以可执行 HTML 渲染材料正文。存在多个来源时 MUST 全部列出，每个来源独立定位；不得只显示第一条来源而隐藏其余来源。

#### Scenario: 点击 PDF 来源的边定位到页码

- **WHEN** 用户点选一条由 PDF 第 3 页支持的边并点击“查看原文”
- **THEN** 打开该 PDF 原件并定位到 `#page=3`
- **AND** 地址仍属于当前项目与当前阶段，`layout` 与 `lang` 保持不变

#### Scenario: 点击文本来源的节点高亮原文区间

- **WHEN** 用户点选一个由 Markdown 或 TXT 支持的节点并点击“查看原文”
- **THEN** 原文视图使用该来源的 UTF-16 偏移高亮对应片段
- **AND** 高亮内容来自解码后的完整原文，不执行材料中的 HTML、脚本或命令

#### Scenario: 多条来源分别可定位

- **WHEN** 一个节点或边有两条及以上材料来源
- **THEN** 详情列出全部来源及其页码或段落区间
- **AND** 点击任一来源都能定位到对应材料位置，不把多个来源合并成一条引文

#### Scenario: 他人项目或匿名访问来源

- **WHEN** 用户 B 尝试读取 A 项目的节点、边或来源，或匿名请求来源
- **THEN** 匿名请求返回 401，他人项目返回与不存在项目相同的 404 `项目不存在`
- **AND** 不返回节点、边、引文、页码、段落或材料名称

### Requirement: 建图输入与外部依赖的边界行为

系统 MUST 在建图开始阶段拒绝空问题、未就绪材料、空材料列表、超过 5 份材料与跨项目材料；匿名请求 MUST 在任何数据库查询前返回 401。模型或 Zep 不可达、认证失败、超时或返回不可用结果时，建图 MUST 进入失败终态，MUST NOT 生成节点、边、引文或完成快照；当前 build 最近一次已发布的部分快照 MUST 保留但不得标记为本次完成。

系统 MUST NOT 把材料正文、完整模型响应、完整 episode 内容或私有样本写入日志、验收报告或错误响应。失败日志只记录 `buildId`、`documentId`、阶段、原因码与异常类型；面向浏览器的错误响应只包含中文说明与稳定原因标识。

#### Scenario: 空问题与未就绪材料都不创建图谱

- **WHEN** 项目所有者提交空问题，或选择一份尚未就绪的材料
- **THEN** 前者返回 422，后者返回 409，均不创建 build、job、run、节点或边
- **AND** 不发起模型或 Zep 调用

#### Scenario: 超过材料数量上限明确拒绝

- **WHEN** 项目所有者选择 6 份材料
- **THEN** 返回 422 与 `too_many_documents`，说明单次最多 5 份
- **AND** 不创建 build、job 或 run

#### Scenario: 跨项目读取与不存在资源等价

- **WHEN** 用户 B 请求 A 项目的图谱快照、节点详情或来源
- **THEN** 返回 404 `项目不存在`，与随机不存在项目完全一致
- **AND** 不返回任何图谱、材料或来源元数据

#### Scenario: 外部依赖不可达不伪造证据

- **WHEN** 模型或 Zep 在建图中途不可达且预算耗尽
- **THEN** build 进入 `failed`，没有新增节点、边、引文或完成快照
- **AND** 页面显示依赖不可达原因，当前 build 最近一次已发布的部分快照只作为历史结果展示

#### Scenario: 日志与错误响应不含材料正文

- **WHEN** 建图因来源校验或外部调用失败
- **THEN** 日志只包含标识、阶段、原因码与异常类型
- **AND** 错误响应不包含材料正文、引文、完整模型响应、完整 episode 或私有样本内容
