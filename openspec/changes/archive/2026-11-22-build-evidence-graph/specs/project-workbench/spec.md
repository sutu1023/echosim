# Spec Delta

## ADDED Requirements

### Requirement: 第一阶段保留材料面板并提供证据图谱面板

第一阶段工作台 SHALL 在保留现有材料列表、上传、摘录与来源定位的同时，提供证据图谱面板。面板 MUST 只读取当前项目的真实建图接口，不得内置示例节点、示例边、测试夹具或伪造进度。第一阶段 MUST 继续保留“测试任务”面板，且业务建图与测试任务在数据、日志与状态上互不混入。

面板 MUST 提供建图表单：从本项目 `ready` 材料中选择一份或多份材料（单次最多 5 份）、输入一个情景问题并开始建图。材料未就绪、材料超过 5 份或问题为空时 MUST 显示对应原因，且不得显示已开始。开始成功后 MUST 显示 `buildId`、`jobId`、`runId` 与任务状态，并允许在刷新后从地址与接口恢复同一建图。

材料列表加载、失败或重试 MUST NOT 改写图谱面板状态；图谱面板的加载、失败或重试 MUST NOT 改写材料列表或测试任务面板。三者共用当前项目、阶段、`layout` 与 `lang`，但状态相互独立。

#### Scenario: 就绪材料出现在建图选择中

- **WHEN** 项目已有至少一份 `ready` 材料且用户打开第一阶段
- **THEN** 图谱面板的材料选择器只列出 `ready` 材料，并显示材料名称、类型与页数或分块数
- **AND** 不把 `queued`、`parsing` 或 `failed` 材料列为可选
- **AND** 材料面板仍按既有规则显示全部材料与状态

#### Scenario: 空问题不开始建图

- **WHEN** 用户未输入问题、只输入空白或选择零份材料就点击开始
- **THEN** 页面显示问题不能为空或至少选择一份材料
- **AND** 不创建建图任务，不显示“等待索引”或图谱节点

#### Scenario: 超过 5 份材料时显示明确原因

- **WHEN** 用户选择 6 份 `ready` 材料
- **THEN** 页面显示“单次最多 5 份材料”与 `too_many_documents`
- **AND** 不提交建图，不静默只选前 5 份

#### Scenario: 开始建图后显示真实身份与状态

- **WHEN** 用户选择就绪材料、输入有效问题并开始建图
- **THEN** 面板显示服务端返回的 `buildId`、`jobId`、`runId` 与当前状态
- **AND** 刷新页面后仍能读取同一建图，而不是回到空白表单或伪造进度

#### Scenario: 材料区、图谱面板与测试任务互不改写

- **WHEN** 材料列表、图谱面板或测试任务面板中的任一侧加载失败
- **THEN** 失败的一侧显示自己的错误与重试，其它已加载的一侧保持内容
- **AND** 不把材料失败显示成图谱失败，也不把图谱失败显示成没有材料
- **AND** 测试任务面板仍只显示测试任务

### Requirement: 最近 build 默认显示与旧 build 查询

第一阶段图谱面板 SHALL 默认显示服务端选择的最近 build：项目存在 `queued` 或 `running` build 时显示该活动 build，否则显示最近创建的 build。用户 MUST 能通过完整 URL 的 `build=<buildId>` 查询旧 build，并保留既有 `layout`、`lang` 与 `document` 查询参数。

前端 MUST 用 `buildId` 绑定当前展示的 build 与快照；任何 `buildId` 不匹配的迟到响应 MUST 被丢弃。同一项目第二次 build 仍在等待索引时，刷新或迟到响应 MUST NOT 把第一次的完成图当作第二次结果；只有显式打开 `build=<第一次 buildId>` 时才显示第一次的完成图。

#### Scenario: 默认显示最近 build

- **WHEN** 项目已有一次完成 build 且没有活动 build
- **THEN** 未带 `build` 参数打开第一阶段显示该最近 build 与其最终快照
- **AND** 地址不因默认选择被改写为旧 build

#### Scenario: 第二次等待时不显示第一次完成图

- **WHEN** 第一次 build 已完成，第二次 build 仍处于等待索引
- **THEN** 第一阶段默认显示第二次 build 与“等待索引”
- **AND** 不显示第一次的节点、边、计数或“已完成”
- **AND** 刷新后仍显示第二次 build

#### Scenario: 迟到响应不覆盖当前 build

- **WHEN** 第一次 build 的快照响应在第二次 build 已开始后迟到到达
- **THEN** 页面因 `buildId` 不匹配丢弃该响应
- **AND** 当前画面、计数与 phase 仍属于第二次 build

#### Scenario: 按 ID 打开旧 build

- **WHEN** 用户打开带 `build=<第一次 buildId>` 的第一阶段地址
- **THEN** 页面显示第一次 build 与其已发布完成快照
- **AND** `layout`、`lang` 与其它查询参数保持不变
- **AND** 默认读取的第二次活动 build 不受影响

#### Scenario: 他人 build ID 不可读取

- **WHEN** 用户 B 打开 A 项目的 `build=<buildId>` 地址
- **THEN** 页面显示与不存在项目相同的“项目不存在”
- **AND** 不显示 build、节点、边、来源或材料名称

### Requirement: 图谱三态进度与同快照渲染

图谱面板 SHALL 根据服务端 build 状态显示等待索引、增量绘图、完成三种进度状态，并显示 `acceptedEpisodes`、`confirmedEpisodes`、`plannedEpisodes` 与快照版本。状态 MUST 由服务端字段决定，不得由前端计时器、动画或节点数量自行推断。

等待索引 MUST 表示“写入已受理但尚无本次检索匹配”；此时 MUST 显示等待提示，不得把空图画布标记为完成。增量绘图 MUST 表示“至少一个 episode 已匹配，但尚未全部匹配、处理完成并读回可用节点/边”；此时 MUST 保留上一份已发布画面并渲染新的部分快照。完成 MUST 表示“全部 episode 已匹配处理、节点/边读回稳定、最终快照已在发布事务中发布、任务成功”；此时 MUST 显示最终快照与可进入下一阶段的入口。

每次渲染 MUST 使用同一份已发布快照的 `snapshotId`、`revision`、`complete`、`nodeCount`、`edgeCount`、节点与边。节点数与边数 MUST 与画布中的节点、边来自同一响应；页面 MUST NOT 用上一次快照的计数配新一次快照的节点，或反之。较旧的响应晚到 MUST 被忽略，不得覆盖更高版本的快照。

#### Scenario: 等待索引时不清空为完成

- **WHEN** build 处于等待索引，服务端返回 `acceptedEpisodes > 0` 与 `confirmedEpisodes = 0`
- **THEN** 画布区域显示“等待索引”与已受理数量
- **AND** 不显示“已完成”、不显示空图的节点数 0 作为完成结果
- **AND** 若之前已有已发布快照，保留该历史快照并标记它不是本次完成结果

#### Scenario: 增量绘图保留上一份画面

- **WHEN** 第一个 episode 被匹配，服务端返回 `phase=drawing` 与 `complete=false` 的新快照
- **THEN** 面板在加载新快照期间保留上一份画面，不闪回空白
- **AND** 新快照到达后显示其节点、边与计数，并显示“增量绘图”与已确认/计划数量

#### Scenario: episode 可搜索但无可用边时仍不完成

- **WHEN** 服务端已匹配 episode，但节点/边读回尚未稳定或没有可用边
- **THEN** 面板显示“正在读取节点与边”或等价说明
- **AND** 不显示“已完成”，不提供下一阶段入口

#### Scenario: 完成时计数与画面同源

- **WHEN** build 进入 `ready` 并返回 `complete=true` 的最终快照
- **THEN** 页面显示的节点数、边数分别等于该快照中节点与边数组的长度
- **AND** 画面、计数、图例与详情都来自同一 `snapshotId` 与 `revision`
- **AND** 不显示“已完成”直到服务端同时返回 `ready` 与最终已发布快照

#### Scenario: 刷新后恢复上次已发布快照

- **WHEN** 用户在等待索引、增量绘图或完成后刷新页面
- **THEN** 页面重新读取最近一次已发布快照，并显示与刷新前相同的版本、计数与画面
- **AND** 不依赖浏览器内存中的旧响应或未提交的本地动画状态

#### Scenario: 旧响应不覆盖新快照

- **WHEN** 一个较早请求的快照响应在较新快照之后到达
- **THEN** 页面忽略较低 `revision` 的响应，保留较高版本
- **AND** 计数、节点、边与详情仍来自较高版本

#### Scenario: 服务不可用与没有建图可区分

- **WHEN** 图谱接口返回 503，或项目尚未发起过建图
- **THEN** 前者显示“服务暂时不可用”与重试，保留登录态
- **AND** 后者显示“尚未建图”与建图表单，不显示服务错误或示例节点

### Requirement: D3 力图、图例与交互控制

图谱面板 SHALL 使用 D3 力图渲染节点与边，并提供图例、缩放与平移、节点拖动、边标签开关、刷新、最大化与点选。图例 MUST 显示节点类型、边类型与来源类型（材料陈述/用户假设），且只显示当前快照实际存在的类型。

缩放、平移、拖动、边标签开关与最大化 MUST 只改变本地视图，不得修改服务端数据、build 状态或阶段进入条件。刷新 MUST 重新读取最近一次已发布快照，不得重新开始建图。最大化 MUST 扩大图谱区域，同时保留当前项目、阶段、`layout`、`lang`、`buildId` 与快照版本。边标签开关 MUST 能分别观察“显示标签”和“隐藏标签”两种状态。

#### Scenario: 缩放与拖动不改变数据

- **WHEN** 用户缩放画布、平移视图或拖动一个节点
- **THEN** 节点与边的服务端数据、计数与快照版本保持不变
- **AND** 当前项目、阶段、布局与语言不变
- **AND** 刷新后节点位置可以由力导向重新计算，但数据仍来自同一快照

#### Scenario: 图例区分类型与来源

- **WHEN** 当前快照同时包含材料陈述与用户假设
- **THEN** 图例分别显示节点类型、边类型与两种来源类型
- **AND** 图例数量与画布中实际类型一致，不显示不存在的类型

#### Scenario: 边标签开关可观察

- **WHEN** 用户点击“边标签”开关
- **THEN** 画布在显示关系标签与隐藏关系标签之间切换
- **AND** 节点、边、计数、快照版本与当前选中项不被删除或改写

#### Scenario: 最大化保留上下文

- **WHEN** 用户点击最大化
- **THEN** 图谱区域扩大并保持当前快照可见
- **AND** 当前项目、阶段、`layout`、`lang`、`buildId` 与快照版本不变
- **AND** 再次点击可恢复到原布局

#### Scenario: 刷新只读取最新已发布快照

- **WHEN** 用户点击刷新
- **THEN** 面板重新请求当前 build 的最近已发布快照
- **AND** 不新增 job、run、build 或 episode，不改变任务状态
- **AND** 刷新失败时保留当前画面并显示可重试提示

### Requirement: 节点与边详情可返回材料位置

图谱面板 SHALL 支持点选节点或边并显示详情。详情 MUST 包含类型、来源类型（`material` 或 `hypothesis`）、摘要、与该条目同快照的全部材料来源，以及每个来源的材料名称、PDF 物理页码或文本段落区间与原文引文。

详情中的来源入口 MUST 能把用户带回材料位置：PDF 打开原件并定位到 `#page=<物理页码>`，Markdown/TXT 打开原文视图并用 UTF-16 偏移高亮对应区间。跳转 MUST 保留当前项目、阶段、`layout`、`lang`、`buildId` 与材料查询参数；从材料返回图谱时 MUST 仍能读取同一 build 与快照。`hypothesis` 条目 MUST 明确标注为用户假设，不得显示成材料事实。

#### Scenario: 点选节点显示来源

- **WHEN** 用户点选一个材料来源的节点
- **THEN** 详情显示节点类型、材料来源类型、摘要与至少一条来源
- **AND** 每条来源显示材料名称、页码或段落区间与引文
- **AND** 不显示与该快照无关的节点或来源

#### Scenario: 点选边显示关系与来源

- **WHEN** 用户点选一条边
- **THEN** 详情显示关系类型、起点、终点、来源类型与全部材料来源
- **AND** 点击任一来源可定位到对应原文位置

#### Scenario: 用户假设与材料陈述样式不同

- **WHEN** 用户点选一个 `hypothesis` 节点或边
- **THEN** 详情明确标注“来自用户假设”，并显示它关联的情景问题
- **AND** 不把它显示为材料中的陈述，也不伪造材料引文

#### Scenario: 返回材料位置保留上下文

- **WHEN** 用户从详情点击一个 PDF 来源或文本来源
- **THEN** PDF 打开到对应物理页，文本打开并高亮对应偏移
- **AND** 地址保留当前项目、阶段、`layout`、`lang` 与 `buildId`
- **AND** 从材料视图返回图谱后仍显示同一 build 与快照版本

#### Scenario: 他人项目不能读取详情

- **WHEN** 用户 B 请求 A 项目的图谱详情或来源
- **THEN** 返回与不存在项目相同的 404 `项目不存在`
- **AND** 不显示节点、边、引文、页码或材料名称

### Requirement: 完成后提供下一阶段入口

第一阶段 SHALL 在服务端返回 `canContinue=true` 时提供进入第二阶段“准备角色与环境”的入口。入口 MUST 使用服务端字段，不得由前端根据节点数、动画或本地状态推断；跳转 MUST 使用 `push` 并显式保留当前 `layout`、`lang` 与 `buildId`。

`canContinue=false` 时 MUST 禁用入口并说明原因（尚未建图、等待索引、增量绘图、失败、取消、规模超限或来源不完整）。进入第二阶段后，第二阶段 MUST 显示角色与环境尚未配置的真实空态，MUST NOT 再显示“缺少证据图谱”；本变更 MUST NOT 实现角色、环境、双平台运行或报告内容。

#### Scenario: 完成后进入第二阶段

- **WHEN** build 为 `ready` 且服务端返回 `canContinue=true`
- **THEN** 面板显示可用的“进入准备角色与环境”按钮
- **AND** 点击后进入 `/projects/<项目 ID>/workbench/roles-environment`，并保留 `layout`、`lang` 与 `buildId`
- **AND** 第二阶段显示角色与环境尚未配置，而不是缺少证据图谱

#### Scenario: 未完成时入口禁用

- **WHEN** build 处于等待索引、增量绘图、失败、取消或规模超限
- **THEN** 下一阶段入口禁用，并显示对应原因
- **AND** 点击不会进入第二阶段，也不会创建新任务

#### Scenario: 来源不完整时不允许进入

- **WHEN** 服务端因材料来源不完整返回 `canContinue=false`
- **THEN** 面板显示来源校验失败或来源不足原因
- **AND** 不把图谱显示为可继续的完成结果

## MODIFIED Requirements

### Requirement: 材料就绪不改变图谱状态

材料就绪 SHALL 只使第一阶段的“至少一份材料”条件得到满足，MUST NOT 把证据图谱标记为已构建。证据图谱状态 MUST 只由真实建图任务与持久化结果改变：没有建图结果时显示“待构建”；建图中显示等待索引或增量绘图；建图成功且最终已发布快照通过校验后才显示完成。材料列表、摘录与来源定位 MUST 与“测试任务”面板、证据图谱面板相互独立：任一侧的加载、失败或重试 MUST NOT 改写另一侧的状态，也 MUST NOT 改变阶段进入条件或伪造图谱节点。

#### Scenario: 材料就绪后图谱仍待构建

- **GIVEN** 项目已有至少一份就绪材料且尚未发起建图
- **WHEN** 项目所有者打开第一阶段
- **THEN** 材料列表显示就绪材料，图谱区域仍显示“待构建”或等价的未完成说明
- **AND** 不显示节点、边、进度百分比或“已完成”
- **AND** 建图表单可以选择该材料，但不会自动开始建图

#### Scenario: 建图成功后图谱显示真实结果

- **GIVEN** 项目已完成一次建图且服务端返回最终已发布快照与 `canContinue=true`
- **WHEN** 项目所有者打开或刷新第一阶段
- **THEN** 图谱区域显示该最终快照的节点、边、计数与来源详情
- **AND** 材料列表与图谱结果来自同一项目，互不覆盖
- **AND** 不显示测试夹具、示例节点或“待构建”

#### Scenario: 材料失败不影响已有图谱

- **GIVEN** 项目已有一次成功的建图，随后新上传的一份材料解析失败
- **WHEN** 项目所有者打开第一阶段
- **THEN** 材料区显示失败原因与重新上传入口
- **AND** 已有图谱仍显示其最近一次已发布快照，不因新材料失败被清空或改写
- **AND** 阶段进入条件与建图结果保持可查询

#### Scenario: 材料失败不影响其他阶段外壳

- **GIVEN** 项目唯一一份材料解析失败且尚无建图结果
- **WHEN** 项目所有者打开第一阶段与第二阶段
- **THEN** 第一阶段显示失败原因与重新上传入口，第二阶段仍按缺少前置条件说明
- **AND** 工具条、阶段导航、布局与语言保持可用

#### Scenario: 材料区与测试任务面板互不改写

- **GIVEN** 材料列表加载成功，而测试任务面板请求失败
- **WHEN** 用户在页面上重试测试任务面板
- **THEN** 材料列表保持已加载的内容与状态
- **AND** 材料区的错误或重试不会把测试任务标记为失败或成功

#### Scenario: 测试任务列表不包含材料解析任务

- **GIVEN** 同一项目既有材料解析任务，也有最近一次连通性测试任务
- **WHEN** 用户打开测试任务面板的任务列表
- **THEN** 列表只包含连通性测试任务，不出现材料解析的 `jobId`、文件名称或页数
- **AND** 材料解析的进度与结果只在材料区显示
