# Proposal

## Why

运行骨架与本地模型诊断已完成，但创作者还不能登录或保存自己的作品。本轮交付“登录后管理自己的作品”这一可独立验收能力，为后续创作流程建立身份和归属边界。

## What Changes

- 维护者通过本地命令创建账号、重置密码；用户名密码登录、固定七天会话、退出与失败限速。
- 开发环境显式开启后提供体验账号 A/B 一键登录；切换结束当前会话，生产环境前后端均禁用。
- 创建、分页列出、查看自己的作品；标题必填且允许重名；跨账号与不存在作品统一 404，未登录业务请求返回 401。
- 创建请求持久幂等，相同标识不同内容返回 409；作品和未过期会话在重启后保留。
- **BREAKING**：替换运行骨架中业务入口始终 404 的约束；已实现接口按认证与授权契约响应，首页加入真实作品入口。
- 本轮不提供注册、找回密码页面、作品改名/删除、材料、推演、章节或持久模型配置；公网继续暂缓。P01 仅完成账号与作品部分，M0/M1 均不因此完成。

## Capabilities

### New Capabilities

- `private-works`: 作品创建、列表、详情、归属隔离与创建幂等。

### Modified Capabilities

- `system-runtime`: R1 增加 API 同源配置；R3 开放已实现业务入口并维持安全错误契约；R5 保留状态页并加入真实登录/作品入口。

## Dependencies

依赖 `2026-11-13-user-auth`，原访谈中的账号与快捷登录范围拆到此前置变更，仍与本轮作品能力一起实施和验收。拆分遵循 tasks 1.1 与 delivery.md，不减少用户确认的能力。

## Impact

- 后端 api/services/domain/adapters 与 main 组装；首次 PostgreSQL 业务迁移、账号管理命令、会话与幂等存储。
- 前端登录、作品列表及详情路由；保留健康页和开发模型诊断。
- 更新 runtime tests、smoke、产品状态和相关规范的骨架描述；新增认证/双用户授权/并发与重启测试。
- 密码哈希所需依赖须锁定并审计；无需模型调用、向量检索或 worker 任务。
- 实现阶段同步追溯表并将真实结果写入 docs/verification/2026-11-13-private-works.md；本提案不宣称验证已完成。
