# Spec Delta

## MODIFIED Requirements

### Requirement: 阶段进入条件与缺失前置提示

每个阶段 SHALL 声明进入条件，并在条件不满足时说明缺少什么以及可以到哪里继续。阶段进入条件固定为：

| 阶段 | 进入条件 | 缺少时去哪里继续 |
| --- | --- | --- |
| 构建证据图谱 | 项目至少有一份材料 | 控制台材料入口 |
| 准备角色与环境 | 证据图谱已构建，且存在该 build 的已发布最终快照 | 第一阶段 |
| 双平台运行 | 角色与环境已确认冻结 | 第二阶段 |
| 生成报告 | 双平台运行已完成 | 第三阶段 |
| 深度互动 | 报告已生成 | 第四阶段 |

第一阶段与第二阶段已有真实业务接口时，工作台 MUST 按接口返回的真实状态显示“可开始”“准备中（含可展开的已完成批次）”“已就绪待确认”“已确认”“失败”或“取消”，不得用阶段空态覆盖真实结果。第三至第五阶段尚未接入业务数据时，工作台 MUST 如实展示缺少前置条件或尚未开放，不得显示“已完成”、进度百分比、示例角色、虚假运行结果或可下载报告。

#### Scenario: 直接打开缺少材料的阶段

- **WHEN** 项目所有者直接打开 `/projects/<自己的项目 ID>/workbench/evidence-graph` 且项目没有材料
- **THEN** 页面显示“还没有材料”或等价说明，并指出材料入口的位置
- **AND** 不显示上传成功、图谱节点或“已完成”状态

#### Scenario: 直接打开缺少前置阶段的阶段

- **WHEN** 项目所有者直接打开“双平台运行”而角色与环境尚未确认冻结
- **THEN** 页面说明缺少“角色与环境已确认”
- **AND** 提供前往“准备角色与环境”阶段的链接，点击后进入该阶段而不是控制台

#### Scenario: 第二阶段缺少最终快照

- **WHEN** 项目所有者打开“准备角色与环境”，但证据图谱尚未完成、已失败或没有已发布最终快照
- **THEN** 页面说明证据图谱尚未完成，并显示服务端返回的具体原因
- **AND** 提供返回第一阶段的入口，不显示开始准备按钮或示例角色

#### Scenario: 第二阶段已有可继续的 build

- **WHEN** 证据图谱的最终快照已发布且服务端返回 `canContinue=true`
- **THEN** 第二阶段显示同一 build 的推演问题、快照标识与开始准备入口
- **AND** 不再把第二阶段显示为“角色与环境尚未配置”的纯空态

#### Scenario: 前往上一阶段保留布局与语言

- **WHEN** 用户在 `/projects/<项目 ID>/workbench/dual-platform-run?layout=workbench&lang=en` 点击“前往准备角色与环境”
- **THEN** 地址变为 `/projects/<项目 ID>/workbench/roles-environment?layout=workbench&lang=en`
- **AND** 页面仍为英文工作台布局，不丢失当前查询参数

### Requirement: 加载、空数据、错误与正常四态

工作台 SHALL 分开报告“外壳状态”与“阶段内容状态”，并区分加载中、空数据、错误与正常四种页面状态。加载中 MUST 显示明确的加载提示且不得提前显示空数据文案；项目加载成功 MUST 视为“外壳就绪”，此时项目名、当前阶段高亮、工具条与三种布局都可正常操作，即使阶段内容同时显示“还没有材料”“证据图谱尚未完成”或缺少前置步骤。空数据 MUST 使用非错误文案；错误 MUST 按原因显示“服务暂时不可用”“项目不存在”“阶段不存在”“图谱不存在”或“准备不存在”，并提供重试、返回控制台或有效阶段入口；正常阶段内容 MUST 只来自真实数据并展示当前阶段结果与下一步操作。用户 MUST 能区分“还没有内容”和“服务暂时不可用”。

第一阶段与第二阶段已有真实数据接口时，产品页面 MUST 只展示真实 API 数据，不得把测试夹具或示例数据放进产品。第二阶段 MUST 分别呈现“图谱未完成”“尚未开始准备”“准备中（含分批预览）”“已就绪待确认”“已确认”“生成失败”与“已取消”，不得把其中任一状态误报为另一状态；预览角色不得显示为最终角色。第三至第五阶段尚未接入业务数据时，可观察的“正常”证据只是工作台外壳就绪；若保留“阶段已有业务结果”的渲染分支，MUST 只用隔离测试数据验证，并在验收记录中标记为“隔离数据验证”。

#### Scenario: 加载中不误报空数据

- **WHEN** 工作台正在读取项目或阶段信息
- **THEN** 页面显示加载提示或骨架
- **AND** 不显示“还没有材料”“尚未准备角色”或“项目不存在”，直到请求有确定结果

#### Scenario: 空数据与 503 文案不同

- **WHEN** 项目存在但第二阶段尚未开始准备，另一时刻数据库不可用导致请求返回 503
- **THEN** 第一种情况显示“尚未准备角色与环境”与开始入口
- **AND** 第二种情况显示“服务暂时不可用”并提供重试，不把服务故障描述成没有准备

#### Scenario: 正常状态展示阶段内容

- **WHEN** 项目加载成功且阶段所需真实数据存在
- **THEN** 外壳保持就绪，页面展示该阶段的真实内容与下一步操作
- **AND** 不显示错误、空数据或加载提示

#### Scenario: 外壳就绪与阶段空态共存

- **WHEN** 项目所有者打开自己的真实项目第二阶段，项目请求返回 200，但准备尚未开始
- **THEN** 页面显示项目名、当前阶段高亮、工具条与可切换的三种布局，外壳可正常操作
- **AND** 同一页的阶段内容显示“尚未准备角色与环境”与开始入口，不显示示例角色、完成进度或冻结选择
- **AND** 不因阶段空态把整个页面判为项目不存在或服务不可用

#### Scenario: 第二阶段失败与服务不可用可区分

- **WHEN** 准备任务已失败，另一时刻准备读取请求返回 503
- **THEN** 第一种情况显示失败原因、失败步骤与重试入口
- **AND** 第二种情况显示“服务暂时不可用”并提供重试，不把服务故障描述成准备失败

#### Scenario: 正常阶段结果只来自真实数据

- **WHEN** 审查产品页面与“阶段正常”渲染分支
- **THEN** 产品页面只请求真实 API，不包含测试夹具或示例阶段结果
- **AND** 若用隔离测试数据验证正常分支，证据类型明确标注为“隔离数据验证”，不得混入浏览器签收证据

### Requirement: 完成后提供下一阶段入口

第一阶段 SHALL 在服务端返回 `canContinue=true` 时提供进入第二阶段“准备角色与环境”的入口。入口 MUST 使用服务端字段，不得由前端根据节点数、动画或本地状态推断；跳转 MUST 使用 `push` 并显式保留当前 `layout`、`lang` 与 `buildId`。

`canContinue=false` 时 MUST 禁用入口并说明原因（尚未建图、等待索引、增量绘图、失败、取消、规模超限或来源不完整）。进入第二阶段后，页面 MUST 读取该 build 的最终快照、推演问题与准备上下文，并按真实状态显示普通开始、准备中分批预览、已就绪待确认、已确认、失败或取消；失败/取消后只显示显式重试入口；MUST NOT 再把“角色与环境尚未配置”当作已进入第二阶段的完成态。第二阶段 MUST NOT 重新显示“缺少证据图谱”，除非服务端明确返回该 build 的最终快照不可用。本变更 MUST NOT 实现双平台实际运行、报告生成或深度互动内容。

#### Scenario: 完成后进入第二阶段

- **WHEN** build 为 `ready` 且服务端返回 `canContinue=true`
- **THEN** 面板显示可用的“进入准备角色与环境”按钮
- **AND** 点击后进入 `/projects/<项目 ID>/workbench/roles-environment`，并保留 `layout`、`lang` 与 `buildId`
- **AND** 第二阶段显示同一 build 的推演问题与准备入口，而不是缺少证据图谱

#### Scenario: 未完成时入口禁用

- **WHEN** build 处于等待索引、增量绘图、失败、取消或规模超限
- **THEN** 下一阶段入口禁用，并显示对应原因
- **AND** 点击不会进入第二阶段，也不会创建新任务

#### Scenario: 来源不完整时不允许进入

- **WHEN** 服务端因材料来源不完整返回 `canContinue=false`
- **THEN** 面板显示来源校验失败或来源不足原因
- **AND** 不把图谱显示为可继续的完成结果

#### Scenario: 第二阶段不把未完成图谱当作可准备

- **WHEN** 用户直接打开第二阶段且该 build 没有已发布最终快照
- **THEN** 页面显示证据图谱尚未完成及具体原因
- **AND** 不显示开始准备按钮，也不创建准备任务

#### Scenario: 第二阶段准备中可展开第一批预览

- **WHEN** 第二阶段读取到 `phase=preparing` 且已完成至少一批画像
- **THEN** 页面显示“准备中”，并可展开该批角色及其来源
- **AND** 确认与“进入双平台运行”仍不可用
- **AND** 未完成批次不显示为已完成

#### Scenario: 第二阶段失败或取消后只读预览

- **WHEN** 第二阶段读取到 `failed` 或 `canceled` 且已有已完成批次
- **THEN** 页面显示失败/取消原因与显式重试入口
- **AND** 已完成批次只读显示为“未完成预览”
- **AND** 不显示平台、话题、顺序、冻结选择或可用的第三阶段入口

#### Scenario: 确认版本冲突后重新读取

- **WHEN** 用户确认时收到 `settings_conflict`
- **THEN** 页面提示配置已被其他标签页更新，并重新读取准备详情
- **AND** 不用旧 `settingsRevision` 继续确认
- **AND** 重新读取后显示最新轮数，用户再次确认才冻结

#### Scenario: 第二阶段确认后才允许进入第三阶段

- **WHEN** 准备已 `ready` 但用户尚未确认冻结选择
- **THEN** 第二阶段显示“待确认”与确认入口
- **AND** “进入双平台运行”禁用，直到服务端返回 `canContinue=true`
