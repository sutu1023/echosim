# Proposal

## Why

武大项目旧 build `f4c9a593-aa36-49e3-84cf-125ccaa88c21` 对 25 页报告生成 26 对互不相连的段首文本节点；当前 Change 08 的“主体注册表 + 抽取清单”路径虽然能保证来源，但把发布范围限制在首轮登记的少量主体和必须命中清单的关系上。读回结果再丰富，工作台也只能展示清单里的少数节点与边，用户仍看不出整份报告的主要事件、相关方和具体行动。

全文用于规划本体，原始文本分块作为 episode 写入图谱服务，服务完成索引后按本次 build 分页读回全部节点、边与事实描述。EchoSim 沿用现有六步建图、租约、快照与来源定位机制，对同一份 25 页报告全量生成一张新图。

## What Changes

- 从现有已上传材料重建“建图全文”：沿用入库阶段已清理的页眉页脚，保留段落、标题与跨页衔接；按 500 字、50 字重叠切分为建图分块，并保留每个分块到原始材料、物理页码与 UTF-16 字符区间的映射。旧材料无需重新上传。
- 规划阶段只由模型根据整份报告与问题设计实体类型、关系类型；不再登记“首轮最多 24 个主体”的白名单，也不再要求后续抽取围着这张名单转。
- 建图采用参考项目主链路：把规划出的本体设置到本次 build 的图谱，把带上下文映射的原文分块作为 episode 交给图谱服务，等待索引与处理，再按本次 build 的 episode UUID 分页读回节点、边和事实描述。
- 发布来源改为“读回事实 → 关联 episode → 定位支持原句 → 映射原文坐标”，不再要求命中旧抽取清单。保留项目和 build 隔离；新 build 使用独立图谱，旧 build 与旧快照只读对照。
- 读回节点按规范名称归并跨页/重复节点；读回边按端点、动作和事实去重。每条发布关系必须能定位到同时支持主体、动作与对象的原句。
- 保留来源性质区分：媒体报道、当事方主张、报告建议、机构正式决定、其他材料陈述。媒体名单不能推出报道关系；建议撤销不能变成已经撤销；这两项继续作为回归。
- 修正画布上的语义方向与限定：平台上的用户行动画成“用户 → 平台”并在界面读成“用户在平台上行动”；被转述的不实说法建成“待核实说法”节点；作者建议标为“报告建议”，不冒充机构已作出的决定。
- 工作台继续使用现有快照接口与来源跳转，展示新图的主体、动作、方向、来源性质与原句；旧 build 仍可打开。
- 验收：在武大工作台对 25 页报告执行一次全新的真实建图，记录覆盖页数、写入原文块数、图谱读回节点/边数、最终发布节点/边数；若读回丰富而展示很少，必须先定位并修复损失环节。
- **非目标**：不把模型二次抽取的 JSON 当作图谱事实来源；不以节点/边数量或截图密度作为通过条件；不使用测试替身、校园夹具或手工补图冒充武大新图；不改变 Change 07 的六步、租约、事件、快照可见性与原文坐标语义；不扩大私有材料授权范围。

## Capabilities

### New Capabilities

- `evidence-graph-semantics`: 建图全文与 500/50 分块映射、全文本体规划、原文 episode 写入与读回、跨页节点归并、读回事实到支持原句与来源性质的映射。

### Modified Capabilities

- `project-workbench`: 新图直接展示整份报告的主体、事件、行动、方向与来源性质；关系详情显示读回事实、支持原句与材料位置；旧 build 保持可打开。
- `reproducible-verification`: 武大 25 页报告的真实全量建图验收，记录覆盖页数、写入块数、读回与最终发布计数，并保留媒体名单/建议撤销回归。

## Impact

- 代码：`app/services/document_extract.py`（建图全文与分块辅助）、`app/engines/business_model.py`（全文本体规划）、`app/engines/business_graph.py`（set_ontology、原文 episode 读回、节点/边归并）、`app/engines/business_semantics.py`（读回事实到原句、来源性质）、`app/services/worker.py`（plan/extract/write/readback 新链路）、`app/engines/business_stub.py` 与 `business_runtime.py`（离线替身与计数）、前端图谱展示与测试。
- 数据库：沿用 `0009_graph_claim_nature.sql` 的 `graph_edges.claim_nature`、`graph_builds.graph_id` 与真实 provider 绑定；新 build 使用独立图谱，旧 build 不回填、不改写。建图全文分块映射保存在建图步骤载荷中，不重写材料分块。
- 接口：沿用现有快照响应字段；新快照返回读回后的语义节点/边、动作标签与来源性质。
- 验收：真实建图只在开发者显式操作武大工作台时触发；默认 `make up`、`make verify` 与 CI 仍为零真实外呼。
