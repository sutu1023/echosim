# project-workbench Specification

## Purpose
让每个项目拥有按阶段可直接打开的工作台外壳：共用顶部工具条、三种可切换布局与中英文界面，并在缺少材料或前置阶段时如实说明下一步；当前版本只交付页面、路由与交互，不伪造材料、任务、推演或报告数据。

## Requirements

### Requirement: 项目与阶段的稳定深链接

工作台 SHALL 为五个阶段提供稳定的英文路径 slug，并允许直接打开任一阶段：

| 顺序 | 阶段 | slug |
| --- | --- | --- |
| 1 | 构建证据图谱 | `evidence-graph` |
| 2 | 准备角色与环境 | `roles-environment` |
| 3 | 双平台运行 | `dual-platform-run` |
| 4 | 生成报告 | `report` |
| 5 | 深度互动 | `interaction` |

`/projects/:projectId/workbench` 在没有阶段 slug 时 MUST 重定向到第一阶段并保留查询参数。打开任一阶段地址时，页面 MUST 显示对应项目名称、当前阶段高亮与阶段内容，不得跳回控制台或项目列表。

#### Scenario: 直接打开第一阶段

- **WHEN** 项目所有者打开 `/projects/<自己的项目 ID>/workbench/evidence-graph`
- **THEN** 工作台显示该项目名称，第一阶段“构建证据图谱”为当前阶段
- **AND** 地址保持在该阶段路径，不跳转 `/` 或 `/projects`

#### Scenario: 直接打开后续阶段

- **WHEN** 项目所有者打开 `/projects/<自己的项目 ID>/workbench/dual-platform-run`
- **THEN** 工作台显示“双平台运行”为当前阶段，五个阶段导航中其余阶段仍可点击
- **AND** 当前项目与阶段由地址决定，而不是由浏览器内存中的“上次位置”决定

#### Scenario: 无阶段路径回到第一阶段

- **WHEN** 项目所有者打开 `/projects/<自己的项目 ID>/workbench?layout=graph&lang=en`
- **THEN** 页面重定向到 `/projects/<项目 ID>/workbench/evidence-graph?layout=graph&lang=en`
- **AND** 布局与语言参数不因重定向丢失

### Requirement: 共用顶部工具条

工作台 SHALL 在所有布局中显示同一套顶部工具条，包含：返回控制台、项目名称、五个阶段导航、布局切换、“图谱/双栏/工作台”名称、中英文切换、服务状态与当前账户操作。切换布局 MUST NOT 隐藏或替换工具条，MUST NOT 丢失当前项目与阶段。

#### Scenario: 三种布局共用工具条

- **WHEN** 用户在任一阶段的三种布局之间切换
- **THEN** 顶部工具条始终显示返回控制台、项目名称、五个阶段、布局切换与语言切换
- **AND** 当前项目名称与当前阶段在工具条与阶段导航中保持一致

#### Scenario: 工具条提供服务状态与账户操作

- **WHEN** 已登录用户打开任一工作台阶段
- **THEN** 工具条显示服务状态与当前账户操作（至少包含退出登录）
- **AND** 服务状态来自同源健康检查，不显示数据库连接串、凭据或内部主机名

### Requirement: 三种布局的区域可见性

工作台 SHALL 提供「图谱」「双栏」「工作台」三种布局，默认使用「双栏」。三种布局的可见区域 MUST 按下表区分，且都保留当前项目、当前阶段与共用工具条：

| 布局 | 必须可见的区域 | 不占用主视区的区域 |
| --- | --- | --- |
| 图谱 | 工具条、阶段导航、全宽图谱画布、阶段摘要条 | 材料/问题侧栏折叠为工具条入口，不占据画布宽度 |
| 双栏 | 工具条、阶段导航、左侧主区（阶段说明 + 画布或阶段内容）、右侧上下文栏（材料入口、推演问题、下一步） | 项目/阶段侧栏不单独展开 |
| 工作台 | 工具条、阶段导航、左侧项目/阶段栏（含进入条件）、中央主区、右侧上下文栏、底部状态栏 | 无整栏隐藏；侧栏可折叠但默认展开 |

#### Scenario: 图谱布局显示画布

- **WHEN** 用户选择「图谱」布局
- **THEN** 主视区显示全宽图谱画布与阶段摘要条
- **AND** 材料/问题侧栏不占据画布宽度，可通过工具条入口打开
- **AND** 当前阶段与项目保持不变

#### Scenario: 双栏布局显示左右两栏

- **WHEN** 用户选择「双栏」布局
- **THEN** 左侧显示当前阶段说明与内容，右侧显示材料入口、推演问题与下一步操作
- **AND** 不出现单独的项目/阶段侧栏

#### Scenario: 工作台布局显示完整三栏

- **WHEN** 用户选择「工作台」布局
- **THEN** 左侧显示项目/阶段栏与进入条件，中央显示阶段内容，右侧显示材料与问题上下文，底部显示状态栏
- **AND** 当前项目与阶段不因区域增多而改变

### Requirement: 布局与语言状态可由 URL 恢复

工作台 SHALL 使用查询参数 `layout=graph|split|workbench` 与 `lang=zh|en` 表示布局和语言；缺失或非法时分别使用默认值 `split` 与 `zh`，不得报错或跳转。用户切换布局或语言时 MUST 保留当前项目与阶段，并只更新对应查询参数；切换 MUST 使用替换当前历史记录的方式，不额外制造后退步骤。页面刷新后 MUST 从 URL 恢复布局、语言、项目与阶段。阶段导航、缺少前置条件时的“前往上一阶段”、无阶段地址重定向以及非法阶段页的有效阶段入口 MUST 显式携带当前 `layout` 与 `lang`，不得依赖路由自动保留查询参数。

#### Scenario: 刷新后保留非首页阶段与设置

- **WHEN** 用户在 `/projects/<项目 ID>/workbench/roles-environment?layout=graph&lang=en` 刷新页面
- **THEN** 页面仍显示同一项目与“准备角色与环境”阶段
- **AND** 布局仍为图谱，界面仍为英文

#### Scenario: 中英文各切换三种布局

- **WHEN** 用户在同一项目的非首页阶段分别以中文和英文切换「图谱」「双栏」「工作台」
- **THEN** 每次切换后地址中的 `layout` 更新，`lang` 与阶段路径保持不变
- **AND** 三种布局的可见区域符合区域表，页面不回到第一阶段、项目列表或控制台

#### Scenario: 刷新后保留语言

- **WHEN** 用户把 `lang` 从 `zh` 切换为 `en` 后刷新页面
- **THEN** 界面仍为英文，`lang=en` 仍在地址中
- **AND** 项目名称、阶段 slug 与阶段序号不被翻译或改写

#### Scenario: 非法布局或语言回退

- **WHEN** 用户打开带 `layout=unknown` 或 `lang=fr` 的工作台地址
- **THEN** 页面分别使用「双栏」与中文，不显示错误页或跳回首页
- **AND** 当前项目与阶段保持地址中的值

#### Scenario: 阶段导航显式保留查询参数

- **WHEN** 用户在 `/projects/<项目 ID>/workbench/report?layout=graph&lang=en` 点击阶段导航进入“深度互动”
- **THEN** 地址变为 `/projects/<项目 ID>/workbench/interaction?layout=graph&lang=en`
- **AND** 页面仍为英文图谱布局，不回退到双栏或中文
- **AND** 刷新后仍在深度互动且保持 `graph/en`

### Requirement: 刷新、后退与返回控制台

工作台导航 SHALL 满足以下历史行为：刷新恢复当前地址；点击阶段导航新增历史记录，使浏览器后退回到上一阶段并保留布局与语言；切换布局或语言不新增历史记录；点击“返回控制台”进入 `/`，随后浏览器后退回到离开前的工作台完整地址。阶段链接 MUST 显式携带当前 `layout` 与 `lang`，不得因 `router.push` 只传阶段参数而丢失查询参数。

#### Scenario: 报告阶段到深度互动的完整后退序列

- **WHEN** 用户从项目详情进入 `/projects/<项目 ID>/workbench/report?layout=graph&lang=en`，选择图谱布局和英文，再点击阶段导航进入“深度互动”
- **THEN** 当前地址为 `/projects/<项目 ID>/workbench/interaction?layout=graph&lang=en`，页面为英文图谱布局
- **AND** 刷新后仍在“深度互动”，布局与语言不变
- **AND** 浏览器后退一次回到同一项目的 `/projects/<项目 ID>/workbench/report?layout=graph&lang=en`，页面为英文图谱布局的报告阶段
- **AND** 若地址缺少 `layout=graph&lang=en`、回到第一阶段或回到首页，则判定失败

#### Scenario: 切换布局不制造后退步骤

- **WHEN** 用户在“生成报告”阶段从双栏切换到工作台，随后点击浏览器后退
- **THEN** 页面离开工作台，回到进入工作台前的上一个页面
- **AND** 不会只在“双栏”和“工作台”之间来回切换

#### Scenario: 返回控制台后可后退回到工作台

- **WHEN** 用户在工作台点击“返回控制台”，随后点击浏览器后退
- **THEN** 首先看到 `/` 控制台
- **AND** 后退后回到离开前的同一项目、同一阶段、同一布局与语言

### Requirement: 阶段进入条件与缺失前置提示

每个阶段 SHALL 声明进入条件，并在条件不满足时说明缺少什么以及可以到哪里继续。阶段进入条件固定为：

| 阶段 | 进入条件 | 缺少时去哪里继续 |
| --- | --- | --- |
| 构建证据图谱 | 项目至少有一份材料 | 控制台材料入口 |
| 准备角色与环境 | 证据图谱已构建 | 第一阶段 |
| 双平台运行 | 角色与环境已准备 | 第二阶段 |
| 生成报告 | 双平台运行已完成 | 第三阶段 |
| 深度互动 | 报告已生成 | 第四阶段 |

当前版本没有材料与阶段数据接口时，工作台 MUST 如实展示空态或缺少前置条件，不得显示“已完成”、进度百分比、示例材料、虚假运行结果或可下载报告。

#### Scenario: 直接打开缺少材料的阶段

- **WHEN** 项目所有者直接打开 `/projects/<自己的项目 ID>/workbench/evidence-graph` 且项目没有材料
- **THEN** 页面显示“还没有材料”或等价说明，并指出材料入口的位置
- **AND** 不显示上传成功、图谱节点或“已完成”状态

#### Scenario: 直接打开缺少前置阶段的阶段

- **WHEN** 项目所有者直接打开“双平台运行”而角色与环境尚未准备
- **THEN** 页面说明缺少“角色与环境”
- **AND** 提供前往“准备角色与环境”阶段的链接，点击后进入该阶段而不是控制台

#### Scenario: 前往上一阶段保留布局与语言

- **WHEN** 用户在 `/projects/<项目 ID>/workbench/dual-platform-run?layout=workbench&lang=en` 点击“前往准备角色与环境”
- **THEN** 地址变为 `/projects/<项目 ID>/workbench/roles-environment?layout=workbench&lang=en`
- **AND** 页面仍为英文工作台布局，不丢失当前查询参数

### Requirement: 加载、空数据、错误与正常四态

工作台 SHALL 分开报告“外壳状态”与“阶段内容状态”，并区分加载中、空数据、错误与正常四种页面状态。加载中 MUST 显示明确的加载提示且不得提前显示空数据文案；项目加载成功 MUST 视为“外壳就绪”，此时项目名、当前阶段高亮、工具条与三种布局都可正常操作，即使阶段内容同时显示“还没有材料”或缺少前置步骤。空数据 MUST 使用“还没有材料”或“缺少前置条件”等非错误文案；错误 MUST 按原因显示“服务暂时不可用”“项目不存在”或“阶段不存在”，并提供重试、返回控制台或有效阶段入口；正常阶段内容 MUST 只来自真实数据并展示当前阶段结果与下一步操作。用户 MUST 能区分“还没有材料”和“服务暂时不可用”。

当前版本没有阶段数据接口时，产品页面 MUST 只展示真实 API 数据，不得把测试夹具或示例数据放进产品；可观察的“正常”证据是工作台外壳就绪。若保留“阶段已有业务结果”的渲染分支，MUST 只用隔离测试数据验证，并在验收记录中标记为“隔离数据验证”。

#### Scenario: 加载中不误报空数据

- **WHEN** 工作台正在读取项目或阶段信息
- **THEN** 页面显示加载提示或骨架
- **AND** 不显示“还没有材料”或“项目不存在”，直到请求有确定结果

#### Scenario: 空数据与 503 文案不同

- **WHEN** 项目存在但没有材料，另一时刻数据库不可用导致请求返回 503
- **THEN** 第一种情况显示“还没有材料”并提供材料入口说明
- **AND** 第二种情况显示“服务暂时不可用”并提供重试，不把服务故障描述成没有材料

#### Scenario: 正常状态展示阶段内容

- **WHEN** 项目加载成功且阶段所需真实数据存在
- **THEN** 外壳保持就绪，页面展示该阶段的真实内容与下一步操作
- **AND** 不显示错误、空数据或加载提示

#### Scenario: 外壳就绪与阶段空态共存

- **WHEN** 项目所有者打开自己的真实项目阶段，项目请求返回 200，但当前版本没有阶段数据
- **THEN** 页面显示项目名、当前阶段高亮、工具条与可切换的三种布局，外壳可正常操作
- **AND** 同一页的阶段内容显示“还没有材料”或缺少前置步骤，不显示完成进度、示例节点或报告
- **AND** 不因阶段空态把整个页面判为项目不存在或服务不可用

#### Scenario: 正常阶段结果只来自真实数据

- **WHEN** 审查产品页面与“阶段正常”渲染分支
- **THEN** 产品页面只请求真实 API，不包含测试夹具或示例阶段结果
- **AND** 若用隔离测试数据验证正常分支，证据类型明确标注为“隔离数据验证”，不得混入浏览器签收证据

### Requirement: 私有工作台访问边界

任一工作台阶段地址 SHALL 先完成身份与项目归属判断，再判断阶段是否合法。未携带会话时 MUST 跳转登录并保留完整原地址；数据库不可达但会话存在时 MUST 显示“服务暂时不可用”并保留登录态；他人项目、不存在项目与非法项目 ID MUST 显示相同的“项目不存在”，不得显示项目名称或“无权访问”；只有项目归属通过后，非法阶段才显示“阶段不存在”，且不得跳回 `/`。

#### Scenario: 匿名打开工作台深链接

- **WHEN** 未登录访客打开 `/projects/<任意项目 ID>/workbench/report?layout=graph&lang=en`
- **THEN** 页面跳转 `/login`，`next` 保留该完整地址
- **AND** 登录成功后直接回到该阶段，而不是控制台或项目列表

#### Scenario: 他人项目与不存在项目等价

- **WHEN** 已登录用户 B 打开 A 的项目工作台，随后打开一个随机不存在的项目工作台
- **THEN** 两次页面都显示相同的“项目不存在”提示
- **AND** 都不显示 A 的项目名称、阶段内容或“无权访问”

#### Scenario: 数据库不可达时显示服务错误

- **WHEN** 已登录用户打开自己的工作台，但项目请求返回 503
- **THEN** 页面显示“服务暂时不可用”与重试操作
- **AND** 不清除会话、不跳转登录页，恢复后可直接重试

#### Scenario: 非法阶段不跳回首页

- **WHEN** 项目所有者打开 `/projects/<自己的项目 ID>/workbench/not-a-stage`
- **THEN** 页面显示“阶段不存在”并列出五个有效阶段入口
- **AND** 地址保持在该路径，不自动跳转 `/`、`/projects` 或第一阶段

### Requirement: 中英文界面切换

工作台 SHALL 支持中文与英文界面，默认中文。切换语言 MUST 翻译工具条、阶段名称、布局名称、材料/问题区域、按钮、空数据、加载与错误状态等外壳文案，并更新文档语言属性；MUST NOT 翻译项目名称、项目 ID 与阶段 slug。已知的 401、404、503 状态 MUST 使用当前语言的界面文案，不得直接展示另一种语言的后端原始 `detail` 作为主提示。

#### Scenario: 英文界面覆盖工作台外壳

- **WHEN** 用户把 `lang` 切换为 `en`
- **THEN** 工具条、五个阶段名称、三种布局名称、材料/问题区域、按钮与状态文案均为英文
- **AND** 项目名称保持原样，阶段 slug 仍为 `evidence-graph` 等英文标识

#### Scenario: 英文界面下的错误状态

- **WHEN** 用户在 `lang=en` 下遇到项目不存在或服务暂时不可用
- **THEN** 页面分别显示对应的英文提示，而不是“项目不存在”或“服务暂时不可用”的中文原文
- **AND** 不泄露额外的项目是否存在信息
